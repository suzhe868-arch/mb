## 1. 本轮确认的设计方向

用户已确认：不继续把原 `A 蓝灰商务 / B 石墨汽车` 两套候选直接作为最终方向；H01 改为以以下组合方向完成正式修订稿：

- 整体气质：**专业汽车平台的品牌质感 + 高效找车**，不能为了“高级感”牺牲真实车源信息密度和找车效率。
- 基础视觉：**暖白浅色底 + 石墨深色文字/主体 + 克制的金色系品牌强调**。金色的具体色值目前不是永久冻结值，后续允许基于真实页面、对比度和用户观感微调。
- 客户端重点突出真实车辆图片、清晰车型信息和可用筛选；避免通用二手车平台的杂乱营销标签，也避免做成只有大图、缺少业务信息的“展厅海报”。
- E 员工端和 P PC 后台继承统一品牌语言，但优先操作效率、数据密度和权限辨识，不强行复制 C 客户端布局。

## 2. 颜色必须令牌化，不得逐页硬编码

本轮将颜色作为 Design Token（设计令牌）管理，而不是散落在每个页面的固定色值。

至少保持以下语义层：
- `semantic.brand.primary`：品牌强调色；
- `semantic.brand.subtle`：品牌浅色背景；
- `semantic.surface.*`：页面/卡片/禁用背景；
- `semantic.foreground.*`：主文字/次文字；
- `semantic.border.*`：边框与分隔；
- `semantic.feedback.success/warning/danger/focus`：业务反馈色。

要求：
1. 后续若用户只调整品牌主色，应优先通过令牌统一替换，不要求逐页重新设计。
2. 成功/警告/错误色不得因为品牌改成金色而混用；业务状态仍使用独立语义色并配中文/图形。
3. 当前“暖白 + 石墨 + 金色”是**视觉方向确认**，不是所有具体 HEX 色值永久冻结。C 应给出可测量的候选色值并做对比度检查。
4. 布局、组件、信息层级等结构性视觉语言与单纯换色分离，避免以后改色牵动整套页面重做。

## 3. C01 首页必须采用“完整态 + 紧凑态”两态结构

### 3.1 首次进入 / 回到顶部：完整态

必须基于 Current IA / Current Low-Fi 的合法结构，重点表现：
- 名邦汽车品牌识别；
- 品牌主视觉 / Banner（高度克制，不能长期挤压看车区域）；
- 搜索框；
- **批发车源 / 名邦车源 / 4S 店车源**三类来源切换；
- Current 正式存在的排序 / 品牌 / 价格 / 筛选入口；
- 真实车源列表；
- 客户端底部一级导航。

品牌主视觉可以有品质感，但不能把首屏做成大面积广告海报，以致真实车源只能露出极少内容。

### 3.2 用户下滑浏览：紧凑态

当用户向下浏览车源时：
- 大面积 Banner / 主视觉、非必要品牌快捷区等占高内容退出；
- 顶部保留紧凑的“名邦汽车”品牌标题；
- **搜索框继续保留**；
- **批发车源 / 名邦车源 / 4S 店车源**切换继续保留；
- **排序 / 品牌 / 价格 / 筛选**继续保留；
- 其余空间优先用于连续浏览真实车源。

紧凑态与搜索状态应复用同一结构壳：
- 未搜索时，搜索框显示合法占位提示；
- 已搜索时，搜索框显示实际关键词；
- 不再额外设计第三套“半折叠”结构。

交互原则：只有真正回到页面顶部才恢复完整大主视觉，避免用户轻微反向滚动就频繁弹出大 Banner 造成页面跳动。

> 本节只明确 H01 的设计/交互方向；具体滚动阈值、动画时长和小程序实现属于后续获批前端阶段，不在 H01 擅自实现。

## 4. 客户端底部导航严格保持三项

当前正式一级导航必须保持：
1. **车源**
2. **帮我找车**（中间）
3. **我的**

禁止：
- 新增第四个底部“收藏”一级入口；
- 因通用汽车 App 惯例改成“首页 / 找车 / 收藏 / 我的”等四栏结构；
- 用设计稿改变 Current IA 的一级导航归属。

收藏业务本身没有因此删除：详情页合法收藏动作和“我的”体系内的收藏入口仍按 Current Authority；**列表卡片是否需要收藏快捷动作必须以 Current 页面动作依据为准，不因视觉效果自行增加。**

## 5. 车源卡片必须使用真实业务字段，不造营销事实

H01 代表卡片优先围绕当前真实可获得/可展示的信息组织，典型信息层级包括：
- 车辆图片；
- 车型/年款/款型等 Current 可用标题信息；
- 年份或上牌相关合法展示字段（以当前数据事实为准）；
- 里程；
- 所在城市/地区；
- 上架时间或 Current 已确认的真实时间字段；
- 车源来源：批发 / 名邦 / 4S；
- 按客户等级、车源来源、价格事实和 Current 权限规则投影的价格状态。

不得为了效果图自行生成或默认宣称：
- “高性价比”；
- “已检测”；
- “官方直营”；
- “质保 xx 天”；
- “严选”“精品”“认证”等没有当前正式数据事实支持的营销标签；
- 任何其他仅因第三方汽车 App 常见而补入的标签。

如 Current 有结构化车况标签、报告或其他真实字段，必须先明确其来源、适用条件和展示权限，再决定是否在列表出现；不能把“存在这种数据能力”画成“每台车默认都有该标签”。

## 6. 价格区域的本轮排版要求

用户明确认为首轮代表稿中价格作为宽大的独立右侧区域会拖宽卡片、破坏整体观感。本轮应：

- 保持车型标题为主要视觉层级；
- 将价格收回车辆基础信息区的后半段，可尝试位于城市/地区信息之后、卡片中后部的紧凑位置；
- 价格仍需有足够视觉辨识度，但不得形成占据大量横向空间的独立宽列；
- 以真实手机宽度验证长车型名、长城市名、里程和价格同时存在时的截断/换行；
- 普通、粉丝/VIP 及不同价格事实必须严格遵守 PDM-10，不能为了版式统一而泄露数字价格或混淆 `--万` 与 `价格咨询`。

本条确定的是**布局方向**，不是要求固定某个坐标。C 应以 390px 等真实参考宽度做至少一轮可读性验证。

## 8. 正式设计前的强制核对流程

从本轮起，每个 H01/H02 视觉页面在形成正式稿前，必须先建立最小“设计输入清单”：
- 页面 ID；
- PDM Final 相关规则；
- Current IA 页面/动作；
- Current Low-Fi 当前有效载体；
- 当前身份/客户等级/权限/数据范围；
- 可显示真实字段；
- 可执行动作；
- 必须覆盖的关键状态；
- 禁止恢复项。

视觉设计只在上述边界内自由处理颜色、字体、间距、图片比例、信息层级、卡片结构和视觉节奏。

**禁止先让生成式图片自行补全汽车 App，再倒推产品规则。** AI 概念效果图可以用于风格探索，但必须经过上述清单逐项校验后，才能转为正式设计依据。
