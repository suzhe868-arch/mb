# H01-2｜Design System 基础令牌与三端适配规范

> 状态：`PROVISIONAL_DESIGN_SPEC`，待 A 设计/业务一致性审核及用户核心视觉方向确认。
> 本规范是设计提案，不是 PDM 产品规则或已验收的品牌手册。**A/B 品牌色只作为并列候选**。

## 1. 命名分层

- `primitive.*` 原始色阶与数字，只供内部设计编辑；不得直接用原始红色代表“错误”等业务含义。
- `semantic.*` 角色：`surface/foreground/border/brand/success/warning/danger/focus`，必须有足够文本或状态图标区别。
- `component.*` 组件尺寸：卡片、按钮、表单、导航、标记与 PC 表格。
- `context.*` 终端差异：C 小程序、E 员工小程序、P PC 后台。
- 业务状态和值不属于视觉 Token，不创建 `token.priorityLock` 等伪状态；只映射后台返回的事实。

## 2. 未受品牌争议影响的基础色（候选通用）

| 用途 | 草案值 | 交互/风险说明 |
| --- | --- | --- |
| 主文字 `foreground.primary` | `#24282E` | 与浅色底对比优先 |
| 次要文字 `foreground.secondary` | `#626B76` | 长说明需再核查对比度 |
| 页面背景 `surface.canvas` | `#F6F7F8` | 移动/PC 都用浅底降低视觉噪声 |
| 内容底 `surface.panel` | `#FFFFFF` | 组件不依赖渐变区分 |
| 分隔边框 `border.subtle` | `#E3E7EA` | 表格分栏需可读 |
| 正向结果 `feedback.success` | `#176A45` | 搭配“已完成”等中文文字 |
| 警告 `feedback.warning` | `#995A13` | 不用红色替代所有待办 |
| 错误 `feedback.danger` | `#B42318` | 搭配字段/提交失败原因 |
| 禁用背景 `surface.disabled` | `#ECEFF1` | 无权限默认**隐藏**而非禁用 |

候选 A `brand.primary=#2563EB`、`brand.subtle=#EAF1FF`；候选 B `brand.primary=#D65438`、`brand.subtle=#FCE9E4`。用户确认前，设计源同时保留两个方案，不默认单一实锤值。

## 3. 字体、可读性与间距

- 中文优先：终端系统无衬线字体栈（iOS/Android/Windows 原生简中字体），不把个人电脑字体打包进设计仓库。
- 大标题 26/32、页标题 22/30、卡片标题 17/25、正文 15/23、辅助 13/19、数据标签 12/18，单位 px/行高；PC 一级标题建议 24/32、表格 13～14/20。均为设计初稿，极小字须单独验收。
- 数字价格需字体视觉强度但不可暗示不存在的数字价格；价格占位 `--万`、`价格咨询` 与数字价三类区别清楚。
- 间距基元：`4/8/12/16/20/24/32/40/48` px；移动水平内容边距 16px，PC 主容器 24px；PC 稠密表格可用 12/16px 单元格内边距。
- 圆角：8（表单/小按钮）、12（卡片）、16（弹层）、24（强调容器）；不因样式创建新的动作。
- 阴影：小卡片只做轻微高度层级；弹层焦点与遮罩优先靠明暗和清晰标题，避免激进阴影。
- 图标参考 18/20/24px，重要状态必须同时有文字；纯 SVG 图标需可读标签。

## 4. 三端布局与交互

| 维度 | C 客户小程序 | E 员工 / 4S 同 App | P PC 后台 |
| --- | --- | --- | --- |
| 基准画板 | 390×844（仅设计参考） | 390×844（仅设计参考） | 1440×900（仅设计参考） |
| 安全区域 | 顶部系统状态区 + 底部系统安全区；实际以宿主提供值布局 | 同 C，紧急待办优先可见 | 浏览器缩放/窗口大小；长表格横向管理 |
| 主布局 | 列表/筛选，固定动作条需避让安全区 | 工作台任务优先，操作目标不压住系统导航 | 侧边导航+标题/工具栏+表格，宽度不足折叠筛选 |
| 触达建议 | 最小可触控目标 44×44px（设计目标） | 同 C，审批按钮需足够区分与二次确认 | 按钮高度 32/36/40px；仍应键盘可操作 |
| 变化提示 | 轻量提示+明确回退路径 | 乐观更新谨慎，服务端拒绝恢复当前真实状态 | 行内反馈/确认弹层/操作审计提示 |
| 价格/电话 | 仅公开客户字段 | 依 permission / data scope / 来源投影；4S hard deny 有独立校验 | 与当前身份/权限/对象状态一致，System Admin 不天然越权 |

小程序正式安全区 CSS env/运行平台适配属于 H03 施工，H01 只给出必须满足的尺寸和禁止遮挡准则。响应式断点建议 `390/768/1024/1440` 作为视觉评估视口，**不是业务路由切换规则**。

## 5. 组件初始规格

| 组件 | 样式/尺寸草案 | 状态必需 |
| --- | --- | --- |
| 主按钮 | 移动高度 48px、PC 36～40px；高对比主色 | 默认/加载/成功/失败/无权隐藏/有权对象禁用 |
| 次按钮 | 轮廓+文字，不与主操作混淆 | 同上 |
| 输入框 | 移动 48px，PC 36～40px；错误文字在字段下方 | 正常/焦点/校验错/提交中/服务端拒绝 |
| 车源卡片 | 图片纵横比按合法资产；多行主信息 | 价格三态、空图、部分字段缺失、收藏反馈 |
| 详情动作条 | 锁车/候补/进度按 **PDM-20 §19** 动态切换 | LockRequest、Waitlist、Lock、终态只读 |
| 草稿自动保存提示 | 不抢占表单主 CTA | 无有效输入无草稿；保存中/保存成功/保存失败 |
| PC 管理表格 | 默认行高建议 48px，可选密度层级但不可隐藏必需业务字段 | 分页/加载/空/错误/无权限/服务端重验 |
| 消息/反馈 | 确认、警示、失败使用文字+图形 | 无“全局消息中心”新业务设计 |

## 6. 无障碍与检查门槛

- 设计目标：普通文本对比至少 4.5:1；大字/主要非文本界面轮廓至少 3:1，最终根据字号与真实色值分别检查。**当前尚未完成逐色实际测量**，不能声称 PASS。
- 重要按钮在触控端应有 44×44px 目标区域，正文不靠极浅灰色勉强区分。
- 手势必须有可见替代操作（已冻结业务明确例外除外），焦点可识别，出错信息明确。
- 页面有用户可操作数据时不能因为加载状态短暂出现敏感内容占位，避免闪露价/电话。
- 配色方向确定后执行独立对比度测量、中文文本截断与响应视口实测，并保存检查证据。

## 7. 设计实现不应越权

- `当前用户能看见`≠`可以提交动作`；当前身份/权限/数据范围/状态先由后端裁剪，提交时重验。
- 缺失 permission 的员工敏感按钮**不渲染**；只有有权限但对象暂不可操作，才显示禁用和原因（PDM-21 §13）。
- 缺数字客户价的“价格咨询”与额度耗尽“--万”不能互换（PDM-10 §7）。
- 4S 的同 App 裁剪不允许把 LockRequest 审核变成仅灰化操作。
- 正式落地设计 token CSS/原生配置须在 H03 对应页面批次获批后执行。
