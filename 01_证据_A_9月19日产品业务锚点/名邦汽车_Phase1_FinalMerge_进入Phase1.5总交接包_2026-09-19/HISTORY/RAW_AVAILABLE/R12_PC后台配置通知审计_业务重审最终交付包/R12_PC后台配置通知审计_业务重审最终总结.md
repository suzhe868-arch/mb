# 3. PC 后台身份与访问边界

## 3.1 PC 后台不是 System Admin 专属业务后台

名邦员工身份与 System Admin 身份继续严格分离。

### 员工身份

普通销售、经理、店长可以在：

> **角色权限 + 具体权限 + 数据范围 + 对象状态**

允许的范围内访问对应 PC 业务管理能力。

不能因为页面属于 `/admin` 或“PC 后台”就要求必须使用 System Admin 身份。

### System Admin

System Admin：

- 使用独立系统身份；
- 负责 System Admin 自身账号与系统级治理能力；
- 不因为 System Admin 身份自动获得 CRM、车源、价格、锁车、交易纠错等员工业务权限；
- 如果同一真人同时需要执行员工业务，必须使用其独立员工身份。

### 4S 成员

4S 成员默认不进入名邦 PC 业务管理后台。

其车辆日常管理继续通过统一员工端及自身允许范围完成。

## 10.1 公海配置

后台可配置：

- 待公海处理候选条件；
- 继续当前销售后的重新检查周期；
- 公海领取数量上限；

这些配置：

有未完成责任 / 保护业务的客户不能直接进入公海。

## 10.2 Recommendation 资格

Recommendation 资格是客户级业务资格。

只有同时满足：

## 10.3 Consultation

- `pending`
- `processing`
- `resolved`
- `invalid`

旧 PC 后台中把 `timeout` 当成 consultation 状态的口径废弃。

当前：

> **timeout 只能作为超时标记 / 提醒 / 筛选条件，不能成为第五个咨询主状态。**

咨询超时不自动关闭。

咨询负责人变更 / 转派必须保留历史与审计。

# 11. P07｜Lock / 候补 / 意向金 / Transaction / 退款

至少包含：

- Lock；
- 候补；
- 意向金事实；
- Transaction；
- 退款；
- 成交纠错 / 业务纠错；
- 相关历史 / 关联时间线。

## 11.1 Lock 时长

当前统一：

> **默认 72 小时，后台可配置。**

新 Lock 创建时按当时配置生成 `expires_at`。

之后修改默认锁车时长：

> **不追改已经创建的 Lock。**

已收意向金的 Lock 不因普通 72 小时超时自动释放。

## 11.2 候补

候补：

- 不占车辆；
- 不自动升级成 Lock；
- Lock 释放后仍需人工重新确认是否锁车。

后台不得提供“自动候补顶锁”开关。

## 11.3 成交纠错

旧后台规则中：

> “授权经理 / 店长 / System Admin 等按权限直接纠错”

正式废弃。

当前规则：

- 普通销售不能直接纠正已成交 Transaction；
- 具备对应交易纠错业务权限的经理 / 店长可以执行；
- 必须填写原因；
- 必须完整审计；
- 不做二级审批；
- **System Admin 身份本身不具备成交纠错业务权限。**

同一真人如果同时有 System Admin 和员工身份，必须使用员工身份执行交易纠错。

## 11.4 退款

退款主状态继续只保留：

- `pending`
- `refunded`

部分退款通过多笔实际退款事实表达，不新增 `partial` 主状态。

# 12. P08｜价格 / 查价 / 客户展示价覆盖

至少包含：

- 批发车阶梯加价；
- 加价开关；
- 每日查价额度；
- 客户等级查价权益；
- 单车客户展示价覆盖；
- 价格历史 / 审计。

## 12.1 单车客户展示价覆盖范围

旧后台如果只把覆盖价作为批发车能力：

> **正式废弃。**

当前覆盖价适用于：

- 批发车；
- 名邦车；
- 4S 合作车。

名邦 / 4S：

- 有覆盖价 → 显示覆盖价；
- 无覆盖价 → 显示当前客户标价；
- 客户标价为空 → “价格咨询”。

覆盖价只改变客户展示结果，不改内部价 / 原客户标价。

## 12.2 查价

批发车数字查价继续按：

> `customer + vehicle + listing_cycle`

控制。

每日基础额度后台配置。

客户等级支持：

- 每日次数限制；
- 无限查价。

正式 Recommendation 免费授予该车辆当前周期查价权。

普通分享不授价。

“价格咨询”不消耗数字查价额度。

## 12.3 禁止恢复费用体系

不得恢复：

- 服务费；
- 物流费报价；
- 检测费报价；
- 过户费报价；
- 预计到手价 / 到手价测算；
- 后台费用规则。

# 13. P09｜通知 / 飞书 / 提醒策略

名邦数据库仍然是业务事实唯一权威来源。

通知失败：

> **不能改变业务事实。**

## 13.1 员工飞书映射

维护：

> `employee_id ↔ 当前飞书接收身份`

员工更换飞书账号：

- 只更新当前通知路由；
- 不改变 employee_id；
- 不改变客户 owner；
- 不改变业务负责人；
- 旧映射保留必要审计。

员工 inactive 后：

> 不再向旧飞书身份发送新的个人业务通知。

## 13.2 当前明确的飞书主动提醒

可包括：

- 新明确咨询；
- 候补车辆释放；
- Lock 到期提醒；
- 供应异常；
- Transaction 重要变化；
- 咨询首次响应 SLA 超时大群告警；
- 当前仍有效的上游 incident 告警 / 恢复通知。

普通浏览、点击、埋点不逐条推送。

普通匹配 / 客户机会不恢复“个人飞书逐条推送”。

## 13.3 Consultation SLA

已有业务规则继续承接：

- 首次人工响应 SLA 默认 15 分钟；
- 后台可配置；
- consultation 创建时固化该次 deadline；
- 后续修改默认值不追改已经创建的 consultation；
- 超时不改变 consultation 主状态；
- 超时只产生提醒 / 告警。

## 13.4 夜间免打扰

当前继承：

> **23:00 ～ 次日 08:30，后台可配置。**

夜间：

- 业务继续运行；
- SLA / incident / 日志继续计时与入库；
- 主动飞书通知暂停。

恢复后重新判断事件是否仍有效：

- 已解决 / 已失效不机械补发；
- 仍然重要的异常再发送。

## 13.5 通知日志

通知必须能记录：

- 业务事件；
- 接收对象；
- 当前阶段；
- 发送时间；
- 当前状态；
- 失败 / 跳过 / 去重等结果。

具体持久化结构、重试机制、消息队列留 Phase 2。

## 13.6 R6 公海提醒的渠道边界

R6 已明确“必须提醒”的事项继续保留。

但 R6 未冻结“这些提醒必须使用飞书”。

因此 R12 不擅自把所有 CRM / 公海提醒扩大成飞书消息。

业务层只冻结：

> **提醒必须存在；具体展示形态在员工工作台 / PC / 飞书之间的承载，由后续低保真 / IA 与 Phase 2 在不改变业务结果的前提下实现。**

# 17. 配置统一原则

## 17.1 配置必须有明确业务归属

配置不建设一个脱离业务的“大杂烩配置中心”。

配置放回对应业务模块：

- Lock 时长 → P07；
- 公海 / CRM 提醒条件 → P06；
- 查价 / 阶梯加价 → P08；
- SLA / 夜间免打扰 / 飞书 → P09；
- Banner → P12；
- 上游集成 → P03；
- 权限 / 数据范围 → P04。

## 17.2 配置修改不能偷偷改写历史事实

已经创建并固化的业务对象：

- Lock `expires_at`；
- consultation 首次响应 deadline；

不得因为后来后台改默认配置而追溯重写。

## 17.3 配置变更可追溯

会改变业务行为、权限、安全或客户展示结果的重要配置必须记录：

- 修改前；
- 修改后；
- 操作人；
- 时间。

是否强制填写原因：

> 按对应业务规则执行；没有明确要求的，不额外强制。

# 19. 操作闭环扫描

## 19.1 权限配置闭环

员工 → 角色模板 → 个人覆盖 → 数据范围 → 生效 → 旧权限失效 → 关键变化审计。

闭环成立。

## 19.2 离职闭环

员工 inactive → 当前权限立即失效 → 客户 / 活跃业务交接 → 交接批次保留 → 新负责人继续处理 → 历史不改写。

闭环成立。

## 19.3 上游电话闭环

内部模式 → 当前权限校验 → `upstream_publisher_id` → 查看缓存 / 获取最新 → 成功更新 / 失败保留原事实 → 查看 / 拨打 / 刷新审计。

闭环成立。

## 19.4 公海闭环

候选条件 → 待公海处理 → 人工判断 → 公海 / 继续当前销售 / 指定移交 → 领取 / 分配 → 首次跟进提醒 → 历史 / 审计。

不存在“自动抢 owner”。

闭环成立。

## 19.5 Consultation 闭环

咨询创建 → pending → 实际处理 → processing → resolved / invalid；SLA 独立计时，超时只提醒，不造第五主状态。

闭环成立。

## 19.6 Lock / Transaction 闭环

Lock → 候补并行关系 → 意向金事实 → Transaction → completed / cancelled → 退款 / 纠错按权限处理 → 审计。

System Admin 不越权。

闭环成立。

## 19.7 价格闭环

上游 / 人工价格事实 → 阶梯 / 客户标价 → 单车客户展示价覆盖 → 查价权限 → Lock 价格快照 → 后续价格变更不改写历史。

三类车源覆盖规则已统一。

闭环成立。

## 19.8 Banner / 公告闭环

PC 创建 / 编辑 → 启用 / 生效窗口 / 排序 → 客户端展示 → 停用 / 到期 → 历史和审计。

闭环成立。
