# 二、R10-01～R10-79 最终结论

## R10-01｜客户端车源页的两级结构

客户端一级车源切换固定为：

> **批发车源｜名邦车源｜4S店车源**

- 默认进入：**批发车源**。
- “名邦第一、4S第二、批发第三”不是一级频道顺序，而是 **批发车源页面内部展示顺序**。
- 批发页内部依次为：
  1. 名邦车源机会块 / 入口；
  2. 4S店车源机会块 / 入口；
  3. 正常批发车源列表。

**覆盖旧误判：**废弃“一级默认名邦、一级顺序名邦→4S→批发”的错误理解。

## R10-02｜分享直达车辆详情

- 分享打开后直接进入 **同一套车辆详情业务页**，不复制一套“分享版详情页”。
- 只有“分享直达态”底部额外显示：**查看更多车源**。
- 点击后进入正常车辆首页。
- 小程序内部正常进入详情时，不显示这个分享态底部入口。
- 分享直达不能绕过车辆当前可见性和业务权限。

## R10-03｜车辆详情核心参数

固定前六项：

1. 上牌时间
2. 表显里程
3. 变速箱
4. 排量 / 能源
5. 车身 / 内饰颜色
6. 车辆位置

新能源有效数据存在时追加：

7. 电池容量
8. 纯电续航
9. 总功率

展示规则：
- 普通燃油车通常为 **2×3**；
- 新能源三项数据齐全时可为 **3×3**；
- 新能源字段不适用或无有效数据时整项隐藏，不显示 `--`、0 或空白占位。

## R10-04｜员工车辆详情内部模式

员工端车辆详情默认始终是 **客户安全视图**。

进入内部模式：
> **长按价格区域约 3 秒**

内部能力按来源、权限、数据范围和车辆状态裁剪，可包含：
- 内部价 / 批发价；
- 上游电话；
- 编辑车辆资料；
- 调价；
- 上 / 下架；
- 客户展示价覆盖；
- 一键转名邦；
- 隐藏 / 恢复显示。

权限原则：
- 进入内部模式本身不另设独立权限；
- 名邦员工进入内部模式后可查看内部价 / 批发价，不再另设“内部价查看权限”；
- 4S 成员不可查看名邦内部价 / 批发价；
- 电话、隐藏 / 恢复、调价、上下架、客户展示价覆盖等敏感动作仍按各自具体权限控制；
- 无相应具体权限时，对应敏感按钮 **完全不显示**，不是灰色禁用；
- 后端在提交敏感动作时仍必须重新校验当前权限、数据范围和车辆状态。

内部模式只在当前员工、当前车辆、当前访问过程内有效。返回、离开详情、重新打开、切换车辆、分享、推荐、长时间进入后台后再返回等，都恢复客户安全视图，不长期记住内部模式。

## R10-05｜员工端 E02 车辆列表

- E02 与客户端使用同一套基础浏览 / 搜索 / 筛选结构，但业务入口按员工权限裁剪。
- 列表卡片不放推荐、锁车、隐藏、调价、上下架等快捷经营按钮；列表职责是找车、识别车辆、进入详情。
- 隐藏车辆不混入默认列表；有权限员工通过 `更多 → 隐藏车源` 查看，进入详情内部模式恢复显示；无权限不显示入口。

E02「更多」当前内容：
- 新增车源
- 草稿车源
- 隐藏车源
- 分隔后：能源类型、排量、颜色、变速箱

**已删除：客户专属。**

普通车辆卡片至少包含：
- 主图；
- 完整车型名称；
- 客户展示价格 / 价格咨询 / 查看价格；
- 上牌时间；
- 表显里程；
- 车辆位置；
- 车源类型；
- 上架日期；
- 必要业务状态，例如已锁定。

补充：
- “上架日期”只展示日期值；
- 隐藏 / 下架 / 已售车不在正常列表；
- 已锁定但仍在售车辆可继续显示；
- 来源切换保留当前搜索、筛选、地域、排序上下文。

## R10-06｜车辆详情外层操作与锁车入口

客户端普通可售车辆：

被其他客户锁定：
> **收藏｜登记候补**

“联系顾问”作为次级入口。

员工车辆详情外层高频操作：
> **推荐给客户｜锁车**

不需要先进入内部模式，但仍受权限、数据范围、车辆状态、客户资格校验。

锁车入口调整：
- 删除独立的 `CRM客户详情 → 锁车 → 再选车辆` 快捷入口；
- 保留 `车辆详情 → 锁车 → 选择客户`；
- 客户“我要这辆车”已形成客户+车辆上下文时，员工直接进入最终锁车确认；
- 员工在找车需求 / 候选车辆上下文中客户+车辆已明确时，同样直接最终确认；
- 客户“我要这辆车”本身 **不是正式 Lock**。

## R10-07｜“我要这辆车”立即进入员工工作台

客户点击“我要这辆车”后，立即进入负责员工工作台，不等待临近 SLA。

待办卡片至少显示：
- 客户；
- 车辆；
- 车源类型；
- 点击 / 提交时间；
- 负责人；
- 当前状态 / SLA。

可执行：
- 联系客户；
- 查看详情；
- 有权限且车辆可锁时：确认锁车。

“确认锁车”时客户和车辆已明确，不重复选择。

## R10-08｜“我要这辆车”归入咨询类工作台任务

不新增第 9 个独立一级任务类型。

“我要这辆车”归入 **咨询 / 客户服务待处理类**。

咨询类内部优先级：
1. 已超时；
2. 即将超时；
3. 新咨询 / 新要车意向。

员工完成第一次真实人工服务动作后，新咨询待办可从紧急队列消失，但对应咨询业务对象仍可继续处于“处理中”。复杂处理回对应咨询 / 锁车等业务模块。

4S 员工使用同一员工小程序，不另做一套 App。

- 找车服务；
- 咨询经营；
- 推荐；
- 锁车；

保留：
- 车辆浏览；
- 自己有权限管理的 4S 车源能力。

本质是 **同一 IA + 权限裁剪**。

## R10-11｜手机号作为人工服务硬门槛

手机号是人工服务动作硬门槛，包括：
- 我要这辆车；
- 登记候补；
- 提交帮我找车；
- 联系 / 咨询顾问；
- 后续需要进入人工服务链的动作。

无手机号时触发绑定 / 授权。

授权成功：保存手机号并自动继续刚才动作，不要求再次点击。

授权拒绝：
- 不创建正式人工服务业务对象；
- 不创建咨询 / 要车意向；
- 不创建候补；
- 不创建正式找车申请；
- 不进入顾问服务链。

普通浏览、收藏等非人工服务动作不受手机号门槛影响。

## R10-12｜已售 / 下架车辆历史详情

已售、下架车辆不再出现在正常在售 Feed，但客户如果已有 Recommendation、咨询、锁车、交易等历史业务，可从自己的历史记录进入历史详情。

历史详情中不得重新发起：
- 我要这辆车；
- 登记候补；
- 新 Lock 等新的在售业务动作。

若客户本身存在咨询、锁车、交易等历史业务，可从自己的历史业务记录进入对应历史详情。

**旧分享链接不等于永久查看权限。**

## R10-16｜客户端「帮我找车」完整业务结构

申请与正式需求分离：
> 手机号门槛 → 找车申请 pending → 员工处理 → 激活后生成正式 demand

客户端工作区允许同时管理：
- 活跃需求；
- 待处理申请；
- 已暂停需求；
- 推荐结果；
- 已结束需求；
- 新建需求。

状态文案必须真实：
- 待处理申请：等待服务确认；
- 已激活但条件仍在整理：顾问整理条件；
- 条件进入正式匹配：匹配中；
- 某些条件未知时，可继续使用已明确条件，不要求全部补完。

找车申请最低必填：
> **想找什么车**

预算可选；年款、里程、车况、颜色、地域、其他要求等均可作为可选条件。

pending 申请客户可以编辑同一申请，也可以主动撤回；撤回后关闭，不生成正式需求。

推荐车辆在客户端找车工作区只负责展示 / 查看详情，不直接在卡片放“我要这辆车”；进入统一详情后再走正常 CTA。

被推荐车辆后续售出 / 下架 / 不可公开时，推荐历史仍保留，可看历史详情，但不能发起新的在售动作。

客户可以暂停、恢复、结束自己的正式需求；暂停保留历史推荐；结束后未来如仍要找车，建立新需求。

员工 E05 找车详情包含：
- 客户原始找车要求；
- 销售匹配描述；
- 解析后的标准化条件；
- 备注；
- 跟进；
- 候选车辆及候选等级等。

需求上下文中候选车可“推荐给客户”，有权限且车辆可锁时可直接锁车；客户已明确，不重复选择。

## R10-17｜Recommendation 正式推荐

客户端“我的推荐”只展示 **正式 Recommendation**，不混入自动候选、Source Radar、系统匹配但未正式推荐的车辆。

推荐记录至少包括：
- 车辆；
- 推荐时间；
- 推荐销售；
- 关联找车需求（如有）；
- 当前车辆状态；
- 当前 listing_cycle 的价格访问情况。

不建立独立“接受 / 拒绝”推荐状态机。

即使找车需求结束、销售离职、客户 owner 变化、车辆售出，推荐历史仍保留。

Recommendation 授予的免费查价只作用于 **当前 listing_cycle**，新周期不自动继承。

员工入口：
- 车辆详情 → 推荐 → 选择客户；
- CRM 客户详情 → 推荐车辆；
- 找车需求候选上下文 → 客户已明确，直接推荐。

正式推荐权限仍受 R7 的 owner / 服务责任规则约束，不能利用 UI 绕过。

## R10-18｜收藏

收藏：
- 不要求手机号；
- 不要求先完善头像 / 昵称；
- 点击后先正常完成收藏。

车辆状态变化：
- 隐藏：收藏关系保留，显示“车源暂不可查看”；
- 下架 / 已售：收藏关系保留，进入历史状态；
- 同一 `vehicle_id` 后续重新上架：收藏关系可继续存在。

新的 listing_cycle 价格权限重新判断，不继承旧周期查价权。

员工 CRM 默认只看到收藏数量和聚合兴趣，不默认开放完整收藏明细。

## R10-19｜咨询

客户端入口：我的咨询；员工入口：E06 咨询业务。

核心状态：
- pending
- processing
- resolved
- invalid

同一 `customer + vehicle + listing_cycle` 若已有未终结咨询，后续相关动作复用原咨询，不重复创建。

resolved / invalid 后，后续新的真实咨询意图可以建立新咨询对象，不复活旧对象。

交易完成不自动把咨询强制改成 resolved。

## R10-20｜我的锁车 / 候补

客户端“我的锁车 / 候补”区分当前与历史。

普通 Lock：
- 显示当前有效到期时间；
- 员工延长后同步新到期时间；
- 可显示“已延期”。

支付真实意向金后：
- 车辆进入持续占用；
- 不再显示普通倒计时；
- 显示 **已支付意向金 · 车辆持续锁定中**；
- 可以显示客户自己实际支付的意向金金额。

候补：
- 展示当前候补和历史候补；
- 不显示“第几名”等队列排名，因为候补不是自动排队自动晋升机制。

---

## R10-21｜我的交易

客户端“我的交易”可分：
- 当前交易；
- 已完成；
- 已取消。

至少显示：
- 车辆；
- 当前交易状态；
- 创建时间；
- 当前负责人；
- 客户自己的意向金 / 支付事实。

已取消 / 已完成交易记录继续保留，历史交易不能直接重新生成旧 Lock。

发生换车时：旧交易 / 旧 Lock 保留历史，新车辆建立新的 Lock / Transaction。

## R10-22｜公告与个人资料

客户端不建设泛化“消息中心”，当前保留 **公告**，用于 active / history 公告。

个人资料包含：
- 头像；
- 昵称；
- 手机号；

## R10-34｜内部操作按车源类型裁剪

**批发车源：**
- 普通名邦销售可进入内部编辑 / 详情页面查看完整详细参数；
- JYT 上游原始车辆事实和上游原始价格只读，禁止普通人工改写；
- 名邦员工进入内部模式后可查看内部 / 批发价，不另设“内部价查看权限”；
- 上游电话、客户展示价覆盖、隐藏 / 恢复等继续按对应具体权限控制；
- 普通名邦销售默认可用“一键转名邦”，不另设独立权限门槛；
- 4S 成员不可用“一键转名邦”。

**名邦车源：**
- 在数据范围内可管理车辆，不以“是否本人上传”为权限边界；
- 调价、上下架、客户展示价覆盖、隐藏 / 恢复继续按对应具体权限控制。

**4S 车源：**
- 名邦员工在数据范围内可管理，不以“是否本人上传”为权限边界；
- 4S 成员仍按其自身可管理车辆范围操作；
- 调价、上下架、客户展示价覆盖、隐藏 / 恢复继续按对应具体权限控制。

**4S 成员公开浏览：**

- 可以看到正常对外展示价格；
- 对外展示价不等于内部价 / 批发价；
- 4S 成员不能查看名邦内部价 / 批发价。

关键规则：**客户展示价覆盖适用于批发、名邦、4S 三种来源。**

内部菜单裁剪顺序：
> 先按身份 / 车源类型裁剪 → 再按具体权限 / 数据范围 / 当前状态裁剪。

## R10-38｜搜索、排序、车型选择和筛选

### 搜索框
搜索框与 **帮我找车匹配引擎** 使用同一套确定性解析 / 匹配字典规则，不是简单关键词搜索。

例：`26款 奥迪A6` 可直接解析品牌、车系、年款等结构化条件。

### 手动车型选择 UI
表现为：
> 品牌 → 车系 → 年款分组 → 具体车型 / 款式

但底层主数据仍遵守 R3：
> 品牌 → 车系 → 具体车型

年款是具体车型结构化字段 / UI 分组，不是额外主数据实体。

### 品牌选择器
- 品牌搜索；
- 热门品牌；
- A-Z 分组；
- 右侧 A-Z 快速索引。

### 年款分组多选
- `2026款（全部车型）` 可一键选中该年款全部具体车型；
- 可同一年款选多个具体车型；
- 可跨多个年款多选。

### 主筛选栏顺序
> **排序｜品牌/车系｜价格｜年份｜里程｜更多**

### 排序
1. 最新上架（默认）
2. 价格低→高
3. 价格高→低
4. 年份新→旧
5. 年份旧→新
6. 里程少→多
7. 里程多→少

**删除综合排序。**

### “年份”定义
主筛选“年份”= **首次上牌年份**，不是车型年款；采用区间，例如 2020–2025。

### 价格筛选
按当前真实客户展示价参与判断；即使客户尚未解锁数字价格也照常参与。明确数字价格区间下，“价格咨询”车辆不参与。不得按内部批发价 / 上游原始价筛选。

### 里程
按当前表显里程范围筛选，支持最小、最大、单侧；搜索解析到的里程条件落到同一结构化字段。

### 更多
- 能源类型：多选；
- 排量：数值范围，例如 1.8–2.0，2.0–2.0=精确 2.0；
- 颜色：多选；
- 变速箱：多选。

### 已选条件标签
筛选栏下方显示 chips，小标签可直接删除。

层级删除：
- 删除具体车型 → 保留品牌+车系；
- 删除车系 → 清依赖具体车型，品牌保留；
- 删除品牌 → 其下车系 / 具体车型依赖一起清除。

其他标签包括价格区间、上牌年份区间、里程、颜色、变速箱、能源、排量等；保留“重置”能力。

## R10-56｜头像 / 昵称完善提醒

- 每日主动提醒总量最多 **10 次**；
- 多个触发同时命中只提醒一次。

如果用户正在执行“我要这辆车”、候补、找车提交等关键业务，资料提醒不能中途阻断，可延后到合适节点。

用户可以跳过 / 关闭。

覆盖旧规则：每天最多一次、第5/10台车、30分钟冷却、每天最多4次等。

## R10-64｜新增车源与已有草稿

采用 **多草稿模式**。

原草稿统一在“更多 → 草稿车源”管理。

空白草稿控制：
- 刚进入新增页，什么有效内容都没填就退出 → 不生成草稿；
- 开始填写有效车辆资料 / 上传内容后 → 自动保存为草稿。

因此：
- 新增车源 = 新建；
- 草稿车源 = 找旧草稿继续。

## R10-65｜VIN 重复

人工车辆 VIN **不是必填字段**。

没填 VIN：不做 VIN 重复 Gate，不能用车型、年款、里程、相似描述猜同一台车并阻止发布。

填了 VIN：正式发布时做 **完全一致 VIN 精确查重**。

若当前已有名邦 / 4S 人工车辆使用相同 VIN：阻止普通正式发布，并明确提示：
> **检测到相同 VIN 的现有车辆，请确认是否重复录入。**

提供：
- 查看已有车辆；
- 返回修改。

查看已有车辆 → 打开疑似重复车辆的员工详情；返回修改 → 回当前草稿且已填数据完整保留。

普通员工不提供“忽略并继续发布”。特殊历史数据纠错以后由专门权限 / 工程机制处理。

- 新增成功后返回当前草稿；
- 自动选中刚新增的车型；

## R10-68｜车辆详情微信官方分享与来源归因

- 群聊；
- 朋友圈（按微信小程序当时官方实际能力接入）。

- 哪个员工分享；
- 或哪个客户分享；
- 哪台车辆；
- 必要来源链。

技术字段名本阶段不冻结。

归属原则：
- 已有客户打开别人的分享，不抢原 owner；
- 新客户通过有效销售分享进入，按 R5 当前规则建立对应归因 / 归属；
- 客户转介绍按 R5 规则处理。

普通分享：
- 不自动创建 Recommendation；
- 不赠送批发查价权限；
- 不携带员工内部模式；
- 不泄露内部价 / 上游电话等敏感信息。

## R10-69｜车辆分享卡片展示内容

- “点击查看车辆详情”等引导。

不把动态 / 受权限价格写死到分享卡片。

分享卡片不直接展示：
- 客户展示价；
- 内部批发价；
- VIN；
- 上游电话；
- 内部状态。

真正打开详情后，再按接收人的身份、权限、车辆当前状态实时计算展示。

旧分享消息无需追回，但再次打开时必须按车辆最新状态判断，不能因旧分享继续查看已不可公开内容。

## R10-70｜“在售车源 / 今日新增”统计口径

两个数字是 **全站公共统计**，不随当前频道、搜索、筛选变化。

在售车源：统计当前客户端真正可公开浏览的全部在售车辆，包含批发、名邦、4S。

不计入：
- 隐藏；
- 下架；
- 已售；
- 草稿；
- 未通过审核；
- 其他不可公开车辆。

Priority 保护车辆不是普通公共可见车辆，**不计入普通首页公共在售总数**。

今日新增：统计今天第一次进入系统并正式公开在售、且当前仍可公开浏览的新车辆。

## R10-71｜首页统计数字不可点击

不：
- 点击跳转；
- 自动筛选；
- 切换来源；
- 建立跨三来源“全部车源列表”。

用户找车继续使用搜索、来源频道、筛选。

## R10-72｜上架日期、最新上架与今日新增

列表卡片“上架日期”使用 **当前 listing_cycle 的正式上架日期**，不是车辆第一次录入系统的历史日期。

例如 9月1日首次上架、9月10日下架、9月19日重新上架，当前卡片显示 09-19。

“最新上架”排序也使用当前 listing_cycle 上架时间。

“今日新增”与之区分：只统计今天 **首次进入系统并正式在售** 的新车辆；历史车辆重新上架不计入“今日新增”。

## R10-73｜“价格咨询”在价格排序中的位置

没有有效数字价格、显示“价格咨询”的车辆，在价格排序时统一排在所有有数字价格车辆之后。

- 价格低→高：数字价格低→高 → 价格咨询
- 价格高→低：数字价格高→低 → 价格咨询

多台“价格咨询”之间按 **最新上架优先**。

不能把“价格咨询”当 0 元、无限大或排序第一。

---

## R10-74｜批发车辆尚未解锁价格时怎么显示

有限查价次数客户，如果该批发车辆当前 listing_cycle 尚未解锁：
> **查看价格**

不显示 `****`、`¥?` 或假价格。

点击后如需要消耗 1 次额度，弹轻量确认，例如：
> 本次将使用 1 次今日查价机会，今日剩余 X 次。

确认后消耗额度并显示真实客户展示价。

不需要消耗的情况：
- 本车当前周期已经解锁；
- Recommendation 已赠送当前周期查价；
- 客户等级为无限查价；
- 本车实际为“价格咨询”。

“价格咨询”不消耗数值查价次数。

列表 / 详情任一处成功解锁后，另一处同步显示真实价格，不重复扣。

---

## R10-75｜未解锁批发价格仍参与真实价格排序

即使客户页面只看到“查看价格”，车辆仍按真实客户展示价参与价格低→高 / 高→低排序。

例如：A 实际10万未解锁、B 12万已解锁、C 15万未解锁，低→高仍为 A→B→C；页面仅分别显示“查看价格 / 12万 / 查看价格”。

排序准确性不受是否已解锁影响；“价格咨询”继续按 R10-73 放最后。

## R10-76｜车辆被锁定 / 进入交易后是否继续出现在客户列表

只要车辆底层仍属于 **在售**，即使已经：
- 普通 Lock；
- 已支付真实意向金进入持续占用；
- 已进入交易处理中，

仍可继续保留在客户正常车辆列表。

对其他普通客户统一只暴露：**已锁定**。

不公开：
- 谁锁的；
- 是否已交意向金；
- 意向金金额；
- 内部交易进度；
- 具体交易状态。

其他客户仍可登记候补。

车辆最终已售、正式下架或其他原因退出公开在售时，才从普通列表消失。

这种仍公开显示、允许候补的已锁车辆仍计入“在售车源”数量。

## R10-77｜客户列表区分“自己的锁车”和“别人锁车”

当前客户自己有有效 Lock：
> **我的锁车**

被其他客户锁定：
> **已锁定**

员工客户安全视图不使用“我的锁车”这种客户个人视角文案，员工按车辆真实经营状态显示。

## R10-78｜客户列表多业务状态显示优先级

同一车辆若命中多种当前客户本人业务关系，只显示最高优先一个，不堆多个标签。

优先级：
1. **我的交易**
2. **我的锁车**
3. **我的候补**
4. **已锁定**

该顺序与车辆详情 CTA 状态矩阵保持一致。

---

## R10-79｜员工车辆列表的占用状态

员工端 E02 不使用“我的锁车 / 我的候补”这类客户个人视角，而看车辆真实经营占用状态。

- 有有效普通 Lock → **已锁定**
- 已支付意向金、持续占用 → **已锁定**
- 已正式进入 Transaction → **交易中**
- 无占用 → 不显示占用标签

同时命中时：
> **交易中 > 已锁定**

列表不直接显示客户姓名、手机号、意向金金额、详细交易进度。

要查看谁锁的、负责人、Lock 时间、Transaction 信息，进入车辆详情 / 锁车业务 / 交易业务页面。

# 三、R10 期间同步确认的锁车补充规则

## 1. 普通 Lock 可以延期

授权员工可在锁车管理中手动延长普通 Lock，修改同一个 Lock 的有效期，不重新创建第二个 Lock。

必须审计：
- 原到期时间；
- 新到期时间；
- 操作人；
- 操作时间。

客户端“我的锁车”同步显示新到期时间，可显示“已延期”。

## 2. 支付真实意向金后不再按普通锁车自动释放

客户真实支付意向金 / 定金事实成立后，车辆进入持续 / 长期占用状态，不再因原 72 小时 Lock 到期自动释放。

必须有明确业务结果才结束，例如继续成交、取消、换车或其他正式结束动作。

客户端此时不显示普通倒计时。

# 四、R10 已明确废弃 / 覆盖的旧规则

R11 滚动合并后，以下旧方向也不得恢复：
