# 2. R11 核心定位

R11 管理的是：

> 员工在车辆详情中的客户安全视图、内部模式、敏感信息展示、敏感操作入口、权限裁剪、异常退出与审计边界。

内部模式本身不是一套新的权限系统，而是：

> **敏感能力的承载入口。**

进入内部模式之后，系统仍然需要根据：

1. 车源类型；
2. 员工身份；
3. 数据范围；
4. 具体权限；
5. 当前车辆状态；

决定最终显示哪些敏感信息、哪些按钮可以操作。

---

# 3. 客户安全视图

员工进入车辆详情时，默认始终进入：

> **客户安全视图**

客户安全视图与客户端对外展示口径一致，不展示员工内部敏感信息。

至少不得展示：

- 内部价；
- 批发价；
- 上游发布人电话；
- 员工内部备注；
- 其他只允许内部查看的敏感信息。

## 3.1 后端隔离

客户安全视图不能只靠前端“隐藏按钮 / 隐藏文字”。

原则：

> **敏感字段应从数据返回层就按照当前模式和权限进行隔离。**

不能出现：

- 后端把全部敏感字段返回；
- 前端只是视觉隐藏；
- 切换模式、缓存、页面恢复或调试后又泄露敏感内容。

---

# 4. 内部模式进入方式

员工端车辆详情：

> **长按价格区域约 3 秒进入内部模式。**

内部模式不单独增加“能不能进入内部模式”的权限开关。

即：

> 员工可以进入内部模式，但进入之后看到什么、能做什么，仍按具体权限和数据范围逐项裁剪。

不能理解为：

> 进入内部模式 = 自动获得全部敏感权限。

---

# 5. 内部模式生命周期

内部模式只对：

> 当前员工 + 当前车辆 + 当前一次访问过程

有效。

以下情况恢复客户安全视图：

- 返回上一页；
- 离开车辆详情；
- 重新打开车辆详情；
- 切换到另一辆车；
- 分享车辆；
- 推荐车辆；
- 页面重新进入；
- 长时间进入后台再返回；
- 员工身份 / 权限发生变化后重新校验。

内部模式不能长期记忆为全局状态。

---

# 6. 内部价 / 批发价

最终冻结：

> **内部价 / 批发价必须进入内部模式后才能查看。**

默认客户安全视图绝不展示。

## 6.1 名邦员工

普通名邦销售进入内部模式后：

> **可以查看内部价 / 批发价。**

不再为“查看内部价 / 批发价”单独设置一层独立权限。

## 6.2 4S 成员

4S 成员：

> **不能查看名邦内部价 / 批发价。**

但 4S 成员仍然可以正常浏览所有公开车源，并查看所有车源当前正常对外展示的价格。

即：

- 批发车源：看客户对外展示价；
- 名邦车源：看当前对外展示价；
- 4S 车源：看当前对外展示价；
- 价格咨询车辆：显示“价格咨询”。

必须严格区分：

> **对外价格 ≠ 内部价 / 批发价**

---

# 7. 上游发布人电话

电话继续保留独立权限开关。

## 7.1 归属维度

最终规则：

> **上游电话属于上游发布人维度。**

稳定身份为：

`upstream_publisher_id`

获取最新电话、电话缓存、电话历史均按：

> **上游发布人维度**

处理。

不再使用任何其他旧口径。

## 7.2 展示

有电话权限：

- 内部模式中显示电话区域；
- 可以查看 / 拨打；
- 可以执行“获取最新电话”。

无电话权限：

> **整个电话区域不显示。**

## 7.3 审计

电话相关敏感动作必须可追溯，包括：

- 查看；
- 获取最新电话；
- 拨打；
- 刷新成功 / 失败结果；
- 操作人；
- 操作时间。

---

# 8. 名邦销售可管理车辆范围

最终冻结：

> **名邦销售管理人工车辆时，不再区分“自己上传”还是“其他人上传”。**

在正常数据范围内，名邦销售可以管理：

- 自己上传的名邦车；
- 其他名邦员工上传的名邦车；
- 名邦员工上传的 4S 合作车；
- 4S 成员上传的 4S 合作车。

“是否本人上传”不再作为名邦销售车辆管理边界。

但：

> **能管理哪些车辆，与能执行哪些敏感操作是两层规则。**

数据范围决定：

> 能管哪些车。

独立敏感权限决定：

> 能做哪些高风险操作。

---

# 9. 批发车内部详情

普通名邦销售：

> **可以进入批发车源的内部编辑 / 详情入口，查看完整详细参数。**

但必须区分：

## 9.1 可以查看

可以查看：

- 批发车完整车辆参数；
- 名邦内部业务信息；
- 内部价 / 批发价；
- 其他当前允许显示的内部信息。

## 9.2 上游原始事实只读

JYT 上游原始车辆事实和上游原始价格：

> **只读，不允许普通人工修改。**

名邦员工可以查看，不代表可以改写上游事实。

## 9.3 名邦自己的业务动作

名邦自己的业务字段和业务动作，继续按照当前规则和权限处理，例如：

- 隐藏 / 恢复；
- 客户展示价覆盖；
- 一键转名邦；
- 其他名邦本地业务操作。

---

# 10. 一键转名邦

最终冻结：

> **普通名邦销售默认可以对批发车执行“一键转名邦”。**

不再额外设置“一键转名邦”独立权限门槛。

边界：

- 仅名邦员工侧开放；
- 4S 成员不具备该能力；
- 转换后继续继承既有 R2 车源转换规则；
- 必须保留来源关系和审计。

---

# 11. 隐藏 / 恢复显示

隐藏 / 恢复显示继续保留独立权限控制。

即：

有隐藏管理权限 + 对应数据范围：

> 内部模式显示“隐藏 / 恢复显示”。

无权限：

> 该操作入口完全不显示。

隐藏 / 恢复与真实上下架不是同一概念。

隐藏只是平台展示层状态，不等于车辆真实下架。

---

# 12. 调价

调价继续保留独立权限控制。

有调价权限：

> 内部模式显示调价入口。

无调价权限：

> 不显示调价入口。

“名邦销售可以管理这辆车”不等于自动获得调价权限。

---

# 13. 上下架

上架 / 下架继续保留独立权限控制。

有权限：

> 显示对应操作入口。

无权限：

> 不显示。

真实上下架会影响车辆生命周期，因此继续作为敏感操作处理。

---

# 14. 客户展示价覆盖

最终业务规则：

> **客户展示价覆盖适用于批发、名邦、4S 三类车源。**

但该操作继续保留独立权限控制。

有覆盖权限：

> 内部模式显示覆盖价操作。

无权限：

> 不显示。

## 14.1 名邦 / 4S 价格回退逻辑

名邦 / 4S：

- 有覆盖价 → 对外显示覆盖价；
- 无覆盖价 → 显示当前最新客户标价；
- 客户标价为空 → 价格咨询。

覆盖价：

> 只覆盖展示结果，不改原客户标价，也不改内部价。

覆盖期间客户标价仍可以正常更新。

取消覆盖后：

> 回到取消时最新客户标价。

---

# 15. 编辑人工车辆

名邦销售在正常数据范围内：

> 可以编辑人工车辆，不再区分本人上传 / 他人上传。

这属于基础车辆管理能力。

但：

- 调价；
- 上下架；
- 隐藏 / 恢复；
- 客户展示价覆盖；

仍然按照独立权限判断。

---

# 16. VIN / 原始敏感档案

完整 VIN、行驶证、绿本、保单等原始敏感车辆资料：

> 作为车辆内部编辑 / 管理资料的一部分。

不再额外建立一套独立“VIN 查看权限 / 原始档案查看权限”。

只要员工：

- 对该车辆有有效编辑 / 管理权限；
- 且车辆在其数据范围内；

即可在内部编辑 / 管理入口查看。

客户侧：

> 始终不展示完整 VIN 和原始敏感档案。

4S 成员：

> 只在自己有权管理的 4S 车辆范围内查看对应内部档案。

---

# 17. source_type 修改

旧规则“首次正式发布后 source_type 冻结”正式废弃。

当前最终规则：

> **正式发布后的 source_type 允许修改。**

只要员工对该车辆具备管理能力，就可以在：

- 名邦车源；
- 4S 合作车源；

之间进行来源纠正。

不再要求：

- 必须经理；
- 必须店长；
- 必须特殊纠错权限。

但必须审计：

- 修改前 source_type；
- 修改后 source_type；
- 操作人；
- 操作时间。

不强制填写原因。

## 17.1 修改后的权限重新计算

source_type 修改后：

> 当前可操作能力立即按照新的来源重新计算。

例如：

- 原 4S → 改成名邦后；
- 4S 成员不能因为自己过去上传过，就继续获得名邦车管理能力。

历史来源变化仍保留审计。

---

# 18. 4S 成员能力边界

4S 成员使用同一员工小程序，但按角色裁剪。

4S 成员：

可以：

- 浏览所有正常公开车源；
- 查看所有车源对外展示价格；
- 管理自己有权管理的 4S 车源；
- 编辑这些 4S 车的正常车辆资料；
- 按当前权限维护相应业务。

不能：

- 查看名邦内部价 / 批发价；
- 使用一键转名邦；
- 获得名邦车管理能力；
- 因进入内部模式而突破自己的数据范围；
- 自动获得电话权限；
- 自动获得调价 / 上下架 / 隐藏 / 覆盖等敏感权限。

---

# 19. 车型主数据权限不随车辆管理放开

名邦销售可以管理车辆，不代表可以修改车型主字典。

车型主数据继续独立使用：

`vehicle.model.manage`

普通销售不能因为上传 / 编辑车辆，就直接修改：

- 品牌；
- 车系；
- 具体车型；
- 车型映射；
- 车型合并；
- 其他车型主数据。

---

# 20. 权限撤销与旧页面失效

如果员工在页面已经打开后：

- 权限被撤销；
- 数据范围变化；
- 员工离职 / 停用；
- 车辆状态变化；

前端旧页面不能继续依赖旧权限执行操作。

原则：

> **敏感操作提交时，后端必须重新校验当前真实权限和对象状态。**

刷新 / 重进页面后：

- 被撤销的敏感数据消失；
- 被撤销的操作按钮消失。

不能因为之前进入过内部模式就继续保留旧权限。

---

# 21. 分享 / 推荐不能携带内部模式

任何：

- 分享；
- Recommendation；
- 外部链接；
- 客户打开详情；

都只能进入客户安全展示逻辑。

不得携带：

- 内部模式状态；
- 内部价；
- 批发价；
- 上游电话；
- 内部操作入口；
- 其他员工敏感信息。

---

# 22. 内部模式显示裁剪顺序

内部模式建议遵循统一裁剪逻辑：

> **先按车源类型裁剪 → 再按角色 / 数据范围 → 再按具体权限 → 最后按当前车辆状态裁剪。**

例如：

批发车：
- 可显示内部价 / 批发价；
- 可显示一键转名邦；
- 上游电话按电话权限显示；
- 上游原始事实只读。

人工名邦 / 4S：
- 可编辑业务资料；
- 调价 / 上下架 / 隐藏 / 覆盖按权限显示。

4S 成员：
- 再额外执行 4S 角色边界裁剪。

---

# 23. 高风险操作审计

以下敏感操作必须保留必要审计：

- 电话查看 / 获取最新 / 拨打；
- 调价；
- 上架；
- 下架；
- 隐藏；
- 恢复显示；
- 客户展示价覆盖；
- 取消覆盖；
- 一键转名邦；
- source_type 修改；
- 车辆关键资料修改；
- 档案重要修改；
- 其他敏感车辆管理动作。

至少能够追溯：

- 操作人；
- 操作时间；
- 操作对象；
- 操作结果；
- 修改前 / 后关键事实（适用时）。

# 24. R11 操作闭环

正常路径：

客户安全视图  
→ 长按价格区约 3 秒  
→ 进入内部模式  
→ 按来源 / 数据范围 / 权限 / 状态裁剪  
→ 查看允许的敏感信息  
→ 执行允许的敏感操作  
→ 后端重新校验  
→ 成功后刷新真实结果  
→ 离开详情  
→ 恢复客户安全视图

异常路径已经覆盖：

- 没权限；
- 权限被撤销；
- 员工停用；
- 车辆状态变化；
- 4S 数据范围不足；
- 上游字段不可修改；
- 电话无权限；
- 敏感操作提交失败；
- source_type 修改后角色能力变化；
- 分享 / 推荐不得携带内部状态。

---

# 25. R11 明确保留的独立权限

以下继续保留独立权限控制：

1. 上游发布人电话；
2. 隐藏 / 恢复显示；
3. 调价；
4. 上架 / 下架；
5. 客户展示价覆盖。

# 26. R11 明确取消的独立权限门槛

以下不再单独设置额外权限门槛：

1. 名邦员工内部价 / 批发价查看；
2. 名邦普通销售一键转名邦；
3. 名邦销售编辑非本人上传人工车辆；
4. source_type 修改的经理 / 店长 / 特殊纠错权限限制；
5. VIN / 原始档案独立查看权限。

注意：

> 取消单独权限，不等于取消数据范围和员工身份限制。
