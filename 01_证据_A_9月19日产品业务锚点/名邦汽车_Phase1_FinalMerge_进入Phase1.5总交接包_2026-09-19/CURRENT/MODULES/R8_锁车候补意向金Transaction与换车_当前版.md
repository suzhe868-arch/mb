## 3. 继续继承的既有核心规则

以下规则本轮整体复核后继续保留，不重新打开：

### 3.1 锁车唯一性

同一车辆同一时刻：

> **只能存在一个有效 Lock。**

同一客户可以锁不同车辆，但同一车辆不能同时被多个客户有效锁定。

---

### 3.2 候补

当车辆已经存在有效 Lock 时，其他客户可进入候补。

候补：

- 只形成排队 / 意向事实；
- **不会自动升级为锁车**；
- Lock 释放后，是否重新锁车仍需重新确认；
- 车辆单纯隐藏不结束候补；
- 车辆真实失效 / 已成交等才结束对应候补业务。

---

### 3.3 意向金

意向金属于：

> **真实收款事实。**

可以存在多笔记录。

意向金与 Lock、Transaction、退款分别作为独立业务对象保留关联，不把多个业务事实硬塞成一个状态。

已收意向金后：

> **不能仅因为普通锁车超时就自动释放车辆。**

---

### 3.4 Lock 与 Transaction

Transaction 必须基于当前有效 Lock 进入。

交易创建后：

- Lock 与 Transaction 建立明确关联；
- 历史锁车事实保留；
- 交易不能脱离原锁车事实凭空产生。

---

### 3.5 Transaction 取消

Transaction 正式取消后：

> **不自动恢复原来的旧 Lock。**

如果客户仍需要继续锁车：

> 重新创建新的 Lock。

旧 Lock 只作为历史保留。

---

### 3.6 供应异常

批发车 / 上游车已经进入锁车或交易后，如果上游车辆突然失效：

> **不能直接自动取消当前锁车 / 交易。**

系统应明确标记供应异常，由业务人员继续处理。

避免上游状态变化直接抹掉已经发生的客户业务事实。

---

### 3.7 退款主状态

继续采用已冻结规则：

> **退款主状态只保留 `pending / refunded`。**

部分退款不单独建立 `partial` 主状态。

实际部分退款通过：

> **多笔退款明细 / 实际退款记录**

表达。

不恢复复杂的 `partial / non_refundable` 等退款主状态体系。

---

### 3.8 锁车价格快照

正式锁车必须保存锁车发生时的客户有效展示价快照。

- 有数字价格 → 保存当时数字；
- 当时为“价格咨询” → 保存明确的“价格咨询”事实；
- 不允许用 0 或虚构价格代替。

后续价格变化不能改写历史锁车价格快照。

## 4. R8-01｜默认锁车时长

本轮正式冻结：

> **默认锁车时长 = 72 小时，后台可配置。**

规则：

1. 新 Lock 创建时，根据当时有效配置计算 `expires_at`；
2. Lock 创建完成后，该 Lock 的 `expires_at` 固化；
3. 后台以后修改默认锁车时长，不追改已经存在的 Lock；
4. 已收意向金的 Lock 不因为普通 72 小时超时自动释放。

本条正式覆盖旧资料中：

> 默认锁车 2 小时

的旧结论。

R8 当前统一以：

> **72 小时，可配置**

为准。

## 5. R8-02｜已成交交易纠错

### 5.1 本轮最终规则

普通销售：

> **不能直接撤销 / 纠正已成交 Transaction。**

具备对应业务权限的：

- 经理；
- 店长；

可以直接执行成交纠错。

成交纠错必须：

- 填写纠错原因；
- 保留完整审计；
- 记录操作人；
- 记录操作时间；
- 保留纠错前后的业务事实。

### 5.2 不做二级审批流

本轮一度讨论过：

> 经理发起 → 店长 / 另一名人员再次确认

经过第二遍风险复核后，发现该方案会重新引入 V1 已经不需要的二级审批流程。

因此该中间方案正式作废。

R8 当前最终采用：

> **权限控制 + 必填原因 + 完整审计**

而不是二级审批。

### 5.3 System Admin 边界

System Admin 属于独立系统身份。

因此：

> **System Admin 身份本身不具备成交纠错业务权限。**

如果某个真人同时具有：

- System Admin 身份；
- 员工身份；

其参与成交纠错时，必须使用：

> **具备对应业务权限的员工身份。**

不能因为拥有 System Admin 身份，就自动获得交易业务纠错权。

## 6. R8-03｜换车与旧意向金

V1 不单独设计复杂的“换车专用状态机”。

客户换车时：

1. 原车辆对应的旧 Lock / Transaction 按真实业务结果结束或取消；
2. 新车辆重新创建新的 Lock；
3. 新车辆需要 Transaction 时重新创建新的 Transaction。

如果旧车已经收取意向金：

> **旧意向金不能直接改挂 / 转移到新车。**

处理原则：

- 原交易按实际结果处理原意向金和退款；
- 新车需要意向金时，重新记录新的收款；
- 旧收款、旧退款、新收款分别保留真实资金历史。

本轮不建立：

> “意向金跨车转移”

机制。

这样确保：

> **钱的历史不因为换车被改写。**

---

## 7. 换车业务原则

换车不是修改原车辆 ID。

原则：

> **旧业务结束，新车辆重新建立新的锁车 / 交易关系。**

历史：

- 原车辆；
- 原 Lock；
- 原 Transaction；
- 原意向金；
- 原退款；

全部保留。

新车：

- 新 Lock；
- 新 Transaction；
- 新意向金记录；

重新建立。

不通过直接替换旧交易车辆的方式抹掉历史。

Recommendation / 咨询历史继续保留，但不替代 Lock / Transaction。
