# C1｜批发电话 / Collector 边界

当前冻结：

- 批发电话由 Collector / 采集端负责向上游获取，名邦端不直接绕过 Collector 调 JYT。
- 采集端电话接口业务形态：`POST /integrations/jyt/phone`，输入 `{car_code}`，返回 `{phone}`，内部 Key 鉴权。
- 名邦普通查看 / 拨打优先使用 `publisher_phone_cache`；缓存已有 phone 时可直接用，不因普通查看主动打上游。
- “获取最新电话”绕过普通缓存读取，通过 Collector 获取；成功后覆盖当前缓存。
- `publisher_phone_history` 只做审计 / 历史。
- 不同上游发布人可以并发；同一发布人的“获取最新电话”采用 single-flight 合并。
- 普通查看 / 拨打不调用上游。
- 上游 `user.id` 统一映射为：
  > `upstream_publisher_id`
- R11 / R12 后电话当前唯一身份维度统一为 `upstream_publisher_id`。
- 电话查看 / 拨打 / 获取最新电话继续是独立敏感能力并保留审计。
- 名邦侧配置 Collector Base URL、内部 Key，并支持连接测试。

# C2｜找车 Matching + Priority

当前冻结边界：

- 找车 demand 保留结构化条件，包括品牌、车系、具体车型、年款、里程、预算、偏好等。
- Matching 负责从当前可参与匹配的车辆中按结构化条件形成匹配结果。
- Priority 是客户 / 匹配权益层，不允许在后续实现中变成与普通 Matching 完全割裂的第二套车型匹配引擎。
- 客户归属、Matching、Priority、推荐、客户可见性必须分层，不能互相偷改 owner 或权限。
- 具体历史优先级、排他可见与隐藏车源边界，Phase 1.5 必须回查 C2 / C3 历史原件，防止摘要遗漏。

# C3｜隐藏 / 客户可见性

当前冻结：

- “隐藏”与“下架”严格不同。
- 隐藏：
  > 车辆仍然是有效在售车，只是暂时不进入客户端公开 Feed。
- 下架：
  > 当前真实在售结束 / 当前不可售。
- 隐藏车辆在员工后台仍可管理。
- 隐藏 / 恢复显示属于员工车辆详情 → 内部操作区的正式动作。
- 受权限、数据范围、当前车辆状态控制。
- 不采用车辆列表卡片“随手快捷隐藏”作为正式主操作。
- 适用场景包括资料待检查、临时不公开、客户专属可见性等。
- 上传后可以进入“立即公开 / 暂不公开”的业务选择。
- 隐藏与 Matching / Priority / 客户专属可见性的精确历史边界必须在 Phase 1.5 历史遗漏扫描中回查原 C2/C3 文件。

# C4｜Refund / 跨业务对象完整性

当前冻结并被 R8 / R12 继续承接：

- Refund 不能通过删除 Transaction / Lock / 意向金历史来“修正”。
- 退款主状态保持：
  - `pending`
  - `refunded`
- 部分退款用多笔实际退款事实表达，不新增 `partial` 主状态。
- `refund = pending` 不占车辆，不阻止车辆依据真实车源状态重新进入后续业务。
- Transaction 取消不自动恢复旧 Lock。
- 已成交纠错必须保留原成交事实与纠错审计，不直接擦除历史。
- 跨对象处理必须保证 Lock / Transaction / 意向金 / Refund / Vehicle 当前状态之间不互相伪造历史。

# C5｜图片模块

当前冻结摘要：

- 批发车保存上游图片 URL / 图片来源事实，不要求采集入库时把所有原图全部永久本地化。
- 客户实际浏览产生图片访问后，可以按当前图片缓存规则把已访问图片逐步保存 / 缓存到名邦侧，减少反复依赖上游 URL。
- 列表页重点保证首图可用；详情继续按实际浏览加载更多图片。
- 一键转名邦后，新名邦车图片需要进入名邦自有图片资产，不继续只依赖上游 URL。
- 转存过程允许：
  - 处理中
  - 成功
  - 部分失败
  - 失败
  并支持重试。
- 已经取得并保存到车辆记录中的上游图片链接，其后是否仍出现在上游新增列表，不反向决定名邦已保存事实是否存在。
- 图片模块业务规则已冻结；工程同步状态在 Phase 1 时仍属于后续工程闭环事项。
- Phase 1.5 必须回查完整图片模块最终包，确认缓存触发、失败处理、首图与详情图边界有没有被本摘要省略。
