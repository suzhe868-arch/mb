## CN3 已收口

- 电话：名邦 → Collector → JYT；电话按发布人 ID 查询；名邦不管理 JYT 电话凭证。
- 匹配：普通客户与 Priority 客户共用一套确定性匹配规则。
- Priority：只是在公共匹配结果上的“Priority 客户优先 + 默认 24 小时员工端独占”分支，不是 Lock 优先权，也不是独立复杂业务系统。
- Priority 客户资格：Customer 级，仅 System Admin 开关。
- Priority 可见性：正式 Recommendation 前客户不可见；负责销售和 `priority.view` 范围内人员可见；正式推荐后目标客户可见。
- Lock：不再读取 Priority 作为竞争条件。
- 权限：废弃 `priority.override`；不新增复杂 `priority.manage`；仅保留必要的 `priority.view`。
- Recommendation：增加最小 active/ended 生命周期，可晚于 Priority 结束。

## CN5 新增收口

- Transaction 取消：`biz_status` 从 `trading` 回到 `normal`，不再把 `unavailable` 混入业务状态轴；`source_status` 与 `platform_visibility` 保持真实当前值。
- Waitlist：车辆 `biz_status=completed`，或 `source_status=offline/unavailable/sold_external` 时，全部 active Waitlist 自动结束；仅 `platform_visibility=hidden` 不结束。
- 同一客户取得该车 Lock 时，只结束自己的 active Waitlist；其他候补继续保留。

## CN6 新增收口

- Refund：一张退款单必须且只能绑定 Lock 或 Transaction 其中一个主体；API 与 DB 统一。
- Refund 客户一致性：所选 Lock/Transaction 必须属于同一 `customer_id`。
- 业务链完整性：Demand / Recommendation / Consultation / Waitlist / Lock / Transaction 的来源引用增加组合外键，禁止跨客户、跨车辆串线。
- Lock 侧退款保留，用于已收意向金但尚未进入 Transaction 的场景；一旦存在 Transaction，退款归属 Transaction。
- PostgreSQL 16 真实 Apply/Replay 仍作为外部 Gate，不虚报运行态 PASS。

## CN7 新增收口

- 人工 Mingbang/4S 车辆允许 0 张真实图片正式发布。
- 图片数量不再属于发布必填门槛，也不进入 `PUBLISH_REQUIRED_FIELDS_MISSING`。
- 无真实图片时使用 `image.default_placeholder` 作为展示兜底；占位图不写成真实 `vehicle_images` 记录。
- 后续补充真实图片后自动使用真实图片展示。
