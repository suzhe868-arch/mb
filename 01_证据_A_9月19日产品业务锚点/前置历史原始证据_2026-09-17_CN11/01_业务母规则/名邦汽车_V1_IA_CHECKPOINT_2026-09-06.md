# 1. 编号规则

- `C`：Customer，客户微信小程序
- `E`：Employee，统一员工/销售端小程序
- `P`：PC Admin，管理后台
- `X`：External，外部系统/平台能力

一级模块使用 `C01 / E01 / P01 / X01`。  
一级模块内部页面使用 `C01-01 / E03-02 / P06-11`。

以下原则上不单独占一级 IA 编号：

- Bottom Sheet / 普通弹窗
- 搜索、筛选、排序面板
- 手机号授权弹层
- 头像昵称完善提示
- 客户公告自动弹层
- 图片全屏预览（全屏状态长按图片可唤起“保存图片”，用户确认后保存；不新增独立下载页/长期下载按钮）
- 价格解锁确认
- 推荐确认
- 锁车确认
- 候补确认
- 权限不足提示
- 员工车辆内部模式

它们属于页面状态、组件或操作层。

## C01 车源【一级 Tab】

客户浏览车辆的主入口。

### C01 主页面固定结构

- 在售车源总数
- 今日新增
- 城市/地区
- **顶部 Banner / 运营位：单个 Banner 区域，可轮播 3–5 张；首屏展示，页面下滑后自然离开视口；主要承载名邦自有车源、服务与活动。**
- 来源快捷切换
- 搜索
- 五个主筛选
- 独立排序
- 车辆 Feed
- 普通“分享车源”能力（Feed / 列表具体按钮视觉位置留低保真）

交互约束：
- Banner 不做多块广告墙；
- 下滑后 Banner 不吸顶；
- 搜索与核心筛选允许采用吸顶结构；
- Banner 内容由 PC 后台轻量配置；V1 仅支持图片、标题、可选跳转、排序、启停与有效期。
- Banner 只恢复已确认页面能力，不反向创造新的广告计费、人群定向、CPC/CPM、复杂投放计划、推荐算法或多运营位体系。

### 来源快捷切换

固定只有：

1. **批发车源**
2. **名邦车源**
3. **4S店车源**

其中：

- **批发车源默认选中**
- 客户进入 C01 默认显示批发车源 Feed
- 客户侧“全部车源”正式取消
- 切换来源时继续继承当前搜索、筛选、地区和排序条件

### 默认排序

固定：

**最新上架（默认）**

其他可选：

- 综合排序
- 价格从低到高
- 价格从高到低
- 年份从新到旧
- 里程从少到多

### 批发车源页顶部双入口

当来源为批发车源时，Feed 上方固定：

1. **名邦车源**
2. **4S店车源**

两个入口：

- 始终保留
- 与当前搜索、筛选、地区、排序使用同一套条件
- 有完全符合结果时，按当前排序取首个结果预览
- 无完全符合结果但该来源仍有在售车时，直接展示最接近当前条件的车
- “最接近”使用确定性 fallback：**车型/车系相关性 > 品牌相关性 > 年份接近度 > 价格接近度 > 里程接近度 > 地区接近度 > 颜色/其他普通筛选接近度 > 当前排序 tie-breaker**
- fallback 不使用 AI，也不调用正式 demand 匹配引擎；优先保持车型/品牌意图
- 不额外显示“暂无完全匹配”“为您展示相近车源”等无价值提示
- 该来源确实无任何在售车时，入口仍保留，显示简洁空态，不伪造车辆

### C01-01 客户车辆详情

从首屏开始使用固定自定义顶部导航：

- 有合法上一页：**返回 ｜ 分享车源 ｜ 车型名称 / 车辆标题**
- 从微信好友、朋友圈、二维码等外部直接进入且没有合法上一页：**主页 ｜ 分享车源 ｜ 车型名称 / 车辆标题**

规则：
- 返回 / 主页占同一个导航位置，二选一；
- “分享车源”固定存在；
- 顶部直接显示当前车辆车型名称 / 车辆标题；
- 微信右上角官方胶囊继续保留，自定义导航避开官方胶囊；
- 客户端“主页”回 C01 车源；
- 不采用首屏按钮覆盖车辆大图、下滑后切换吸顶或两阶段顶部导航；
- 不同时显示微信返回和另一套自定义返回；
- 不在详情底部新增“首页”按钮；
- 不增加长期显示的“店铺主页”大按钮；
- 图标、字号、间距留低保真。

客户安全详情，包括：

- 图片轮播
- 图片全屏预览
- 基础参数
- 客户展示价 / 价格咨询
- 车源方车况
- 名邦实际检测结果（如确实存在）
- 档案/报告
- 当前服务顾问
- 收藏
- 顾问咨询入口
- 车辆名称/完整车型与车况描述支持长按复制，成功轻量提示“已复制”；其余车辆结构化字段不专门提供复制交互
- 日期辅助区：配置开启时显示当前上架时间 + 人工车上传时间 / 批发车平台收录时间；默认可隐藏
- `VEHICLE_DETAIL` 运营位：复用 P12；无有效内容时整块隐藏

正常可售车辆底部核心 CTA：

**收藏 ｜ 我要这辆车**

被其他客户正式锁定时：

**收藏 ｜ 登记候补**

规则：

- 客户侧不直接提供正式“锁车”按钮
- “我要这辆车”只创建明确车辆意向/咨询
- 不自动锁车
- 不自动交易
- 不自动创建 demand
- “我要这辆车 / 登记候补 / 联系顾问”执行手机号服务门槛
- 收藏不要求手机号、头像或昵称

已售、已下架车辆不进入正常 Feed，但历史业务入口仍可复用 C01-01 查看历史详情。

# 3. 客户“帮我找车”

## C02 帮我找车 / 我的找车【一级 Tab】

“帮我找车”和“我的找车”是**同一个 Tab 的不同业务状态**，不是两个一级入口。

### 状态 A：从未提交

直接展示客户首填表单。

冻结字段：

- 想找什么车
- 价格预算
- 上牌年份范围
- 里程范围
- 车况要求
- 颜色偏好
- 地区偏好
- 其他要求

“提交找车需求”属于人工服务动作，提交前必须通过手机号服务门槛。

### 状态 B：申请待确认

存在 `pending` 找车申请，但尚未开通正式找车资格。

显示：

- 需求已提交 / 等待服务确认
- 申请内容
- 修改申请
- 我的顾问
- 找车权益说明

不得显示：

- 持续匹配中
- 正在为您筛选
- 已启动自动匹配

### 状态 C：正式 demand 已开启但匹配条件未 ready

`demand = active`，但销售尚未形成合法的销售匹配描述。

显示真实状态，例如：

- 顾问正在整理找车条件
- 当前需求
- 我的顾问
- 找车进度

不得伪装成“持续匹配中”。

### 状态 D：正式持续匹配中

匹配准备度为 `ready` 或可执行的 `ready_with_confirmation_needed`。

显示：

- 找车中 / 持续匹配
- 当前需求
- 找车进度
- 正式推荐车源（系统内部 recommendation 关系，不依赖 REC 链接）
- 我的顾问
- 新增找车需求
- 历史需求

部分条件待确认时，只表达相关条件待顾问确认，不阻断其余确定条件的持续匹配。

### C02 多需求工作区规则

C02 不能被实现成“整个页面只能处于一个互斥状态”的单 demand 页面。一个客户可同时存在：

- 多条 active demand
- pending 找车申请
- paused demand
- completed / cancelled 历史需求
- 与不同 demand 关联的正式推荐

页面按业务集合分区展示：

- **当前找车**：active demand；各自按匹配准备度显示“顾问整理中 / 持续匹配中”
- **待确认申请**：pending application
- **已暂停**：paused demand
- **推荐车源**：按实际 demand 关联
- **已结束**：completed / cancelled
- **操作**：新增找车需求

`paused` 仍是当前正式 demand 的暂停状态，**不得归入已结束历史**。

### C02-01 找车申请详情 / 编辑

对应客户原始找车申请/意向。

支持：

- 查看原始提交
- 修改尚未激活申请
- 查看申请状态
- 查看顾问
- 查看服务资格状态

### C02-02 正式找车需求详情

客户可见：

- 当前 demand 状态
- 客户原始需求
- 顾问整理后的客户可理解需求摘要
- 当前匹配进度
- 推荐车辆
- 顾问信息
- 历史状态

客户不直接配置内部：

- 销售匹配描述
- 硬条件 / 可接受范围 / 偏好
- 规则词典解析结果
- unknown 内部判断细节

# 4. 客户“我的”

## C03 我的【一级 Tab】

客户个人和历史业务中心。

### C03-01 我的收藏

- 收藏车辆
- 收藏不要求手机号
- 收藏不要求头像昵称
- 收藏先成功
- 资料未完善时可按频控提醒完善
- 每天最多主动提醒 1 次

### C03-02 我的推荐

展示正式 recommendation 记录。recommendation 是系统内部 customer↔vehicle 业务关系，不使用 REC 专用链接、REC URL 参数或推荐专用分享页。销售需要微信发送车辆时复用普通“分享车源”。

车辆详情继续复用 C01-01。

### C03-03 我的咨询

展示客户可见咨询：

- 待处理
- 处理中
- 已解决
- 历史/无效

### C03-04 我的锁车 / 候补

展示：
- 当前正式锁车 / 历史锁车；
- 当前候补 / 历史候补；
- 相关车辆当前可用性；
- 当前 lock 的创建时间、到期时间（如适用）、当前进度和负责顾问；
- 与当前 lock 相关、允许客户看到的意向金收款事实摘要；
- 若存在退款，显示客户可见的 `pending / refunded` 退款进度事实。

客户侧为只读进度中心：
- 不提供正式锁车按钮；
- 不提供修改/删除意向金、退款等资金事实的能力；
- V1 不提供“客户自行取消候补”按钮；客户不再等待时通过顾问处理；
- 车辆或历史业务不可继续时显示历史/不可用表达，不借历史入口暴露当前受保护实时车源信息。

### C03-05 我的交易

展示：
- 进行中；
- 已成交；
- 已取消；
- 客户可见交易事实；
- 实际成交价仅在业务规则允许客户查看的交易事实中展示；
- 与交易相关的意向金摘要、退款 `pending / refunded` 进度及必要时间线。

客户侧仅查看，不承担成交撤销、退款录入或交易状态修改。

### C03-06 公告

仅供客户主动查看当前和历史可见公告；V1 不建设通用客户消息中心/已读未读体系。

主动查看不受“自动弹窗每日最多一次”限制。

### C03-07 个人资料 / 我的顾问

包括：

- 头像
- 客户昵称/称呼
- 当前联系电话（可重新授权更新，customer_id 不变）
- 当前服务顾问
- 必要账户资料

微信身份继续作为账号识别基础，不把头像、昵称、手机号作为 customer_id 主键。

## E01 工作台【一级 Tab】

固定结构顺序：

### 1. 顶部员工信息

- 员工姓名
- 当前接客状态

### 2. 紧急异常条

只在真实异常存在时显示，例如：

- 咨询即将/已经超时
- 锁车即将到期
- 已锁/交易车辆供应异常
- 重要交易异常

### 3. 今日待处理

统一待处理区。

优先级固定：

1. 供应异常
2. 咨询超时 / 即将超时
3. 锁车即将到期
4. 重要交易异常
5. 候补车辆释放
6. 已逾期跟进
7. 今日跟进
8. 找车服务待处理

同类事项按：

**最早截止 / 最老事件优先**

### 4. 四个业务快捷入口

- 找车服务
- 咨询
- 锁车/交易
- 公海

分别进入 E05 / E06 / E07 / E08。

### 5. 客户机会

只展示当前确定性规则命中的 3 类机会：
1. 长期未登录/有效浏览（默认 7 天，可配）；
2. 单日高频浏览且无明确意向/真实沟通跟进（默认 >40 次，可配）；
3. 连续多日浏览且无咨询/真实沟通跟进（默认 3 天，可配）。

机会不是 consultation/任务，不设 pending/closed 生命周期，不发个人飞书；条件不再命中即从当前机会消失。

### 6. 车源雷达

按客户 / active demand 聚合展示车源机会和变化。

### E01-01 今日待处理列表 / 详情

统一查看待处理事项及对应业务跳转。

### E01-02 客户机会列表 / 详情

展示聚合后的客户机会，不展示造成监控感的完整浏览流水。

规则：

- 不是咨询
- 不产生咨询 SLA
- 不建立独立机会负责人
- 跟随当前 customer owner
- 不使用 AI 意向评分

### E01-03 车源雷达

按：

**客户 → demand → 车源动态**

聚合。

### E01-04 雷达事件 / 匹配详情

展示：

- 客户
- demand
- 车辆
- 候选层级
- 匹配原因
- unknown / 待确认原因
- 新上架 / 改价 / 重上架 / 下架 / 供应异常

操作：

- 查看车辆
- 推荐给客户：此处 customer_id、demand_id、vehicle_id 已知，直接创建 recommendation，不得再次选择客户
- 标记不合适

# 12. 员工锁车 / 交易业务

## E07 锁车 / 交易【业务模块】

E07 统一提供“我的/可管理业务列表 + 详情 + 关联时间线”。列表必须支持按业务类型、状态、负责人、客户、车辆、到期/超时、供应异常筛选；经理/店长看到的数据受数据范围控制。

### E07-01 正式锁车

列表/详情至少展示：
- lock、客户、车辆、当前负责人；
- 创建时间、`expires_at`、是否已确认存在意向金、锁车价格快照；
- 当前车辆 source / visibility / biz 状态摘要；
- 供应异常标记；
- 来源 recommendation / demand / consultation（如有）；
- 负责人变更与操作历史。

操作：
- 从合法业务上下文创建正式 lock；
- 无意向金 lock 默认 2 小时，可配，创建时可按权限调整具体到期时间；
- 当前有效 lock 可进入 transaction；
- 按权限取消/释放 lock；
- 记录意向金；
- 正式转交负责人并填写原因。

禁止：
- 同车并发创建第二个有效 lock；
- 客户已有自己当前 lock 时重复 lock / 候补；
- 已确认存在意向金后由到期任务自动释放；
- 终态 lock 直接复活。

### E07-02 候补

列表/详情至少展示：
- 客户、车辆、候补负责人；
- 登记时间、排序参考；
- 来源 recommendation / demand / 普通车辆详情；
- 当前车辆和当前 lock 摘要；
- 结束时间/结束原因及负责人变更历史。

规则与操作：
- 同 customer+vehicle 同时最多一条当前有效候补，重复登记复用；
- 负责人按 recommendation → active/paused demand → customer owner，owner 为空先原子分配；
- lock 释放只通知，不自动关候补/自动升级锁；
- 候补负责人或具备数据范围权限的经理/店长可人工结束当前候补，必须填写原因并留历史；
- 客户端 V1 不提供自行取消候补按钮；
- 车辆 completed/offline/unavailable/sold_external 自动结束当前候补；platform hidden 不结束；终态不复活。

### E07-03 交易

列表/详情至少展示：
- transaction、来源 lock、客户、车辆、唯一交易负责人；
- 进行中 / 已成交 / 已取消；
- 创建/成交/取消时间；
- 锁车价格快照与 completed 的实际成交价；
- 意向金、退款、供应异常；
- 负责人转交和操作/纠错历史。

操作：
- 只能由当前有效 lock 创建 transaction，并原子关闭该 lock；
- 进行中交易可按权限成交或取消；
- cancelled 为终态，再买必须重新 lock → 新 transaction；
- completed/cancelled 默认历史只读，授权纠错通过 P07-06 或相应权限入口处理。

### E07-04 意向金

展示与录入多笔线下收款事实：金额、收款时间、方式、操作人、备注、可选凭证。
- 不设结清/部分等主状态；
- 不设独立负责人；
- 与 lock / transaction 关联；
- 原始事实不普通删除，纠错留痕。

### E07-05 退款

展示：
- `pending / refunded`；
- 应退/已退汇总；
- 多笔实际退款事实；
- 实际操作人、时间、方式、备注/凭证；
- 关联 lock / transaction / deposit。

规则：
- 未全部实际退完保持 pending；
- 当场全部退完可直接记录 refunded；
- refund 不设独立负责人；
- pending 保护客户不进公海，但不占用车辆。

### E07-06 业务关联视图 / 时间线

聚合展示 lock、意向金、transaction、refund、负责人转交、供应异常、纠错和操作审计。
- 仅为 read model / 操作导航；
- 不新增统一“大业务单”或统一大状态；
- 每个动作仍回到其真实业务对象和权限校验。

P07 是跨门店/授权数据范围的管理视图，承载与 E07 相同真实业务对象，不新增“大业务单”。所有列表支持按客户、车辆、负责人、业务状态、时间、供应异常、退款状态等筛选，并可跳转客户/车辆/业务关联历史。

### P07-02 候补

显示客户、车辆、负责人、登记时间、来源、当前 lock/车辆状态、结束原因与历史。
- 重复 customer+vehicle 当前候补复用；

### P07-04 交易

展示 transaction、来源 lock、唯一交易负责人、三状态、实际成交价、供应异常、意向金/退款与转交/操作历史。

- 同车最多一笔进行中 transaction；
- cancelled 终态不复活；
- completed/cancelled 默认历史只读。

### P07-05 退款

- 原 completed transaction 不删除；
- 撤销后真实成交统计/事实标签/模型样本同步失效；
- 车辆是否恢复可售由当前 source/visibility/biz 事实决定；
- 若纯误操作且资源从未失效，恢复原 listing_cycle 连续性，不计重新上架/今日新增，原周期查价权限继续；
- 因误成交结束的候补不自动复活。

## P08 价格 / 查价规则

### P08-01 批发客户展示价 / 阶梯加价
