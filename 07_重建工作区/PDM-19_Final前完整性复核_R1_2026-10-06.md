## 3. Final 前修复候选

### P19-LIA-01｜误成交纠错不得制造假重新上架 / 假新 cycle

历史 DEC-062 / Phase 1.5 HR-07 明确：

如果 completed 只是系统 / 业务误操作，而 Vehicle 事实上从未真实不可售：

- 纠错后恢复真实可售事实；
- 继续原 `listing_cycle`；
- 不新建 cycle；
- 不计 `today-new`；
- 不改变“最新上架”时间；
- 不重新置顶；
- 原 cycle 的合法价格 / 查价权益继续；
- 客户不因系统纠错重复解锁 / 重复扣额度；
- 旧 Lock / Waitlist 不复活。

若期间 Vehicle 真实经历不可售 / 下架，之后重新真实可售：

> 按正常 relist 建立新的 listing_cycle。

当前 P19-B4-06 只冻结了 correction 权限与 append-only 历史，尚未完整承接该 listing_cycle 后果。

### P19-LIA-02｜in-progress Transaction 的正常取消动作与 Vehicle 重算边界

Current / 历史规则已明确：

- 只有尚未 completed 的 `in_progress` Transaction 才走普通 cancel；
- 当前合法 Transaction responsible 可在统一 permission / scope / object-state Guard 下执行正常取消；
- completed Transaction 不走普通 cancel，改走 P19-B4-06 correction；
- cancel 后 Transaction 进入 `cancelled` 终态历史；
- 不复活旧 Lock / Waitlist；
- Vehicle 后续资格只按真实 source state、current listing_cycle、当前其他占用重新计算；
- cancel 不强制改写 `source_status` / `platform_visibility`；
- 不制造假 relist。

本条不新增额外取消审批层。

### P19-LIA-03｜真实 Deposit 的记录入口与 correction 权限必须分离

B4-07 已冻结字段 / 线下收款边界，B3-02 已冻结资金纠错权限，但仍需明确：

- 当前合法业务负责人可以记录真实已经发生的收款；
- 同一 Lock 可以存在多笔 Deposit；
- Deposit 本身不单独设置 independent responsible，仅记录每笔 operator；
- 真实收款记录能力 ≠ 资金 correction 能力；
- 普通合法收款记录不能自动获得资金纠错 permission；
- correction 继续由具备独立资金纠错 permission + scope 的经理 / 店长执行；
- 总额由有效 Deposit + correction 事实派生。

### P19-LIA-04｜实际当场全额退款可直接形成 refunded，不强制造假 pending

历史 Refund 规则明确：

- 实际退款已经当场完成时，可直接记录真实 Refund 并进入 `refunded`；
- 不要求为了流程形式先制造一个短暂的假 `pending`；
- 钱尚未实际退，只是进入退款处理 → `pending`；
- pending 后钱真实退完 → `refunded`；
- pending 后决定不再退款 → 按 B3-03 / B4-01 进入 `closed` 并填写原因；
- `closed` 不得用于实际已经退款的场景。

### P19-LIA-05｜Transaction completed 不自动结束 Customer 的 Demand

PDM-11 Final 已冻结：

> 一笔 Transaction completed 只完成该 Transaction 与真实成交事实，不自动把同一 Customer 的全部 Demand 批量 completed / cancelled。

即使 Transaction 与某条 Demand 有关联：

- 也必须按该 Demand 的真实服务目标由 PDM-11 Authority 决定是否结束；
- PDM-19 不得用“已成交”事件直接批量改写 Demand；
- 与 P19-A11“Transaction 不自动结束 Consultation”属于同类跨对象边界。

Startup Gate 未将 PDM-11→PDM-19 登记为正式 incoming handoff，因此 Final 前需要补 completed-PDM invariant / alignment，避免 Transaction engine 越权。
