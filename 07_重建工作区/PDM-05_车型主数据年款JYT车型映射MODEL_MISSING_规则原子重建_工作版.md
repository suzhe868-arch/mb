## 3. 已明确不放入 Batch 1 的事项

以下事项存在历史替代、后续冻结语义、IA 承载冲突或历史细节缺失，必须留到后续批次，不能伪装成“稳定一致”：

1. **JYT 本地映射未完成时，到底哪些“精确车型事实”可直接用于展示 / 搜索 / 筛选 / 精确匹配。**  
   CN11 CR-006 与后续 R3 存在明确口径变化；R3 自己也写明对 CN11 旧规则进行了覆盖，属于知情修改候选。

2. **“首次入库形成完整年款 + 具体车型映射”与“本地车型字典可后补映射”的关系。**  
   9/22 `VR-P-010` 与 R3 的“来源车型事实先保存、本地归属可待确认”需要拆清“车型事实完整”与“本地 model_id 已确认”两层含义。

3. **车型管理员在 E02-02 / MODEL_MISSING 场景中是否可以原地“新建车型并绑定”。**  
   历史与真实页面支持该动作，但当前 Navigation / Action Contract 曾明确写 `no model creation is inferred`，属于真实承载冲突。

4. **本地车型节点挂错父级后的修正、重复车型合并、旧节点退出与轻量合并历史、真实旧车型长期保留。**  
   R3 有完整规则，但 001～078 指出当前层存在历史细节未完整下沉，后续需按遗漏项审查。

5. **不设计车型名称 alias / 同义词、不设计“同一车型多个 JYT 编号”的额外机制、不设计人工单车车型锁定。**  
   这些是明确废弃 / DO_NOT_RESTORE 类型，放 Batch 2。

6. **选择具体车型后自动带出年款、排量、变速箱、排放、能源等固定属性的完整边界。**  
   需要与人工发布 PDM-06 的字段规则一起核对，不能在本批越界冻结。
