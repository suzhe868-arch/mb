## 2. P03-05 publisher 身份与权限

P03-05 定位保持“publisher 电话缓存管理 / 诊断页”，但必须同时满足：

- publisher/current cache 唯一键继续是 `source_platform + upstream_publisher_id`；
- 页面至少明确展示 source_platform 与 upstream_publisher_id；
- 只投影当前操作者 data scope 可触达的 publisher / 关联 Vehicle；
- 明文电话、latest 继续要求独立上游电话敏感能力；
- System Admin 身份本身不自动获得电话明文/latest 权；
- integration/Collector manage、Integration API 配置、运行状态/日志权限不等于电话明文权限；
- P03-05 的历史/诊断能力不等于把电话重新挂回已转名邦/4S Vehicle 日常详情。

## 3. 无有效号码不得覆盖旧缓存

只有返回合法、非空、可作为电话号码使用的有效号码时，才允许写入/更新 publisher 当前缓存。

如果 cache miss / latest 请求：

- 请求失败；或
- 请求完成但返回空值；或
- 无号码；或
- 明显非法号码；

则：

- 有旧有效缓存 → 保留旧缓存，并记录本次未取得有效新号码；
- 无旧缓存 → `PHONE_UNAVAILABLE`；
- 不发起拨号；
- 允许合法重试；
- 必须审计本次真实结果；
- “请求成功”不得被误记成“号码刷新成功”。

## 4. 3A｜source_type 电话入口裁剪

用户最终选择 3A：

> **上游发布人电话只作为当前 wholesale/JYT 批发车源的日常敏感业务能力。**

因此：

- 当前 Vehicle 为 wholesale/JYT 批发，且 active employee + data scope + 独立电话能力全部满足时，才可在车辆详情查看、latest、拨打；
- 同一 Vehicle 完成批发→名邦后，车辆详情立即关闭原上游电话查看/latest/拨打入口；
- 当前 source_type=4S 时，同样不得因历史 upstream_publisher_id 自动出现上游电话入口；
- upstream_publisher_id 来源事实不删除；
- publisher current cache 不因转换自动删除；
- publisher_phone_history 不删除、不改写；
- 既有查看/latest/拨打审计继续保留；
- P03-05 有权限的诊断/历史场景仍可保留该 publisher 记录。

3A 改变的是**当前 Vehicle 日常业务入口**，不改写历史来源事实。
