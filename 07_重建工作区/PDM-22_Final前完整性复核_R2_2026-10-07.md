## 5. Semantic Completeness

### 5.1 PC 身份与认证

已覆盖：

- PC 业务后台不是 System Admin 专属；
- Employee 与 System Admin 身份严格分离；
- Employee PC 登录凭证绑定现有 employee_id，不创建第二 Employee；
- 登录账号 + 密码；账号全局唯一；
- 初始密码、首登强制修改、员工自改密码、后台重置；
- PC credential 开通 / 禁用 / 重置归 P04 Employee account governance；
- Employee inactive 后 PC 登录与旧登录态立即失效；
- System Admin 继续使用 P05 独立 system identity + 独立 credential；
- 4S 默认不进入 PC，仅明确授予 PC 车辆管理能力时开放裁剪入口。

### 5.2 P01 Dashboard

已覆盖：

- Dashboard 只聚合 / 跳转；
- 不造第二套业务状态；
- 统计、待办、异常按当前 permission + data scope 计算；
- 不通过总数、卡片或跳转旁路泄露敏感数据。

### 5.3 P02 Vehicle / Model / Hidden Rule

已覆盖：

- Draft 与 Formal Vehicle 分层；
- Formal Vehicle 无通用物理 Delete；
- source_type / hidden / offline / sold / listing_cycle 继续消费 PDM-04；
- 车型主数据 / JYT mapping / MODEL_MISSING / conflict / merge 由 System Admin 控制平面治理；
- 自动 / 批量隐藏规则独立子页面；
- 来源范围、AND / OR 条件、规则启停、命中重算与 hidden≠offline；
- 单车页显示命中结果，不把规则编辑器塞进单车详情。

### 5.4 P03 Integration / Publisher Phone

已覆盖：

- 三个固定车源同步业务 API；
- 独立启停、名邦同步 credential、统计与运行状态；
- 车源同步 credential 与 JYT / 电话 / Collector credential 隔离；
- 电话链路保持 Collector 向上游取号 → 名邦既有 Integration API 回传；
- 不恢复 Mingbang → Collector Phone API、Collector Base URL / Phone Path；
- publisher cache / 诊断以 source_platform + upstream_publisher_id 定位；
- Integration 管理权不自动授电话明文权；
- P03 下将“车源同步 / Integration API”与“Publisher / 电话诊断”分成两个子页面；
- 电话日常入口按当前 source_type 裁剪，只对当前 wholesale/JYT 车辆开放。

### 5.5 P04 / P05 员工权限与 System Admin

已覆盖：

- 员工账号、角色模板、个人 allow/deny、data scope、接客治理、交接；

- 不能停用最后一个 active System Admin；
- 配置权 ≠ 业务执行权；
- credential 治理与业务身份历史分离。

### 5.6 P06 Customer / Find-car / Matching / CRM / Public Pool

已覆盖：

### 5.7 P07 Lock / Transaction / Fund

### 5.8 P08 Price / Entitlement / Quota
