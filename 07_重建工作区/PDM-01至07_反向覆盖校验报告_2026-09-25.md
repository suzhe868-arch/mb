## 1. 校验判定标准

每一条历史有效规则必须至少有一个明确去向：

1. **MAPPED**：已进入当前最终规则；
2. **SUPERSEDED**：被后续用户明确裁决替代；
3. **DEPRECATED / DO_NOT_RESTORE**：已明确废弃；
4. **DEFERRED**：明确移交给后续 PDM；
5. **ENGINEERING_ONLY**：仅剩实现细节，不属于产品业务规则；
6. **UNMAPPED**：没有明确去向，属于真正遗漏 / 漏审；
7. **PARTIAL**：主规则存在，但关键 Guard / 边界没有完整落入最终规则。

目标：

> **UNMAPPED = 0**

本轮实际结果：**尚未达到 0。**

- 历史永久保留；
- 早期规则明确 **V1 不增加人工“确认异常 / 标记已解决”流程**。

但后续 Current 又出现：

> 人工审查并清除异常

M07-004 已明确判定：

> `CURRENT_OVERINTERPRETATION / HISTORICAL_CONFLICT / NEEDS_SOURCE_CHAIN_RESOLUTION`

PDM-04 Batch 1～4 和最终文件均没有把这个冲突重新提交用户裁决，也没有明确移交后续 PDM。

**用户裁决：CLOSED / MAPPED**

> **供应异常准许人工处理。**

正式规则：
- 系统可以自动发现 / 标记供应异常；
- 系统明确确认风险恢复时可以自动解除；
- 有权限人员也可以基于实际证据人工处理并解除；
- 人工解除前应重新核验当前真实状态；
- 人工处理保留处理人、时间、结果及适用的证据 / 说明；
- 解除异常不删除历史异常；
- 异常本身不自动取消既有 Lock / Waitlist / Transaction，也不删除 Deposit / Snapshot 等历史事实。

## GAP-04-02｜同 vehicle_id 转名邦后，收藏 / Recommendation / 查价关系语义｜已关闭

- Lock 保留；
- Waitlist 保留；
- Transaction 保留；
- price snapshot 保留；
- listing_cycle 保留。

但没有显式回答：

- Favorite 是否继续有效；
- 已有 Recommendation 是否继续有效；
- 当前 listing_cycle 的查价授权 / 免费查价关系是否继续有效或需要重算。

因为现在根本不存在“迁移”动作，旧“不迁移”规则不能直接机械套用；但也不能自动推断“全部继续”。

**用户裁决：CLOSED / MAPPED**

2026-09-25 用户明确确认：

> 一键转名邦只是同一辆车后台车源类型 / 经营来源发生变化，不是新建；`vehicle_id` 与当前 `listing_cycle` 不变，前端客户仍然面对同一辆车。

因此：
- Favorite / 收藏原样继续；
- Recommendation 原样继续；
- 当前 listing_cycle 已成立的查价关系 / 权益原样继续；
- 其他绑定该 vehicle 的客户侧关系原样继续；
- 不迁移、不重建、不清空，不因 `source_type` 改变单独处理。

旧“转名邦后客户关系不迁移到新 vehicle”的规则，其技术前提“双 vehicle”已被 P04-A15 明确替代，因此本项不再构成未决问题。

建议后续分别由 PDM-04 与 PDM-10 / PDM-14 / PDM-20 联动收口，但必须先登记该问题，不能等未来偶然发现。
