## 三、跨 Runtime 可信桥接要求

### 3.1 两套数据库必须隔离

每个独立 Job 都必须使用真实 PG16、非超级用户及两个不同物理 OID：

- F05 来源库：沿用 #214/#216 正式测试链的 M94→000015→000016（14 条已批准迁移）和现有私有 sidecar。
- F06 目标库：沿用 F06 已验收的 24 条签名迁移、161 张父表封印及现有 Composite/Lifecycle/资金侧车。
- 不得把 F05 14 条迁移与 F06 24 条迁移混装进同一个 public Schema；不得修改公共 DDL、迁移账本、旧父签名或现有资金服务。
- 既有服务可能固定连接 `127.0.0.1:5432/f03_auth_test`。允许在可销毁 CI 内使用受控数据库重命名/切换来保持每个旧服务原生校验不变，但所有客户端必须先关闭；切换后要复验 DB 名、OID、迁移数、结构指纹和连接身份。不得为方便而伪造或覆盖真实 `GITHUB_REF`、`GITHUB_SHA`、`GITHUB_RUN_ID`，也不得改 F03 数据库身份验证。
- 两库应分别保存为可直接复核的来源库和 F06 快照库；桥接前后两个 OID 必须不同且在整个证据链中一致。

### 3.2 F05 原发布来源清单

必须通过现有 #214 原生 HTTPS/API 创建一台全新的合成名邦人工车，不能直接 INSERT 伪造 `published_vehicle_facts` 来替代正式发布流程。至少保留并验证：

- `vehicle_id`、`listing_cycle_id`、`source_type=mingbang`、`model_id`、当前 VIN 的脱敏值/摘要、原客户标价；
- 原始里程、城市、描述、车况标签、原始发布 payload 的规范化摘要；
- #214 的唯一已发布 draft、不可变 `PUBLISHED` 事件摘要、发布人、当前 Vehicle/Cycle 关联；
- F05 public migration ledger、结构指纹、私有发布 schema seal、源数据库 OID、当前真实 SHA/Run/Ref。

桥接清单不得包含会话、Cookie、密码、私钥、真实客户资料或真实电话。所有源事实均为本次 Run 新建的合成非生产数据。

### 3.3 F06 同一 Vehicle 投影与签名业务链

- F06 目标库中使用完全相同的 `vehicle_id + listing_cycle_id + source_type`。不允许生成另一 ID 后只在报告里宣称“同一车辆”。如 ID 冲突，必须重新构造无冲突的合法测试源；不能重映射或覆盖既有记录。
- 桥接适配只可在 F06 独立测试库中建立经清单验证的 Vehicle/Cycle/当前客户价格投影及私有桥接 Attestation；投影值必须与 F05 初始发布清单逐字段/摘要一致。
- LockRequest、员工审批、正式 Lock、合成 Deposit 与 Transaction 必须经现有 F06 已验收的业务服务/HTTP 入口完成；不得直接 INSERT/UPDATE 伪造 `public.locks`、`public.transactions`、Deposit/Refund 或签名父源正向行。
- Lock 的 `customer_display` 价格事件必须来自桥接清单中的 F05 原发布客户标价，且 Lock Snapshot / Transaction 来源快照能证明价格一致。
- F06 新签名必须绑定本任务真实分支、当前 SHA、当前 Run ID、F06 DB OID、24 条迁移与 161 表父链封印、既有 F06 父 Attestation，以及本任务桥接源代码/工作流摘要。不能复用历史 Run 或其他 SHA 的签名结果。

### 3.4 正确的时间顺序与编辑后复核

每个 Job 必须真实执行以下顺序：

1. 先完成 F05 #214 发布，导出初始签名来源清单。
2. 以该清单建立 F06 Vehicle/Cycle 投影，使用现有服务完成签名 Lock→合成 Deposit→Transaction；保存相关原生业务行和不可变历史的规范化逐行 SHA-256。
3. 保持 F06 数据库及签名历史存在；切换到 F05 来源库，通过 #216 真实 HTTPS `stage/commit` 将客户标价、里程和车况至少各变更一项，并记录新的编辑版本/不可变审计。不得在编辑前先销毁 F06 快照。
4. 切回 F06 数据库及其原 DB OID，复验两边来源清单与签名。F05 当前有效编辑值必须确实改变；F06 的 Lock 快照、Transaction 来源/快照、Deposit 及相关资金历史、签名 Attestation、相关审计行必须与编辑前逐行哈希一致。
5. 明确证明：F05 初始客户标价 = F06 Lock Snapshot 价格 = F06 Transaction 来源价格；F05 编辑后的客户标价与里程/车况已改变，但 F06 历史值未改变。不得把跨库天然互不相连作为唯一断言；必须有桥接身份、初始价格匹配、F06 原生业务链、编辑后重读与逐行哈希的完整证据。
6. 重新验证 F05 与 F06 的迁移链、Schema 指纹、各自 DB OID、当前 SHA/Run/Ref、签名来源摘要、父链封印均未漂移。
