# 3. Batch 1｜稳定一致项｜重新展开版

> 本批只审没有被后续规则推翻的图片基础生命周期。与后续转换模型、分享图、4:3 等新增/改写内容分开处理。

### P08-A01｜批发图片集合首次冻结

批发车第一次入库时读取当次 `images[]`，保存：

- 图片 path / 来源身份；
- 上游图片标识（如有）；
- 原始顺序；
- 必要来源元数据。

形成该 vehicle 当前首次图片集合快照。

后续普通 JYT 同步：
- 不因为上游后来新增图片而自动补入；
- 不因为上游删图而自动删除本地图片记录；
- 不因为上游调整排序而改写名邦保存的原始顺序；
- 单张图片后续不可用，只处理该图片自身失败 / 恢复；
- 不因为单张失效重新抓整车图片集合。

> 公开图片域名、上游回源域名均不写死进业务数据；按 P08-CDN-01 由配置运行时拼接。

状态：`USER_APPROVED`

### P08-A02｜采集批发车首图 CDN 自然缓存 / fallback / 占位图

批发车首次入库时只冻结图片来源、URL 与原始顺序，不要求主动调用 CDN 厂商预热，也不要求采集阶段先把首图永久落入名邦对象存储。

列表 / 首页首次真正请求车辆首图时：

1. 客户端只请求名邦受控 CDN 地址；
2. CDN 命中缓存则直接返回；
3. CDN 未命中时，CDN 在**同一次请求**中实时回源 JYT，拿到图片后直接返回给当前客户，并同时形成 CDN 缓存；
4. 原排序第一张回源失败时，按原始顺序继续寻找下一张可用图作为当前列表封面；
5. fallback 只改变当前展示封面，不改变数据库原始排序；
6. 原第一张以后恢复可用时，仍可按原始排序恢复为首图；
7. 上游 0 图或全部图片不可用，不阻止车辆入库、匹配、销售 / 在售；
8. 没有可用真实图时使用统一默认占位图。

> CDN 厂商“URL 预热 API / 每日预热额度”不进入本产品规则；图片正常可见性不得依赖主动预热。

状态：`USER_APPROVED`

### P08-A03｜名邦受控图片地址与可配置域名

批发 / 报告静态图片的业务数据只保存图片 path，不把前端公开域名或上游回源域名写死进数据库。

具体：
- 客户端、员工端不得直接使用上游图片域名；
- 对外图片地址由“名邦可控公开图片域名 + 配置前缀 + 图片 path”生成；
- CDN 未命中缓存时，再根据配置的上游图片源站域名 + 同一 path 回源；
- 当前标准上游图片源站配置使用 `img.jytche.com`；
- 名邦公开域名、路径前缀、JYT 图片源站域名均作为配置项，可后续替换；
- 完整 H5 / 报告页面不套用普通图片 path 规则。

状态：`USER_APPROVED`

### P08-A04｜普通批发图片的 CDN 自然缓存

除列表首图外，其余普通批发车图片在批发阶段**不要求浏览时自动永久写入名邦对象存储**。

客户查看 / 预取图片时：

1. 客户端请求名邦受控 CDN 地址；
2. CDN 命中缓存则直接返回；
3. CDN 未命中时，由 CDN 实时回源 JYT；
4. 同一次请求中把图片返回给当前客户；
5. CDN 同时按自身缓存策略形成缓存。

因此：

- 当前 viewer 不需要等待名邦对象存储持久化完成；
- 普通批发浏览过程不再以“吞图 / local_object_key 写入成功”为前提；
- 是否缓存、缓存多久、节点层级、MISS 回源策略由 CDN / Engineering 配置；
- 客户端始终不直接接触 JYT 原始域名。

> 真正“写入名邦对象存储并成为长期自有资产”的动作，发生在人工上传或批发→名邦资产化阶段，不属于普通批发浏览。

状态：`USER_APPROVED`

### P08-A05｜详情页两阶段 CDN 预取

当前规则保留“两阶段预取”，但不依赖 CDN 厂商主动预热 API。

#### 第一阶段：进入详情，优先保障前 5 张

- 列表首图已经通过正常 CDN 请求获得；有缓存则直接返回，无缓存则 CDN 实时回源并在同一次请求中返回、缓存；
- 客户进入车辆详情后，除当前首图外，立即主动请求后续 **4 张**；
- 因此详情页优先准备的目标是：**前 5 张图片连续可看**；
- 这 4 张可以并行请求 CDN，不要求逐张等待前一张完成。

#### 第二阶段：浏览到第 3 张时，开始获取剩余图片

当客户实际浏览到 **第 3 张图片** 时，视为存在继续看图的明确意图：

- 将该车剩余尚未请求的图片全部加入 CDN 预取队列；
- “全部加入队列”不等于瞬间无限并发回源；
- 实际请求仍可分批并行，由 Engineering 根据终端网络、图片大小、CDN 状态等控制；
- CDN 已有缓存的图片直接命中；
- CDN 未缓存的图片由 CDN 实时回源 JYT，并在对应请求中返回给客户端，同时形成缓存。

这样可以避免客户只进详情看一眼时就为整车几十张图片产生无意义回源流量，同时又能保证真正继续浏览的客户后续看图尽量连续。

状态：`USER_APPROVED`

### P08-A06｜对象存储资产化成功边界

“对象存储成功 + DB 引用成功”不再用于定义普通批发图片是否能显示；普通批发图片按 A04 走 CDN 自然缓存。

该双成功规则只适用于**真正进入名邦自有对象存储的图片**，包括：

- 名邦 / 4S 人工上传图片；
- 名邦 / 4S 自上传报告 / 档案图片；
- 批发 → 名邦转换后的图片资产化。

只有同时满足：

1. 对象存储写入成功；
2. DB 成功保存有效 object_key / path / 资产状态引用；

才算名邦自有图片资产正式成立。

异常处理：
- 对象存储成功、DB 最终失败 → 清理刚产生的孤儿对象；
- DB 不得把未完成写入的对象标记成已资产化；
- 图片资产化失败不得回滚已完成的批发→名邦 source_type 转换。

状态：`USER_APPROVED`

### P08-A07｜批发 CDN 缓存与名邦自有资产读取优先级

需要区分两种图片状态：

#### A. 普通批发图片
- 使用名邦 CDN 地址；
- CDN 命中缓存直接返回；
- CDN MISS 时正常回源 JYT；
- 不要求每次读取前检查上游；
- 缓存失效后是否重新回源由 CDN 正常处理。

#### B. 已成为名邦自有对象存储资产的图片
例如人工上传图或批发→名邦后已完成资产化的图片：

- 正常优先读取名邦对象存储 / CDN；
- 不再把 JYT 作为普通日常读取源；
- 如果本地对象损坏 / 丢失 / 404，可按保留的来源事实执行受控恢复；
- 恢复只处理单图，不触发整车图片集合重新同步。

状态：`USER_APPROVED`

### P08-A08｜图片失败与恢复位置

普通批发图通过 CDN 请求失败时：

- 失败重试次数、退避时间、超时、熔断等属于 Engineering，不在产品规则中固定“每轮 3 次”；
- 当前不可用图片可暂不占客户可见图片位置；
- 图片来源记录与原始顺序继续保留；
- 后续再次可用时，按原始排序位置恢复进入图片集合；
- 单张失败不得触发整车图片重新同步；
- 单张失败不得改变车辆在售、Matching、Recommendation、Lock、Transaction 等业务事实。

批发→名邦资产化失败的重试 / 恢复状态，继续按后续转换图片规则单独管理，不与普通 CDN 请求失败混成一个状态机。

状态：`USER_APPROVED`

### P08-A09｜CDN 并行加载 / 重复回源控制

当前 CDN 架构下：

- 取消旧“单车最多 3 张并发”的产品级硬限制；
- A05 第一阶段允许后续约 4 张图片并行向 CDN 请求；
- 客户浏览到**第 3 张**时，将剩余未请求图片加入预取队列；
- “加入预取队列”不等于几十张瞬时无限并发；
- 实际并发数、批次、节流策略由 Engineering 可配置并通过实测调整；
- 同一资源避免无意义重复请求 / 重复回源作为工程优化目标，可由客户端任务去重、CDN Cache Key、厂商缓存 / 合并回源能力等实现；
- CDN 已命中缓存时直接由节点返回，不产生对应 JYT 回源。

> “同图 single-flight”不再作为产品业务状态；“并行几路”也不在 PDM 写死。

状态：`USER_APPROVED`

### P08-A10｜车辆状态变化不改写图片来源事实

车辆 visible / hidden、真实下架、售出、重新上架等状态变化：

- 不改变首次冻结的图片 path / 来源身份 / 原始顺序；
- 不因为上下架重新抓整车图片集合；
- 不因为 hidden / visible 新建图片资产；
- 图片相关变化本身不创建新的 `listing_cycle`。

对于普通批发图：
- CDN 缓存是否存在、何时过期由 CDN 管理；
- 车辆下架不要求主动清空 CDN；
- 重新上架后继续使用同一名邦公开图片 URL，缓存命中则直接返回，MISS 则正常回源。

对于名邦 / 4S 自有对象存储图片：
- 对象存储资产继续按自身图片生命周期保留；
- 车辆上下架本身不自动删除图片对象。

状态：`USER_APPROVED`

### P08-A11｜人工名邦 / 4S 图片生命周期

人工名邦 / 4S：
- 允许 0 张真实图片正式发布；
- 0 图使用统一占位，不因此下架；
- 人工上传成功后即属于名邦服务端正式本地图，不存在“未本地化”状态；
- 正式发布后可继续补图、删图、拖动排序；
- 删除首图后，剩余排序第一张成为新首图；
- 删除到 0 图仍可继续在售。

批发采集图的原始排序：
- 普通人工不得直接拖动 / 改写。

状态：`USER_APPROVED`

### P08-A12｜不设置产品级固定图片限额

产品业务层不硬编码：
- 最多几张；
- 固定单图大小；
- 固定业务格式清单。

仍保留必要技术安全校验，例如：
- 必须是真实可处理图片内容；
- 防危险内容；
- 防明显资源滥用；
- 平台 / 对象存储实际技术限制。

这些技术限制不能反向演变成未经产品确认的“业务最多 N 张图”。

状态：`USER_APPROVED`

### P08-A13｜图片权限继承 Vehicle，不允许 URL 绕权

图片 Read 不是独立越权通道。

要求：
- 图片是否可读，继承当前 Vehicle Read / Visibility；
- hidden / Priority / Recommendation 等场景不能靠拿到历史图片 URL 绕过车辆权限；
- 当前无权读取 Vehicle 时，旧图片地址不能成为永久访问权；
- 客户端只获得名邦受控地址，不获得 JYT 原始 URL / 内部对象地址；
- 具体 URL 签名 / Token 机制属于 Engineering。

状态：`USER_APPROVED`

# 3A. 报告 / 档案图片与 H5 链路

> 本章节单独存在，避免把报告/档案资源误当成车辆普通相册。技术 CDN 基础设施可以复用，但业务归属、可见性与展示入口继续服从 PDM-07。

## R08-R01｜出险记录图片

当前出险记录按**图片呈现方式**处理：

- 上游提供图片 path / 来源；

# 8. 2026-10-03 CDN URL 生成补充裁决

### P08-CDN-01｜图片路径与域名配置

用户确认：采集到的图片原始数据本身不包含固定域名，核心事实是图片路径。

因此普通图片类资源统一采用：

- 数据库只保存图片 path，例如：
  `/user/370436/report/image/1788072135101_1352.jpeg`
- 不在业务数据中写死名邦前端图片域名；
- 不在业务数据中写死 JYT 图片回源域名；
- 前端公开图片地址由“名邦可控公开图片域名 + 固定前缀 + 图片 path”运行时生成；
- CDN 回源地址由“配置的上游图片源站域名 + 图片 path”运行时生成。

示意：

```text
DB:
  /user/xxx/xxx.jpg

Frontend public URL:
  {PUBLIC_IMAGE_DOMAIN}/{PREFIX}/user/xxx/xxx.jpg

CDN origin:
  {JYT_IMAGE_ORIGIN}/user/xxx/xxx.jpg
```

当前示例可表现为：

```text
前端：
https://img.mingbang.com/ct/user/xxx/xxx.jpg

CDN 回源：
https://img.jytche.com/user/xxx/xxx.jpg
```

但 `img.mingbang.com`、`/ct/`、`img.jytche.com` 均属于可配置项，不冻结为数据库永久字段。

适用范围：
- 车辆相册图片；
- 出险记录图片；
- 4S 维保报告内静态图片；
- 其他报告静态图片；
- 后续同类采集图片附件。

例外：
- 完整报告 / H5 链接（如 `app.yutangkeji.com/#/detail/...`）不套用普通图片 path 规则，继续按完整报告 URL / report proxy 规则处理。

状态：`USER_APPROVED`

# 10. 本轮跨模块扫描结论

当前未发现需要推翻 PDM-04、PDM-06、PDM-07 已冻结规则的冲突。
