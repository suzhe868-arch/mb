## 三、上一轮阻断的独立复验

### 1. 原始权限 baseline 恢复

- 生命周期失效时，先持久关闭专项 mode、结束本 API 的 phone-special binding/scope、递增 CAS 版本，再根据保存的原始决定做条件恢复。
- 原始 baseline 为 `NULL`：删除本 API 遗留的 `allow`，并清空旧 baseline 捕获标记；随后显式重新授权、再 DELETE 后仍无 override 行。
- 原始 baseline 为独立 `allow`：生命周期失效、重新授权、再 DELETE 后仍保留独立 `allow`。
- 生命周期失效期间并发提交 `deny`：条件恢复不会删除或覆盖 `deny`；审计 `after_json.permissionDecision` 与数据库最终决定一致。

上述路径均有真实 PG16 业务测试，最终业务 Job 43/43 通过。

### 2. 之前四项安全整改继续保留

- DELETE 保留个人明确 `deny`，只撤销本 API 的专项范围。
- 条件 UPSERT 与双事务 PG16 竞态测试防止并发 `deny` 被覆盖。
- SG01 binding 检查 `granted_at <= transaction_timestamp()`。
- 仅接受正式员工角色 `sales`、`manager`、`store_manager`；旧别名 `store_head` fail-closed。
