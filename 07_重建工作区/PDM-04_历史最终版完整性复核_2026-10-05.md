## 2. Listing Cycle 与时间事实

`listing_cycle` 只在真实不可售/失效 → 再次真实可售时开启新周期。

`listing_started_at` 的取值：

1. 有可信本次真实上架/重上架时间 → 使用真实时间；
2. 没有可信上游真实时间 → 使用名邦首次确认本次不可售→可售的时间；
3. 名邦/4S 人工车首次正式发布或真实重上架成功 → 使用正式发布/重上架成功时间。

必须分离：

- current cycle `listing_started_at`；
- 人工车上传/首次创建时间；
- JYT `first_seen_at` / 名邦平台收录时间。

不得把 JYT `first_seen_at` 伪称成“上游真实上传时间”。

“最新上架”使用 current cycle started_at；“今日新增”只算当天第一次进入名邦系统并正式在售的车辆；历史车辆 relist 不重复计入今日新增。

## 3. 车辆三轴与 occupied vehicle fact update

车辆事实继续分层：

- source/resource 可售事实；
- platform visibility；
- Lock/Waitlist/Transaction 等业务占用事实。

`locked / trading` 期间真实车辆事实仍可变化。有权限人员可以记录真实价格、车况、里程/资料、供应事实。

重大变化可以触发 Supply Anomaly，但事实更新不得：

- 自动取消 Lock / Transaction；
- 覆盖 Lock price snapshot；
- 删除 Deposit / 资金事实；
- 回写已经形成的 Transaction / 成交历史。

## 4. Supply Anomaly｜用户最终选择 B

用户明确选择：

> **Supply Anomaly 本身是风险告警，不统一阻断新增业务。**

具体 Recommendation / Consultation / Waitlist / Lock / Transaction 是否允许继续新增，服从：

- 当前真实 source/resource 可售事实；
- visibility；
- 对应业务对象自身 Guard；
- 对应 PDM 当前规则。

只有当车辆真实进入 `offline / unavailable` 等不可售状态时，才按不可售事实硬性禁止新增普通销售业务。

Supply Anomaly 仍保留：记录、通知、审计、自动/人工解除、历史异常留存；已有 Lock / Waitlist / Transaction / Deposit / 价格快照不因 anomaly 自动删除或取消。

## 5. 4S source_type 权限边界

`source_type=4S` 不等于授权任意 4S 成员。

- 名邦员工上传并选择 4S 合作车源的车辆仍属于名邦公司业务资产；
- 4S 成员只操作自己当前合法有权管理范围内车辆；
- source_type 与 identity / permission / data scope 必须分离。

## 6. JYT 三个固定车源业务 API

V1 固定：

1. 新增/更新车源 API；
2. 批量确认下架 API；
3. 获取当前名邦仍在售批发车源 API。

边界：

- 外部程序无名邦 DB 账号；
- 使用名邦车源同步 API Token/API Key；
- 不是 JYT 登录 Token；
- 与 Collector 电话鉴权分离；
- 三个 API 独立启停；
- 至少记录调用时间、接口名、成功/失败、提交/返回/处理数量等运行事实。
