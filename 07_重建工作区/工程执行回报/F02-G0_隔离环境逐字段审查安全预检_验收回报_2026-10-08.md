## 2. 真实执行环境与数据库隔离

- GitHub Actions 运行器 `ubuntu-latest`，Node `22.16.0`，npm `10.9.2`，依赖由既有 `engineering/package-lock.json` 统一锁定（`pg@8.23.0`）。
- GitHub CI 服务容器 `postgres:16-alpine`（版本由只读 PG `server_version_num` 验证确实是 16 系列）。
- 容器使用一次性引导用户建立专属 `f02_schema_test` **空库**及 `f02_ci` 非超级、不可 CREATE ROLE/CREATE DATABASE 的账号；仅 CI 生命周期内存在。账号不是业务账号。**初始化时使用 CREATE ROLE / CREATE DATABASE 是搭建隔离空环境，不是 Current Schema 迁移或 F02-1 DDL。**
- 严格允许本机 `127.0.0.1:5432/f02_schema_test`；连接字符串独立存于 `F02_G0_DATABASE_URL`。F01 `f01_foundation` 与任何远程/生产库明确拒绝。
- 需 `CI=true`、`GITHUB_ACTIONS=true`、`APP_ENV=test`、`NODE_ENV=test`、`F02_G0_OPERATION=readonly_preflight` 和显式 `F02_G0_ISOLATION_CONFIRM`；任一条件不符 **FAIL CLOSED**。
- G0 入口只接受零参数运行；`--apply/--migrate/--reset` 等直接报 `F02_G0_MIGRATION_EXECUTION_DISABLED`，无执行 SQL 文件或版本写入接口。
- 连接成功后执行 `BEGIN READ ONLY`、只读检查当前数据库/用户/角色权限/PG16/空 public、用 `CREATE TEMP TABLE` 检查数据库引擎拒写（必须 `SQLSTATE 25006`），最后 `ROLLBACK`。**没有业务表、迁移表、种子表创建。**
