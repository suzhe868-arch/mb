| PDM-23/24/25｜横切事实 | Notification/Announcement、Audit、历史、时区、配置版本、真实 mutation 结果、幂等与事件关联 | audit append-only、config-version/snapshot、idempotency/outbox 与通知事实；操作时间可信服务端、业务自然日 Asia/Shanghai；不能把技术日志保留期覆盖永久性业务历史 |

**关键不变量的数据库和服务端职责分界**：

1. 单 active Lock、单 active in-progress Transaction、单 active priority 等适合使用状态限定的部分唯一索引，实际 where 条件须与 Current Final 逐字段对齐。
2. LockRequest 6 小时过期、资格合法性、自动候补条件、资金可退余额和公海保护属于**跨对象、跨时刻条件**；数据库约束 + 单事务行锁/冲突控制 + 服务端 Guard 共同保证，**不能只靠一个 CHECK 表达**。
3. source_platform、upstream identity、listing_cycle、customer/vehicle 身份链采用可复核的复合 FK 或等效事务断言；凡旧模型的历史链接均不得不经验证就重写。
4. 客户可见性/价格/电话安全投影由 F03/F04/F05 服务层严格二次校验，F02 只准备安全字段与关系承载，**不把列存在等同于可见授权**。
5. 历史记录与实时状态分离；真实纠错追加事实而非覆写历史；业务时间存储保留原始时区或 UTC 时间点，再按 Asia/Shanghai 解释业务自然日。

## 5. 拟议安全迁移策略（**获批后才实现/运行**）

### G0：环境与实际数据库基线调查（当前状态：NOT_RUN）

- A 先确定 F02 使用的**唯一隔离数据库目标**、凭据托管、允许的网络、测试环境使用权与操作窗口。
- 仅在获得独立授权后，以只读元数据方式核查：PG 大版本/extensions、`schema_migrations`、对象/索引、现存数据量、DB user 权限、可能的历史 schema 版本。**当前没有已迁真实库的可信证据**；不要假定所有已部署库都从 000001 开始。
- F01 `engineering/src/postgres.mjs` 严格允许 `APP_ENV=test` + localhost + `f01_foundation` 的探针；**不可**通过禁用其 Guard 把它变成迁移执行器。

### G1：双通道 Migration Baseline（仅建议，未裁决）

1. **空库路径**：新的 Current Initial Baseline 建立正式现行模型，不绕道恢复全部八份旧错误结构；新表及约束按 PDM Final 和逐字段清单生成。设计专门的 schema_version 与 checksum。
2. **已有库路径**：从实际已部署历史版本/数据快照到 Current 的**追加式兼容迁移**。已经施行的老 migration 不改写、不乱删；凡需去旧约束，用新 migration 单独处理，并保留必要数据演算和失败回滚证据。
3. 环境未知或身份不明：**FAIL CLOSED**，不得用“重建一次就好”策略清库。
4. 两条路径最终以 schema dump/constraints/数据完整性断言比较等价，且必须覆盖迁移重复运行和中断恢复。

### G2：原子、并发与回滚设计

- 建议版本表保存 migration ID / checksum / applied_at / actor / tool version，单次迁移包含 **SQL 变更 + 成功版本记录在同一事务**（除需显式单列非事务步骤外）；以 PG advisory lock 或等效唯一执行锁防并发迁移。
- 迁移脚本应配置 `statement_timeout`、`lock_timeout`、错误即停止，记录失败 SQL 文件/耗时而不写机密。
- 增量添加约束考虑“扩展列→数据回填→约束验证→切换写路径→收缩废弃列”的 expand/contract 分步。非事务性在线索引、异步回填需专门 failure/cleanup/checkpoint 设计，不能伪报整体一个事务。
- 不依赖 `DROP SCHEMA public CASCADE`、不对有业务历史表使用普通物理删除。破坏性 DDL / 非逆变更要单独标记、审批、备份/恢复演练。
- 备份可恢复性以实际 restore 演练证明，而非仅“已有备份文件”。未具授权时不连接任何用户库。

### G3：预设验收矩阵（尚未运行）

| 验收组 | 必需正例 | 必需负例 / 崩溃恢复 |
|---|---|---|
| Schema | 全新空库迁移完成；目标表/FK/索引/Check 与 Current 核对 | 缺版本/漂移/错误文件 checksum/中断，不可半成功 |
| 已迁库 | 有合法历史数据快照增量升级、历史 IDs 与来源关系保持 | 旧单草稿索引、旧退款两态/Collector 配置不再污染现行约束 |
| 幂等 | 同批重复运行不重复表/索引/种子，版本表准确 | 两个迁移 worker 并发启动只有合法赢家；锁超时可恢复 |
| Draft | 同员工多草稿/自动保存；草稿不进入正式 Vehicle/cycle | 无草稿误生成 cycle/无客户可见；正式 Vehicle 不允许普通删除 |
| Vehicle | 同 `vehicle_id` 来源转换、listing_cycle 事实与 hidden 分层 | 无假新车/重复 active cycle/旧车源被误复活 |
| Lock/Waitlist | LockRequest PENDING 6h、同车唯一 active Lock；合格冲突自动 Waitlist | 申请不先占车；非法资格不自动候补；并发不会多 active Lock |
| Transaction/Refund | Lock 原子转 Transaction、closed 与 refunded 分开、合法余额递减 | 事务任一步错误整体不落；并发超退、重复退款、不合法 Lock subject 被拒 |
| Owner/权限 | 唯一 owner、公海 null；数据/敏感对象正确 FK 与审计 | 4S/System Admin 越权不得仅靠物理表存在获得能力 |
| Dictionary | 六数据资产 staging、中文无损、引用完整、版本变更真实 | orphan/重复/非法 enum/映射冲突隔离；失败不污染正式主数据 |
| 时间/审计 | Asia/Shanghai 自然日和 UTC time instant 分离；history append-only | 时区边界、重试、撤权后敏感历史投影不可泄漏 |

**以上均为计划中的必测项：当前结果统一 `NOT_RUN`。不得用 F01 CI（仅健康探针）替代任何 F02 Schema/迁移证明。**
