## 5. F02 迁移器入口设计与技术冻结边界

本轮实装目录：`engineering/f02-g0/`，仅有 `preflight.mjs`、`guard.mjs`、Guard 正反例和静态字段矩阵。未来 F02-1 迁移模块（`engineering/f02/migrations/current-initial/`、独立 migration runner 与 `schema_migrations`）**尚未创建或执行**。

- 迁移器设计需要：一版本单元 SQL+记录同事务、checksum、并发 advisory lock、未知版本拒绝，连接身份白名单、超时和明确空库条件；非事务性 DDL 单独隔离恢复。
- G0 没有受理 SQL 文件或 `--apply` 的入口；任意命令参数先于数据库连接被 Guard 拒绝，无法将 G0 脚本变成清库工具。
- F02-G0 检查使用 `BEGIN READ ONLY`、系统目录元数据 SELECT 和主动 CREATE TEMP TABLE 负例（数据库应拒绝 SQLSTATE 25006），且最后 ROLLBACK；没有新增任何业务表或版本记录。
- 临时数据库初始化只允许 CI Docker 中创建 `f02_ci` 非超级用户及单独 `f02_schema_test`；和 F01 的 `f01_foundation` 彻底分离。容器随 CI job 回收。
- 不修改 F01 `engineering/src/postgres.mjs`、旧代码、三端 UI，也不触碰生产或真实已迁库。
