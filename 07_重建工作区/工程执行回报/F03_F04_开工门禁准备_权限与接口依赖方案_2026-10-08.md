## 2. F03 身份授权模型计划

| 授权层 | 当前正式要求 | 后续技术方案和测试输入 |
|---|---|---|
| 身份类型 | 客户 / 名邦员工 / 4S 成员 / System Admin 身份边界清楚 | principal 类型、issuer/audience、身份失效条件、双账号隔离合同 |
| 有效能力 | `角色默认 + 个人 allow/deny + hard DENY + data scope + object state` | 建权限评估矩阵；hard DENY 永远优先于个人 allow；权限仅在服务端决策 |
| 员工与客户归属 | 一个 Customer 至多一个 current owner，公海时 null；分享/转介绍不抢已有 owner | 权限决策同时引用 owner + object relationship/assignments；owner 移交与业务 responsible 分层 |
| 4S hard DENY | 4S 不能跨店管理名邦内部数据或见批发价/内部价 | 正反例：列表/详情/导出/缓存/分享链接均无敏感字段 |
| System Admin 控制平面 | 配置能力不自动等于业务执行权，不能配置打开产品 hard DENY | 账号分离与控制平面审计，禁止管理控制台绕过业务审批 |
| 撤权/停用/角色变更 | 旧 session/cache/export 不得保留过期敏感访问 | session/claims freshness 与撤权即时生效策略、负例覆盖 |
| 审计 | 真实 actor/当时 role scope/mutation/before-after/result 记录 | PDM-25 append-only、机密字段脱敏、历史只能按当前权限投影 |

**F03 候选交付拆解（A 后续单独 Gate）**：权限词典和 hard DENY 审计 → principal/session 与 scope 结构 → 4S/System Admin 隔离 → 敏感字段投影和服务侧 Guard → 撤权/停用/缓存负例与审计。数据库权限索引/种子必须和 F02 的 schema_version 与权限初始化策略交接，**不擅自使用历史 000002 许可表作为正式权限**。

## 3. F04 接口合同与工程架构计划

| 合同项 | 后续必须形成的实物 | 必需负例 |
|---|---|---|
| 旧 218 接口归属 | method+path → KEEP/MODIFY/RETIRE/REPLACE/ADD 的逐条决策，标出 PDM、IA/Low-Fi action、DTO、scope、state、结果码、审计与负责 F 阶段 | 老 Collector GET/PATCH/TEST 不可达；“历史接口存在”不能作合同验收 |
| 当前新增接口 | LockRequest / Waitlist、Refund closed+原因、真实价格查看策略、Collector 向名邦 Integration API 回传，以及现行三端动作 | 错误 actor/state/对象/幂等导致的拒绝和业务事实不写入 |
| 生成与运行一致 | Current OpenAPI→types→operation-index→route registration 一致性检查；集成测试实际命中已注册路径 | API 文件写了却没装配 route、隐藏字段被 serializer 透出 |
| 幂等与并发 | idempotency key 结合 actor/operation/object scope，冲突语义清楚；敏感 mutation 绑定事务与审计 | 重放错误参数、并发双成功、跨客户对象引用 |
| 数据模型协同 | API DTO 不直接泄露 DB 行；F03 最小投影；事务/锁/退款/候补边界以 PDM Final 为准 | 4S/System Admin 越权、车辆隐藏/优先保护被查询穿透 |
| 架构路线 | F01 目前 Node ESM + HTTP；历史仅有 Fastify/TypeScript 候选，无实际完整业务实现 | A 在 F04 前审查保留单一 HTTP 服务入口、类型检查策略，避免 Node/Fastify 双入口分裂 |

**F04 不是在旧 OpenAPI 的 218 条里随手修改几条就可以完成**；当前 IA/Low-Fi 的状态/动作覆盖与 PDM 完整义务必须有反向覆盖表。此表应在获批 F04 首个批次生成并实测，不应在未施工 Gate 阶段虚报 218/218 当前逐字段通过。
