## 二、A明确裁定最小物理结构（新迁移000006，真实CI固定manifest）

**仅两张附加表，绝不借此新增额外门店/团队业务组织层级或默认授权：**

- `teams(team_id BIGINT PRIMARY KEY, store_id BIGINT NOT NULL REFERENCES stores(store_id), team_status TEXT NOT NULL, created_at TIMESTAMPTZ NOT NULL)`：代表有显式ID的名邦内部团队，关联宿主门店仅作组织元数据；`team_status`只允许`active/inactive`合成内部值。门店不直接代表团队、店内所有员工不会自动加入团队；**不建立4S店团队**。
- `employee_team_memberships(membership_id BIGINT PRIMARY KEY, team_id BIGINT NOT NULL REFERENCES teams, employee_id BIGINT NOT NULL REFERENCES employees, valid_from TIMESTAMPTZ NOT NULL, ended_at TIMESTAMPTZ NULL, changed_by_system_admin_id BIGINT NOT NULL REFERENCES system_admins)`：仅由可信独立System Admin在CI内部增/结束明确成员，支持时间窗口当前有效判定，成员为Employee当前主角色销售/经理/店长而非4S、必须当前active；缺行、已过期、未来有效均拒绝。历史不物理删除，同一员工/团队不能存在两个重叠有效membership窗口；同角色或同店不能推定成员。是否允许员工多个不同团队由数据明确绑定，不根据门店自动补充。
- 为确保并发修改/校验不发生漏锁和同员工重复活跃成员，B可在**这两个表内部**选择必要唯一/范围/索引、数据库排他约束或统一目标锁，并在真实CI下证明；若某SQL索引/扩展要求额外数据库extension或修改旧Schema，必须交A进一步裁定，不得超出两个表或自动安装扩展。
- **不修改既有`employee_data_scopes`或`employee_capability_scope_bindings`旧表结构**。Team scope必须以已有`employee_data_scopes.scope_kind='team'`、`scope_reference_id=真实team_id`和对应受限capability明确绑定，加上成员当前有效关系共同证明；没有scope或许可就拒绝。已有表scope_kind是否有check枚举必须从真实SQL证据核对，若无法表示team则标`DEFER_DENY`而非修改旧迁移。
- 写入资格与Team Scope读取都需要使用真实F03-1正常PC会话、来自DB的身份、权限和object state；Team成员治理仅可信System Admin内部可写，经理不因这两表产生`team.manage`或额外employee permission。
- 任何新member变更必须在同PG事务追加`audit_events`脱敏old/new并更新明确可复核版本/当前事实，错误全回滚；只有真实状态改变才记录成功事件，同请求NO_OP不重复记录。成员结束不物理删除；新时段必须保留历史区间。请求携带`actor,role,isManager,scope,global,owner`伪事实的方案全部拒绝。
- Team membership / scope的读取仅提供**独立受限内部事实证明函数**，包含`canManageTargetTeamScope`类似用途：验证当前actor真实Employee身份与main_role、当前业务管理permission来源、当前有效capability-specific scope、team实体active及target成员有效、target Employee active+合法角色。必须把`scopes.ended_at`/memberships有效期和权限/个人deny一起判断；不符合一项就DENY。
- 因当前F03-2尚未开放完整员工管理capability及SG07通用提交时重验，本批不实施经理真实写下属接客、员工权限/角色/离职/调店，也不将`canManageTargetTeamScope`读结果自动连接到SG03`changeOwnReceiving`：业务写入另批并按相同事务重验。本批只验证**当前可信Team Scope内部判定**、资格记录原子审计与回滚，不能据此宣称经理团队员工管理完整完成。
- 不直接推断跨店管理权；同一经理/team membership即使跨门店仍须明确合规permission+capability scope和各对象状态，否则拒绝。绝对排除4S和System Admin作为manager/team Employee业务代理。
