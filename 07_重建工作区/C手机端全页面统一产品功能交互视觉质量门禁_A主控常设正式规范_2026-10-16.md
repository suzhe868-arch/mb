## 一、执行者与责任归属（谁应该提前发现错误）

1. **A在下达每个新页面包前必须完成门禁G0、G1**：列页面ID、最终产品权威、字段与业务动作、角色/权限/可见性、有效/禁用状态、页面之间的导航关系、逻辑区域顺序、实际授权的Mock与API边界、同批验收和跨批依赖；提供可逐行复验的「页面契约卡」。A不能把“依照PDM自行设计”当成完整施工单，也不能把未授权的真后端行为包装成前端缺陷。
2. **C必须在编码前独立反向核查A的页面契约**：拿Final、IA、用户冻结问题台账和当前历史遗留缺口逐条比对，发现缺失就提交完整缺口补充，不得因A没写就静默忽略；若仅是样式实现细节C可在确定体系内自主决定，出现业务权限、价格、锁车状态等真冲突先交A裁决。**未完成此核查禁止把页面标记可交验收。**
3. **C对可运行页面的第一轮产品视觉质量负责**：同一工作包一次完成开发、自审、修复、真实浏览器截图、四宽度与各关键状态；不得把第一个粗糙版、调试页或占位图片交给用户做QA。
4. **A独立对“功能完整性＋业务语义＋真实视觉”分开判定**：源需求→元素/动作/状态、元素/动作/状态→合法源要求双向都通，CI合格后仍需真渲染人工审核；用户只看真实可操作页面和关键分歧，不承担替C找常规漏项。A不能以“26/26测试通过”代替画面验收。
5. **已通过的关键模板冻结为“可复用设计基准”**：如客户车辆卡/客户详情底部CTA/客户价格样式、员工内价区/表单/审批确认组件。新增页面复用已验收的token、按钮/提示/导航，而不是各做一套；差异因业务语义、平台限制或产品Authority才成立，附依据。未经过用户认可的C01当前设计**绝不视为模板**。

## 三、固定的视觉质量下限（以实际运行画面为准）

- **品牌与可信度**：克制的黄＋灰＋白/深灰候选，黄用作关键强调而非全屏铺色；内容像正规汽车交易平台，禁止“大MB字母口号广告/渐变/无意义数字墙/开发调试后台感”充当正式视觉。品牌视觉关键方向仍由用户实际看到的预览确认；未确认前只称候选。
- **信息密度与层级**：首屏先呈现该页最重要的业务对象或可执行任务；搜索/筛选/状态/标题要让位于车辆、客户、锁车申请等核心卡片；信息不无故重复，不用多层同义标题；价格、业务状态、主CTA明显高于补充元数据。
- **排版可读性**：正文基线建议不低于14 CSS px（小程序按等效相对单位换算），元信息若用12–13 px必须在真实屏幕证明清晰，对重要动作/价格不得用极小字；长车型、长中文姓名、异常金额、空字段不得溢出、重叠或仅靠截断丢掉关键状态。此为**视觉检查基准**，不替代平台自适应与无障碍要求。
- **交互与触控**：主要触控目标优先达到约44×44 CSS px的等效可触达区域，狭窄屏仍有间距与可辨状态；不要靠仅变色区分已选/禁用/错误；所有显著入口有点击反馈、加载/拒绝与安全回退；底部固定栏/机型安全区不挡内容。
- **图片与素材**：有真实许可且车型、来源、比例匹配才展示汽车照片；否则中性占位并清楚标识，无水印误授权、不能宝马图标比亚迪车型；开发Mock图不冒充真实待售照片；图片损坏有回退，保证版面不塌。
- **组件系统**：C维护一套可复用视觉token与组件约束（颜色语义、字号、间距、圆角、边框、卡片、按钮、表单/筛选、消息、空态、加载、错误、价格/权限提示）；新页引用同一组件实现，业务安全边界需组件级注释与测试。不得为了“统一按钮”抹平C/E不同权限、操作危险级别。
- **页面文案**：给客户/销售看的是自然中文，不出现JYT、DTO、principal、Mock-only技术条、“待开发/调试版”等开发占位；若功能确实没授权，应有合规禁用/友好提示，不许按真服务显示“成功”。QA场景保留独立测试入口/参数及可重复测证据，不能直接删掉测试覆盖。
- **弹层与导航**：筛选、排序、确认、失败、撤销、审批、图片预览都要有可关闭/返回的明确路径；抽屉/弹层可在320宽滚动且按钮不挡内容；由列表进入详情再返回，应符合各页正式上下文恢复要求。工作台审批不得把危险操作做成无提示误触。
- **模板先批准再批量复制**：C01当前用户否决不可推广；当A确认代表性客户页和员工页真实代码模板通过，C后续同类页面用基线资产继续做，不再每页独立画设计稿，也不要求用户逐页签字；若新业务呈现确有重大视觉选择，由A集中请用户看一组候选。

## 四、固定的“不能偷漏功能”追踪逻辑

每页/弹层生成一张**页级合规卡**（见同目录模板TSV），至少追：`PageID + Authority ID + 角色 + 数据字段/来源 + 核心操作 + 业务状态 + 空/加载/错/无权 + 按钮/导航 + 视觉层级 + 代码文件 + Mock/API归属 + 测试/末SHA截图 + 结果 + 未授权依赖 + A验收`。以下规则为硬线：

1. **正向差集0**：Final要求且在当前施工包授权的UI要素，不能没有组件/测试；当前未授权但属于最终产品需求，需留`DEFERRED_WITH_REASON`而不是删除或称已通过。
2. **反向孤儿0**：代码中能点击的业务按钮、展示敏感字段、假成功提示、页面导航不得没有现行产品来源。静态样式组件允许设计系统编号。
3. **状态/角色不可降维**：普通/粉丝/VIP、客户归属、名邦员工/4S/店长/后台权限、车辆/LockRequest/Waitlist/Transaction状态仅按本页适用的合法组合验证，不能随手合并成“未登录/已登录”两态。
4. **Mock与真实分轨**：`UI_IMPLEMENTED`、`MOCK_TESTED`、`API_INTEGRATED`、`E2E_VERIFIED`、`USER_VISUAL_APPROVED`分开记，不能用一种PASS抵其他全部PASS；未签签名/API合同则严格`DEPENDENCY_BLOCKED / NOT_AUTHORIZED`。
5. **每页两类独立检查**：自动化侧查字段过滤/交互/状态/响应与测试，人工真实图侧查首屏信息层级、车型素材、文字可读性、颜色/留白、按钮层级、跟已验收模板一致性。自动断言不能伪装审美已批准。
6. **缺口责任分明**：缺源产品裁决归A集中交用户；缺前端UI/浏览器证据归C；缺受签真实服务合同归后续B/A授权；真实微信真机、生产、第三方凭据另审批。不许一个`C_SELF_PASS`把外部缺口抹掉。

## 五、每次正式交接的不可简化附件

1. **页契约卡与差集**：A签单中逐页明确本批必做UI、未来依赖和禁止恢复；C补实际差集、自审中发现的漏项及已修复结果。
2. **真实可见证据**：同HEAD Chromium主视口完整核心用户路径；四宽代表页和本包特殊状态/长文/无图/加载/拒绝；Mock测试界面与客户展示界面分别取证。关键页首次模板前后对比须标具体改动。
3. **工程与业务安全**：依赖锁/类型/构建/真实交互、适用的正反/拒绝/撤权测试，末SHA Workflow Run/工件；产品Authority权限数据过滤与返回上下文核查。
4. **自评＋A独立核验**：C逐项写是否达标与剩余授权缺口；A不是只看C报告，还要实际检查源码、末SHA图与界面交互。功能和视觉两个判定都未PASS的页面不标`A_ACCEPTED`。
5. **用户只承担关键视觉决策**：业务功能已按Final制定，A/C自行返工；用户集中查看新关键模板真实运行效果，而不是每页逐项查字或担任QA。用户未确认就不能冒充已确认。
