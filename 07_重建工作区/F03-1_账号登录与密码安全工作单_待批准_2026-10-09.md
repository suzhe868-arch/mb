### F03-1实现批：方案获验收并另行放行后
- 单一PC凭证读写、强制改密、本人改密、合法重置、凭证禁用与主身份停用拒绝。
- 使用已审定的密码哈希、验证、通用匿名失败响应与限速；不写明文密码/哈希/token到日志和工件。
- 可撤销会话：退出/重置/禁用/inactive后旧会话拒绝，复职不复活旧会话；并发改密/重置遵循原子更新与一致审计。
- 4S无明确PC资格时不能登录业务后台；具备资格只获得合法4S车辆范围，不绕过hard DENY。
- System Admin登录身份与Employee完全分离；改密不授业务角色或owner资格。
- 若有精确新增结构，仅在批准的一次性隔离PG16库使用新的独立迁移，不连接既有业务库。
- 沿用单一Node ESM运行入口；需要的认证HTTP适配与共享文件改动必须在该实现批工作单明确，不借此开工F04全域API。

## 3. 实现批必须实际证明的检查
| 场景 | 结果 |
|---|---|
| 错误/未知账号、错误密码 | 通用失败，日志无秘密，不暴露账号存在性 |
| 初始认证成功且要求改密 | 只能改密/退出，普通业务与治理请求拒绝 |
| 改密/重置/凭证禁用 | 正确新凭证合法流程通过；所有旧会话拒绝 |
| Employee inactive/复职 | inactive拒绝；复职须重新验证，旧会话不复活 |
| 4S未开PC/已开PC | 未开拒绝；已开仍受身份、scope、hard DENY |
| System Admin与Employee同真人 | 两套独立身份，不能混用或继承业务能力 |
| 会话过期/撤销/退出/伪造 | 拒绝；错误数据不降级为默认允许 |
| 并发改密/重置/停用 | 无旧凭证或旧会话穿透，原子结果及审计可追溯 |
| 迁移失败/重复/并发（如有新增结构） | 不改已验收Initial SQL，失败恢复与新版本证据闭合 |

真实role/scope数据源与完整治理、最后active管理员和接客保护仍需F03-2；微信、JYT、F04业务路由、F03-3全量字段投影、正式前端不包含在本批。
