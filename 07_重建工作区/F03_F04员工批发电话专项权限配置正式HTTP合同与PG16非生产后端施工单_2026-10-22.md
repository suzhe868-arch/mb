## 二、B 必须完成的功能（一次性业务闭环）

1. **员工现时查询 GET**：`GET /api/pc/employees/:employeeId/publisher-phone-permission` 只返回目标 employeeId、当前 active/role 可配置性、既有 `publisher.phone.sensitive` 个人授予状态、模式二选一、version、updatedAt 与合适 ETag；严格不返回电话号码、Collector 缓存、客户资料或其他隐私。只有合格、当前有效的 System Admin 管理会话能读取；普通销售/经理/店长不能凭角色直接读取或配置。若现存管理 capability + scope 已受验覆盖其他管理者，可先标 `SOURCE_GAP`、另提 A 裁决，不能自动授权。
2. **原子授予/模式变更/撤权**：`PUT /api/pc/employees/:employeeId/publisher-phone-permission` 接受 `{scopeMode:"LOCKED_ONLY"|"ALL_ACTIVE_JYT",expectedVersion,requestKey}`；`DELETE` 接受 expectedVersion/requestKey。禁止隐式新 permission、自动角色默认授权。一次 PG16 事务同时检验管理员当前身份/状态、目标员工当前 active 及角色资格、存在的规范 `public.permissions.permission_code='publisher.phone.sensitive'`、员工原个人 override + capability scope binding + 特殊 data scope，变更允许的现行权限实体、私有**同库**模式与版本和不可变事件/审计，失败全回滚。
3. **签名与 DDL 边界**：只用新 `engineering/f03/publisher-phone-staff-admin/**` 下私有、临时 `f03_publisher_phone_admin_test` sidecar 记录 scope mode/版本/重放；绝不变更冻结 `public` M94/000015/000016/F03 已受验 DDL 或通过另一数据库独立写入伪称原子。若 F03 已存在同用途受验模式 source，优先只读复用、不得补出第二套正式模式真源；只允许用此隔离单库建立 `CI_ONLY_F03_PERMISSION_CONFIG` 能力。生产长期存储需要另行完成签名来源整合。
4. **HTTP 真入口**：新增 Node service 与 HTTPS handler；严格验证当前受验 F03 Session、同源、CSRF、凭据、JSON schema/大小、目标 ID、管理资格、请求幂等、ETag/CAS、多管理员竞争及稳定无敏感明文错误。允许仅在`engineering/src/app.mjs` 注入可选的真实 test handler；如必须在 `engineering/src/server.mjs` 接线，仅在独立 `CI=true`、`GITHUB_ACTIONS=true`、`APP_ENV=NODE_ENV=test`、精确 B HEAD/branch/repo、明确 consent、127.0.0.1+TLS、合格非超管 PG16 时可开启。默认启动必须保持旧行为，非隔离场景绝不注册新写入入口。
5. **会话和权限竞态**：同一版本两管理员并发只能一人成功，另一个 409；员工调店/离职/切换 4S/能力明确 deny、系统管理员停用与提交竞争必须按真实 PG16 当前事实重新校验，不能凭页面旧态或旧 cookie 成功。System Admin 本人不得取得电话业务读取/拨号权；撤销应立即让同库配置查询/Guard 看到无权，不靠缓存 TTL。
6. **字段安全与审计**：每次合法改变写入 before/after/admin actor/at-time、幂等关联、模式唯一性和撤销事实；不得记录明文电话/客户敏感资料/密钥；审计与模式/权限在同一 PG16 COMMIT 中。对已有 phone Guard 的**跨数据库来源**明确写 `NOT_CONNECTED_F07_RUNTIME`，不得宣称 F07 真实电话动作已经从本 API 获得有效配置。
