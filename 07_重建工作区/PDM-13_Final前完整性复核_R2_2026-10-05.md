## 2. P13-LIA-07 复核

当前 Authority 已明确：

1. active Priority 不能只依赖“过去曾 high/acceptable”；
2. trigger Demand×Vehicle current Match Result 若降为 `confirmation_needed/no_match`，必须立即重评；
3. 先检查同 Customer 其他 active + matching-ready + current high/acceptable Demand；
4. 有则切换 `trigger_demand_id`，Priority 继续，原 `expires_at` 不变；
5. 无则 Priority ended，记录 `match_invalidated` 或正式等价原因；
6. Vehicle 随即读取全部 Customer 当前合法 Match Result 重新仲裁；

与 PDM-12 invariant 一致：

- confirmation_needed 不占车、不排他、不创建 Priority；
- stale/invalidated 历史结果不得驱动新的 Priority。

结果：`PASS`。

## 3. P13-LIA-08 复核

### 3.1 TTL 是最长保护上限

- 默认 24h / 86400s；
- 后台可调整后续新 Priority 默认时长；
- 创建时固化 expires_at；
- 不人工续期、不人工改 expires_at；
- 合法 responsible employee 无需等待 TTL 到期，可提前执行“释放 Priority / 不推荐此车”。

提前 release ≠ 修改 TTL；它是合法 Priority lifecycle action。

结果：`PASS`。

### 3.2 提前 release 后立即重新仲裁

员工 release 后：

- 当前 Priority ended；
- 记录 actor/time/reason；
- 原 Customer 在同 listing_cycle 内按 release suppression 防止相同旧事实立即自动选回；
- 有其他 Priority candidate → 按统一仲裁；
- 无 Priority candidate、有普通合法 Match Result → 普通后续机会；
- 当前无人符合 → 本轮不创建新对象，Vehicle 继续参与未来 Matching。

结果：`PASS`。

### 3.3 Recommendation 与 Priority 分离

尚未正式 Recommendation 时：

> 只能执行“释放 Priority / 不推荐此车”，不存在“取消 Recommendation”。

已有 Recommendation 时：

- Recommendation 与 Priority 仍是两个对象；
- 员工体验层可后续设计组合动作“结束推荐并释放保护”；
- 底层必须分别执行 Recommendation end 与 Priority release；
- 两个动作分别 Guard、审计、留历史；
- Recommendation cancellation alone 不结束 Priority；
- Priority release / expiry alone 不结束仍合法 Recommendation；
- 正式 Recommendation 成立后可把 `recommendation_id` 关联回 Priority 用于追溯，但不得合并生命周期。

该规则显式 supersede 9/17 历史中把 `recommendation_cancelled` 直接列作 Priority ended reason 的旧绑定；这是用户本轮明确修正版。

结果：`PASS`。

### 3.4 不向后撤销 Lock / Transaction

- Recommendation cancel 不撤销已成立 Lock；
- Recommendation cancel 不撤销已成立 Transaction；
- Priority release/expiry 不撤销已成立 Lock/Transaction；
- Lock cancel/expiry 不恢复旧 Priority；
- Transaction cancel/correction 后 Vehicle 真正开放，也不恢复旧 Priority，只按当前事实重新仲裁；
- Recommendation 若仍 active，其 visibility 继续由 PDM-14 Authority 判断。

结果：`PASS`。
