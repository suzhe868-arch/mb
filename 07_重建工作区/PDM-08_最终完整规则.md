## 1. 批发图片集合首次冻结

批发车第一次入库时读取当次 `images[]`，保存：

- 图片 path / 来源身份；
- 上游图片标识（如有）；
- 原始顺序；
- 必要来源元数据。

后续普通 JYT 同步：

- 不因为上游新增图片而自动补入；
- 不因为上游删图而自动删除当前图片记录；
- 不因为上游改排序而改写名邦保存的原始顺序；
- 单张图片失效只处理该图片自身；
- 不因单张失效重新同步整车图片集合。

普通批发采集图片的原始顺序不允许普通人工直接拖动 / 改写。

---

## 2. 图片 path、公开域名与上游域名

普通采集图片类业务数据以图片 path 为核心来源事实。

- 数据库不把名邦公开图片域名写死进业务数据；
- 数据库不把 JYT 图片回源域名写死进业务数据；
- 对外地址由“名邦可控公开图片域名 + 配置前缀 + path”运行时生成；
- CDN 回源由“配置的上游图片源站 + path”生成；
- 客户端 / 员工端不得直接使用 JYT 原始图片域名；
- 完整 H5 / 报告页面不套用普通图片 path 规则。

公开域名、前缀、回源域名均属于可配置项。

---

## 3. 批发车首图与 CDN 自然缓存

批发车首次入库：

- 只冻结图片来源 / path / 原始顺序；
- 不要求主动调用 CDN 厂商预热 API；
- 不要求采集阶段先把首图永久写入名邦对象存储。

列表 / 首页首次实际请求首图：

1. 客户端请求名邦受控 CDN 地址；
2. CDN HIT：直接返回；
3. CDN MISS：CDN 在同一次请求中实时回源 JYT；
4. 图片成功取得后，同一次请求直接返回当前客户并形成 CDN 缓存。

首图失败时：

- 按原始顺序向后寻找下一张可用图；
- fallback 只改变当前展示封面，不改变数据库原始排序；
- 原第一张以后恢复可用后，可以重新恢复原排序位置 / 首图资格；
- 0 图或全部图片不可用不阻塞车辆入库、在售、Matching 等业务；
- 无可用真实图时使用统一默认占位图。

---

## 4. 普通批发图片浏览阶段不永久落自有对象存储

除首图外，其余普通批发图片同样走 CDN 自然缓存：

- 客户查看 / 预取时请求名邦 CDN 地址；
- CDN HIT 直接返回；
- CDN MISS 实时回源 JYT；
- 同次请求返回客户并缓存。

普通批发浏览阶段：

> **不因为客户看过某张图，就要求把该图永久写入名邦自有对象存储。**

CDN TTL、节点层级、缓存生命周期、回源策略等归 Engineering。

---

## 5. 详情页两阶段图片预取

### 第一阶段：进入详情优先保障前 5 张

- 第 1 张通常已经在列表阶段请求；
- 进入详情后立即主动请求第 2～5 张；
- 这 4 张允许并行请求 CDN；
- 目标是让客户前 5 张尽量连续可看。

### 第二阶段：浏览到第 3 张时预取剩余

当客户实际浏览到第 3 张：

- 将第 6 张及后续所有尚未请求图片加入预取队列；
- 加入队列不等于无限并发；
- 实际并发、批次、节流由 Engineering 控制。

不恢复旧“第2/3张 + 预取第4张 + 前方约2张”的固定窗口。

---

## 6. CDN 并发、失败与恢复

产品层不再固定：

- 单车最多 3 张并发；
- 单图每轮最多 3 次自动重试；
- product-level single-flight；
- 固定退避 / 超时 / 熔断参数。

这些均归 Engineering。

产品业务层只保留：

- 同一资源避免无意义重复请求 / 重复回源；
- 不同图片允许并行请求；
- 当前失败图可暂不占客户可见位置；
- 图片来源记录与原始顺序继续保留；
- 后续图片恢复后按原始位置重新进入可见集合；
- 单图失败不触发整车图片重同步；
- 单图失败不改变 Vehicle 在售、Matching、Recommendation、Lock、Transaction 等业务事实。

---

## 7. 车辆状态变化不改写图片来源事实

visible / hidden、真实下架、售出、重新上架等车辆状态变化：

- 不改变首次冻结的图片 path / 来源 / 原始顺序；
- 不重新抓整车图片集合；
- 不因 hidden / visible 新建图片资产；
- 图片变化本身不创建 listing_cycle。

普通批发图：

- CDN 缓存是否存在、何时过期由 CDN 管；
- 下架不要求主动清空 CDN；
- 再次真实在售后继续使用同一名邦逻辑图片地址。

名邦 / 4S 自有对象存储图片：

- 车辆上下架本身不自动删除图片对象。

---

## 8. 名邦 / 4S 人工上传图片

以下人工上传图片直接进入名邦自有对象存储，不走 JYT 回源：

- 名邦员工上传的名邦车辆图片；
- 名邦员工上传的 4S 车辆图片；
- 4S 成员上传的 4S 车辆图片；
- 名邦 / 4S 自上传报告、档案图片。

DB 保存 object_key / path 等引用，不保存图片二进制。

人工名邦 / 4S：

- 允许 0 张真实图片正式发布；
- 0 图使用统一占位图；
- 正式发布后可继续补图、删图、调整顺序；
- 删除首图后，当前排序第一张成为新首图；
- 删除到 0 图仍可继续在售。

---

## 9. 对象存储资产正式成立的边界

只有真正进入名邦自有对象存储的图片，才适用资产化“双成功”：

1. 对象存储写入成功；
2. DB 成功建立有效 object_key / path / 资产状态引用。

两者同时成功才视为正式自有图片资产。

异常：

- 对象存储成功、DB 最终失败 → 清理新产生的孤儿对象；
- DB 不得把未完成写入的图片标成已资产化。

该规则不用于判断普通批发 CDN 图片是否可以展示。

---

## 10. 批发 → 名邦后的图片资产化

一键转换只存在：

> **批发 → 名邦**

不存在“批发一键转 4S”。

继续服从 PDM-04：

- 同一个 `vehicle_id`；
- 只改变 `source_type / 经营来源`；
- 不创建第二辆 Vehicle；
- 不创建新的 listing_cycle；
- Favorite / Recommendation / 当前 listing_cycle 已成立的客户侧关系不迁移、不重建。

转换后：

- 原批发图片需要正式进入名邦自有对象存储；
- DB 保存资产化后的 object_key / path / 状态；
- 不存在两个 Vehicle 之间的图片所有权转移。

---

## 11. CDN 缓存不等于名邦资产化

即使某张批发图片已经存在于 CDN 节点缓存：

> **也不能仅凭 CDN 有缓存，就认为图片已经成为名邦长期自有资产。**

正式资产化仍要求：

- 图片进入名邦自有对象存储；
- DB 建立正式资产引用。

是否利用已有 CDN / 中间缓存避免重复下载，属于 Engineering 优化。

---

## 12. 车辆转换与图片资产化解耦

批发 → 名邦的 source_type 转换一旦合法完成：

- 图片资产化作为独立子任务执行；
- 图片仍在 processing、部分失败或全部失败，都不得回滚车辆来源转换；
- 不得把车辆重新改回批发；
- 不得重建 vehicle_id；
- 不得重建 listing_cycle；
- Lock / Transaction / Favorite / Recommendation 等既有业务关系不受图片资产化结果影响。

---

## 13. 图片资产化状态与重试

图片资产化任务至少区分：

- `processing`：正在处理；
- `success`：目标图片全部完成资产化；
- `partial_failed`：部分成功、部分失败；
- `failed`：图片资产化任务整体未完成有效资产化。

这里的 `failed`：

> **只代表图片资产化子任务失败，不代表车辆来源转换失败。**

失败图片：

- 支持后续重试；
- 优先只重试失败项；
- 已成功图片不要求重新全部处理；
- 自动重试次数、并发、退避等归 Engineering。

### 13.1 资产化未闭环期间的临时受控回源｜3A

用户于 2026-10-05 明确选择 **3A**。

批发 → 名邦的 `source_type` 转换已经合法完成，但个别/全部图片仍处于 `processing / partial_failed / failed` 时：

1. 已资产化成功的图片立即按名邦自有对象存储 / CDN 读取；
2. 尚未资产化成功的图片，在资产化任务未闭环期间，允许继续基于首次冻结的 JYT 图片来源事实，通过**名邦受控 CDN 地址**临时回源 JYT 展示；
3. 客户端 / 员工端仍不得直接获得 JYT 原始图片 URL；
4. 临时还能展示 **不等于资产化成功**，DB 资产状态不得伪造为 success，失败项仍必须保留并继续重试；
5. 单张图片一旦资产化成功，立即切换为名邦自有对象存储的正常读取链路，不再把 JYT 作为该图片的日常读取源；
6. 若临时 JYT 回源也失败，该图片当前可以跳过 / 使用占位，不影响 Vehicle 已成立的名邦来源事实；
7. 不得因为临时回源失败或图片资产化失败回滚 `source_type`、`vehicle_id`、`listing_cycle`，也不得回滚 Favorite / Recommendation / Lock / Transaction 等既有业务关系；
8. 该机制只允许作为**资产化未闭环期间的过渡读取链路**，禁止实现成“名邦车长期继续依赖 JYT 图片”。

---

## 14. 资产化后进入普通名邦图片生命周期

图片资产化成功后：

- 按普通名邦车辆图片管理；
- 可新增；
- 可删除；
- 可调整顺序；
- 删除图片按名邦自有对象存储生命周期处理；
- 不再把 JYT 作为该图片的正常日常读取源。

同时：

- 原 JYT 图片 path / 来源身份继续保留为历史来源事实；
- 前端公开图片逻辑 URL 尽量保持稳定；
- 收藏、分享、Recommendation 等客户侧引用不因底层存储切换而重建。

## 15. 批发 CDN 缓存与名邦自有图片读取模型

### 普通批发图片

- 名邦 CDN 地址；
- HIT 直接返回；
- MISS 正常回源 JYT；
- CDN 缓存失效后按正常规则重新回源。

### 已成为名邦自有对象存储资产的图片

- 正常优先读取名邦对象存储 / CDN；
- 不再日常依赖 JYT；
- 本地对象损坏 / 丢失 / 404 时，可利用保留的来源事实做单图受控恢复；
- 单图恢复不得触发整车图片集合重新同步。

## 16. 出险记录图片

当前出险记录按图片方式处理：

- 保存图片 path / 必要来源信息；
- 客户端使用名邦可控图片域名；
- CDN HIT 直接返回；
- MISS 按配置回源 JYT；
- 不直接暴露上游域名。

但：

> **出险记录图片属于报告 / 档案资源，不自动进入普通车辆相册。**

客户是否可见继续服从 PDM-07。

## 17. 4S 维保图片与 4S 维保 H5

4S 维保存在两种平行呈现方式。

### 4S 维保图片

- 按普通采集图片 CDN 链路处理；
- DB 保存图片 path；
- 客户端使用名邦可控图片域名；
- CDN 按配置回源标准图片源站；
- 业务上仍属于维保报告，不进入普通车辆相册。

### 4S 维保 H5

- 上游完整 H5 URL 可作为原始报告来源事实保存；
- 客户端不得直接暴露上游 H5 域名；
- 对外输出时，把上游 H5 域名映射 / 替换为名邦可控报告域名；
- path / hash 等报告定位部分保持对应；
- 名邦报告域名配置化；
- 不要求为了 H5 去解析、改写其内部图片。

两者是平行呈现方式，不是父子关系。

### 17.1 报告 / H5 受控 URL 不是永久访问权

名邦受控报告域名、历史报告 URL、CDN 缓存都只是技术访问载体，不构成永久业务授权。

每次对外读取出险 / 维保 / 其他报告资源时，都必须继续服从：

- 当前 Vehicle Read / Visibility；
- PDM-07 当前有效的 `customer_visible`；
- 敏感原件 / 内部资料的 DENY；
- 当前访问者身份与数据范围。

因此：

> **即使用户过去拿到过某个名邦受控报告 URL，若当前已无 Vehicle Read 或该报告已改为非 customer_visible，也不得靠旧 URL 继续访问。**

具体短签、Token、鉴权回源、受控代理等技术机制归 Engineering。

---

## 18. 报告 / 档案资源与普通车辆相册隔离

车辆采集图、出险图片、4S 维保图片可以共用 CDN / 回源基础设施，但：

> **它们不是同一个业务图片集合。**

因此：

- 普通车辆相册只展示普通车辆照片；
- 出险 / 维保报告图片走各自报告入口；
- 绿本、行驶证、敏感原件等档案不进入普通车辆图片浏览序列；
- CDN 技术来源不能决定客户可见性；
- 报告 / 档案客户可见性继续服从 PDM-07。

首页 / 品牌分享标题、营销文案、分享图片配置入口等不在 PDM-08 展开，后续归 PDM-20 / PDM-22。

## 22. 分享卡片安全边界

车辆分享卡片可使用：

- 车辆主图；
- 完整车型名称；
- 必要客户安全展示字段；
- 轻量 CTA。

不得把以下内容固化进分享图 / 卡片：

- **客户展示价以及任何动态 / 受权限价格**；
- 内部批发价 / 上游批发价；
- VIN；
- 上游发布人电话；
- 内部状态；
- 其他仅内部可见字段；
- 不适合长期固化的动态敏感信息。

真正打开详情后，再按接收人的当前身份、权限、价格权益、车辆当前状态实时计算展示；旧卡片中的静态内容不得替代实时详情计算。

旧分享再次打开时：

- 重新读取当前车辆状态；
- 重新校验当前访问者权限；
- 旧分享消息本身不构成永久 Vehicle Read 权限。

---

## 23. 图片访问权限

图片 Read 继承当前 Vehicle Read / Visibility。

要求：

- hidden / Priority / Recommendation 等场景不能靠历史图片 URL 绕权；
- 当前无权读取 Vehicle 时，旧图片地址不能成为永久访问权；
- 客户端只获取名邦受控地址；
- 不向客户端暴露 JYT 原始 URL 或内部对象地址。

URL 签名、Token、私有 CDN、鉴权回源等具体方案归 Engineering。

---

## 24. 产品级图片限制边界

产品业务层不硬编码：

- 最多图片数量；
- 固定单图大小；
- 固定业务格式清单。

仍允许必要技术安全校验，例如：

- 可处理的真实图片内容；
- 安全检查；
- 防资源滥用；
- 平台 / 对象存储技术限制。

这些技术限制不得未经产品确认反向变成“业务最多 N 张”。

## 26. 明确 DO_NOT_RESTORE / SUPERSEDED

以下旧规则不得恢复：
