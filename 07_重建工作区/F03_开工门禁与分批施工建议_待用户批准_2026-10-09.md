首批必需证据：
| 场景 | 必须证明 |
|---|---|
| 未知/失效actor、缺对象事实 | 拒绝，不退化为默认允许 |
| 角色允许 + 个人deny | 拒绝；个人有效allow仍不能突破hard DENY |
| 4S被配置高权限 | CRM/Lock/Transaction/P04/P05/名邦内部价等hard DENY；获批PC车辆能力只投影合法4S范围 |
| System Admin | 可治理明确控制平面动作；同身份不能作为Employee执行业务或接客/owner兜底 |
| scope不符/对象状态非法 | 拒绝；owner、responsible、assignee不是同一关系 |
| 模板变化/个人撤权/inactive | 使用更新后的假事实立即改变决策；注明真实session/cache撤权仍未测 |
| 电话与价格 | 权限合同区分Customer联系电话、上游publisher电话、内部价、客户展示价覆盖；内部模式不提权，不恢复独立调价action |
| 历史投影 | 当前权限过滤输出，保留当时actor/role/store事实；不能直接返回数据库整行 |
| 假数据检查敏感性 | 把hard DENY优先级或scope检查去掉时，对应负例必须失败；恢复后成功 |

验收提交需提供源规则→合同→测试的反向覆盖表，缺口标明具体责任批次；不能写“所有权限已通过”。
不连接数据库、不建会话表、不创建运行登录/业务route、不接真实微信/JYT、不导入真实权限种子、不改PDM/IA/Low-Fi。

## 4. 后续候选批次（均另行批准）

### F03-1：PC认证、会话与撤销
在A接受F03-G0后，先形成密码哈希/会话技术裁定和精确schema差异，再申请实施：

- 临时密码/哈希/令牌不进入日志和工件，登录失败不泄露账号存在性；限速/过期/撤销有明确检查。
