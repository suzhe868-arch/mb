## 2. 本批要完成什么
在一次性全新隔离PG16、合成账号和单Node进程里，实现PC账号密码验证、首次强制改密、本人改密、退出、可撤销会话，以及有可信治理身份时的内部重置/启禁用原语。证明旧凭证/会话在重置、改密、禁用和主体失效后不能继续使用。
对外仅以下认证适配，不建设业务API、管理页面或完整员工治理：

| 方法与路径（工程适配提案） | 合同 |
|---|---|
| POST /api/v1/auth/login | 唯一规范化账号查找、KDF验证、限速；返回普通或仅改密受限会话及改密/退出所需CSRF材料 |
| POST /api/v1/auth/password | 只允许当前本人，旧密码重新验证、新盐新哈希、世代更新、全部旧会话撤销、审计同事务；成功后重新登录 |
| POST /api/v1/auth/logout | 撤销当前可识别会话并清除Cookie；无效会话也可安全退出，不透露账号信息 |

不新增“查询身份/角色/权限”的受限会话读取特例。强制改密期间只允许本人改密与退出，不准治理/业务读取。正常登录也不产生默认业务权限。重置/凭证启禁用仅内部服务原语和合成可信治理测试，不开放公开管理路由；正式P04/P05治理与最后管理员/接客保护仍属F03-2。

## 3. 本批工程参数（待用户批准成为隔离实现参数）

| 项目 | 提案与限制 |
|---|---|
| 密码KDF | Node22内置异步scrypt：N32768/r8/p3，16B以上独立随机盐，32B结果，maxmem64MiB；严格版本/参数白名单，常量时间比较，未知账号等成本哑元校验 |
| KDF容量 | 单进程最多2个同时计算、最多8个排队、队列等待上限2秒；耗尽统一受控失败；CI验证边界和请求完成，不把runner性能外推生产容量 |
| 密码输入 | 隔离实现提案为12～128个Unicode码点且UTF-8不超过512B；不trim、不大小写转换、不Unicode规范化密码，不强制字符种类；非法编码/超长/过短拒绝且不截断。此安全输入参数随本单批准，生产策略仍另审 |
| 账号规范化 | 提案：仅登录名使用trim→NFC→toLowerCase；规范化后1～128个Unicode码点、UTF-8不超过512B，拒绝控制字符；登录/初设一致，证明大小写/边缘空白/等价Unicode冲突只能形成一个全局凭证。不以手机号或employee_id强制替代账号 |
| 会话 | CSPRNG至少32B不透明秘密；DB仅存32B HMAC-SHA256摘要；密钥通过临时安全环境配置，缺失拒绝启用；不输出会话/CSRF/盐/hash/连接串 |
| 期限 | 隔离工程初值：受限10分钟；普通空闲30分钟、绝对12小时；每次请求检查当前DB事实，last_seen缺失按issued_at处理，未来/异常时钟和非法期限拒绝；不提供延长绝对期限的漏洞 |
| 轮换 | 初次认证签发新令牌；改密/重置/启禁用提升世代并撤销全部旧会话；本批不引入周期自动轮换功能，定期策略继续列残余风险待另行明确 |
| Cookie/来源 | __Host-mb_pc、Secure、HttpOnly、Path=/、SameSite=Lax、无Domain；敏感提交校验可信配置Origin和CSRF，登录也校验Origin，不能靠客户端Host/代理头认定可信来源 |
| 登录节流 | 单进程、双键（匿名账号键+来源），有界内存及超时清理。提案账号15分钟最多5次失败、来源1分钟最多20次尝试、冷却60秒；覆盖超限/恢复/枚举防护，禁止永久锁定账号；多进程/多节点部署不在本批准拓扑内 |
| 匿名失败 | 未知账号/密码错误/禁用/inactive/无4S资格使用统一失败形状；内部脱敏原因分离，不把密码证明耗时承诺成精确恒定时间 |

算法/会话结构可作为已验收方案输入；容量、TTL及节流均为这次待批准的隔离工程配置，不变更PDM业务Authority、不等于生产参数签发。账号规范化和密码输入边界均为本单明示提案；若与既有当前合同冲突，B先报A裁定，不能自行改写产品规则。

## 6. 身份/治理/原子性硬条件
- password_hash唯一在pc_login_accounts；employee/system_admin绑定全局唯一/XOR；会话从当前可信账号连接主体，不信HTTP中的身份ID/已认证布尔量或旧权限快照。
- 登录签发与密码变更共享账号行锁/世代条件，KDF证明基于哪个版本必须检查；登录与重置/禁用竞争不得在新版本上接受旧密码。
- 本人改密提交时再核对绑定、主体/PC资格、session/epoch和旧密码证明；写hash/force标记/世代/撤销/审计同事务，失败均不产生部分成功。
- 管理员重置等内部原语从可信已验证会话/DB取当前active治理身份及目标，执行已验收目标状态守卫。正式治理权限尚未实现时，对不具备可验证授权事实的调用拒绝，不通过HTTP传governanceApproved=true放行。
- 禁用System Admin PC凭证的原语必须保护最后一个可用active System Admin，事务锁+并发负例；无法闭合该保护则禁用管理员目标分支，并报告NOT_RUN，不上线缺保护的治理功能。完整P05生命周期/接客池保护仍交F03-2。
- inactive/PC资格撤销必须在敏感变化事务提升世代、撤销旧会话；读取当前资格立即拒绝。合成可信变化fixture模拟事务，明确不是完整员工治理。复职沿用原ID，旧会话/旧授权不得恢复。
- 4S无PC资格拒绝，有资格也只返回最小认证状态，不授CRM/P04/P05/资金/内部价等业务能力；System Admin身份不变成业务Employee。
- 审计真实actor/target/time/前后状态在事务内追加，仅脱敏版本/状态；hash、salt、password、token、digest、cookie、CSRF、连接串都不得进入审计before/after或响应日志。
