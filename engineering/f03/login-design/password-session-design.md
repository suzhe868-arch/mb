# 名邦汽车 V1｜F03-1-G0 密码与登录安全设计（待 A 技术裁定）

状态：`DESIGN_ONLY / READY_FOR_A_REVIEW / NOT_IMPLEMENTED`。正式来源：`07_重建工作区/F03-1-G0_A主控登录安全方案施工放行_2026-10-09.md`，PDM-02 Final §4/6/9/12、PDM-22 Final §2/3、已验收 F02-1 单一 PC 凭证权威。

## 1. 单一 PC 凭证权威与身份

- 保留 `pc_login_accounts` 作为唯一 PC 密码表；仅其 `password_hash` 保存密码 KDF 结果。`employees`、`system_admins` 不增密码或登录账号副本。`normalized_login_key` 为 Employee/4S/System Admin 共用全局唯一名称；`principal_kind` + 对应 ID 的 XOR 静态约束不放宽。
- PC 账户绑定 `employee_id` 或 `system_admin_id`，不能衍生新 Employee、Customer owner、业务权限。`force_password_change` 初始为 TRUE；初次成功凭证证明仅受限于本人改密/退出。4S 必须由当前服务端核实有明确 PC 车辆管理资格才允许正式 PC 会话，不能因为存在密码获得 P04/CRM/资金等权限。
- 正常与受限会话均需查询**当前**账户启用状态、主身份 active、PC资格、凭证世代、对象权限；不能信任客户端令牌中的旧 role、scope 快照。

## 2. 候选密码算法与存储格式（本批只设计和测时）

**建议 A 首选：Node 22 内置成熟 `crypto.scrypt` KDF**，不实现自研密码算法、不开通外部依赖安装。后续实现批如需 Argon2id 方案，A 可基于成熟维护库/运行构建能力再选择；本次 Node 实证用于支持内置 scrypt 方案，而非假定 Argon2id 已可用。

| 参数 | 提议初值（需 A 确认） | 理由 |
|---|---|---|
| KDF | `scrypt`（Node 内置标准成熟实现） | 内存硬化，减少纯 CPU 暴力破解效率 |
| salt | 加密安全随机字节不少于 16B，**每次写新随机盐** | 同密码不同哈希 |
| N / r / p | `N=32768, r=8, p=1` | 约 32MiB KDF 工作集；必须按部署机器及并发容量实测 |
| keylen | `32` 字节 | 足够的 KDF 输出 |
| maxmem | `64*1024*1024` 字节 | 容纳以上 KDF 工作内存；实际进程峰值需另测 |
| 版本标记 | `scrypt$v1$N$r$p$<salt编码>$<derived编码>` | 自描述格式，解析必须严格、设置参数白名单与大小上限 |
| 校验 | 相同参数计算 KDF 后使用常量时间字节比较；**实际认证逻辑本批 NOT_RUN** | 禁止字符串直接比较或返回不同账号存在信息 |
| 升级 | 验证旧方案成功后，在后续受控事务中条件更新为新参数版本，并使旧会话世代失效 | 不在未认证状态被动信任用户输入升级 |

该格式为方案说明，不向日志、事件或 CI 工件输出实际 salt、密码、KDF 输出/哈希/令牌，真实数据库只保存完整结果在 `pc_login_accounts.password_hash`。不要把测试中的伪造 `hash` 常量视为实际用户密码哈希。Node 环境中的 KDF 成本可用仅驻留内存的**固定合成字符串**测量；仅报告耗时、算法可用性与参数，不保存/显示任何产生的派生结果或盐。

### 成本、节流与并发

- 基于 CI 的 Node 22 `crypto.scrypt` 成功运行和实测耗时决定成本是否适用；性能受 CPU/内存影响，**测量结果非生产容量证明**。
- 服务端独立限制 KDF 并发和队列、统一“账号不存在/密码错误”响应、匿名错误码，并为未知账号使用等成本的哑元校验，防止账号枚举与时序泄露。
- 双维度限速：账号标识 HMAC/等价不可逆匿名键 + 来源/IP 风险指标。限制分布式撞库及单账户暴力尝试，但避免永久账户锁定造成恶意拒绝服务。具体阈值、验证码/冷却、告警、速率共享存储、KDF并发预算待 A 后续实现批裁定。
- 任一密码重置/本人改密/禁用，必须以事务原子更新凭证及世代、追加脱敏审计、撤销旧会话；不能保留旧有效会话。

## 3. 密码生命周期与身份状态边界

- 账号开通：授权治理人设置临时初始密码的哈希，`credential_state=enabled`、`force_password_change=true`；主身份 inactive 仍不能成功正式登录。
- 凭证证明通过但 `force_password_change=true`：签发**仅限本人改密和退出**的短时受限会话，所有业务/治理查询拒绝。改密前旧临时密码、受限会话不可跨域授权。
- 本人改密：重新校验当前身份、本人旧密码和主体绑定，使用新盐、新哈希；成功后清除强制标记，提升凭证世代，撤销全部旧会话。不能通过单纯把 `force_password_change` 改为 FALSE 跳过密码证明。
- 管理员重置：授权治理事务设置新临时密码的哈希、`force_password_change=true`，提升世代、撤销全部旧会话；不发操作方可直接使用的业务会话，不在工件/通知中记录明文密码。
- 禁用：`credential_state=disabled`，提升世代并撤销旧会话；启用时仍按当前原有强制改密标记处理，不自动恢复失效会话。
- Employee inactive / 离职与复职：保持原 `employee_id`，inactive 时所有 PC 授权立即失效；复职仍需新认证，不能重新使用 inactive 前 session、角色、权限或已交客户。停用事件还需提升凭证世代/撤销会话，避免恢复 active 后旧会话回生。
- System Admin inactive 与最后一个 active Admin 保护属于实际治理事务；本批不模拟并发事务成功，也不自行建立新的 super admin 或第二密码表。

## 4. 本方案需要 A 逐项决定

2. 受限会话最大有效期、普通绝对/空闲期限及轮换周期；本设计仅列候选值，不直接上线固定产品行为。
3. 采用 `credential_epoch` + 独立会话表，还是另行裁定的可撤销会话权威存储；严禁未审核修改原 Initial SQL。
