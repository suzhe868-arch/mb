# F02-G0｜身份、权限与价格承载一致性合同（候选；禁止执行DDL）

以下结构是根据 Current PDM Final 推导的技术候选，所有复合键、唯一索引及新增字段均待 A 核定。

## 跨对象身份

| 对象链 | F02-1必须保障的关系 | 当前矩阵缺口及责任 |
|---|---|---|
| Vehicle / listing_cycle | 同一 listing_cycle_id 的 vehicle_id 必须与引用它的Vehicle相同；建议在周期表有 UNIQUE(listing_cycle_id, vehicle_id)，下游建立复合外键 | 单列FK不足以拒绝错车引用；部分唯一 active cycle 要独立确认（PDM-04） |
| Consultation | 同 customer+vehicle+listing_cycle 未终结咨询最多一个，且所有来源与负责人必须真实 | 当前 consultations 缺 listing_cycle_id，是明确 **P0冻结阻断缺口**（PDM-15） |
| Recommendation / Match / Priority / Grant | Recommendation 三元身份与周期一致；source_demand_id 属同 Customer；Visibility Grant 的来源Recommendation绑定相同Customer和Vehicle | 普通FK可指向错误客户的合法对象；需复合FK/事务Guard（PDM-11/12/13/14） |
| LockRequest / Lock / Waitlist | customer、vehicle、listing_cycle要全链一致；仅一个active Lock，竞争申请的waitlist来源要同customer/vehicle/cycle | F02-1设计关联键与唯一性，合法资格和六小时失效仍属事务Guard（PDM-18） |
| Lock / Transaction / Refund | 成交必须引用同客户/车/周期真实Lock；Refund XOR目标对象与 refund_cases.customer_id相符 | 普通FK只保证被引用ID存在，不保证同Customer；需要复合关联或等价事务Guard（PDM-19） |
| Customer owner / Employee | 一个Customer只有一个当前owner；owner与业务对象负责人不等同；停用不删除历史 | 当前owner可能合法公海或待分配；不建立跨客户owner共享迁移（PDM-01/03/17） |
| WeChat / Phone | 微信身份作用域内唯一绑定Customer；手机号可以在多个不同Customer登记 | 禁止全局手机号唯一和Customer Merge（PDM-01） |

## 角色默认与个人权限覆盖

- PDM-02 的有效权限：角色默认 + 个人显式 allow/deny + hard DENY + data scope + object state。F03实现有效权限判定，F02只建事实承载。
- role_permission_defaults：当前有效态同一 (role_id, permission_id) 最多一条。候选路线 A 是当前投影表 UNIQUE(role_id,permission_id)，另有不可变role_default_history；路线 B 为单表有效期区间+UNIQUE(role_id,permission_id) WHERE ended_at IS NULL。
- employee_permission_overrides：当前有效态同一 (employee_id,permission_id) 最多一条，decision为明确allow/deny。历史可append-only + 当前投影，或effective_at/ended_at + 部分唯一索引。原矩阵缺 ended_at/version/history，不得用 changed_at 的复合唯一冒充当前有效唯一。
- **A待裁定**：两表统一采用当前投影+历史事件，还是区间版本单表；撤权实时效果由F03提供，角色模板调整留存actor/time/version。

## PDM-10 每日额度 ≠ 周期单车解锁权

| 物理事实 | 候选身份/键 | 核心语义和禁错 |
|---|---|---|
| 每日额度账本 | (customer_id, business_day_shanghai)，追加base/addition/consumption事件 | 当天剩余=max(0,当天base+当天临时追加-当天成功新解锁扣额)；上海UTC+8日切；UNLIMITED不扣，已有当日追加不被清空 |
| 单车周期解锁权 | UNIQUE(customer_id, vehicle_id, listing_cycle_id) | 本周期跨日继续有效；真实下架再上架新cycle必须重新核定；单一周期重复查看不重复扣 |
| 首次成功扣额事件 | actor/request幂等键加客户/车辆/周期事实 | 仅LIMITED客户主动进详情、尚未解锁、有合法数字客户价、quota充足且真实成功才扣一次；超时失败预加载不扣 |
| Recommendation免费权 | source_recommendation_id + customer+vehicle+cycle | 与每日额度独立；推荐创建时只有价格咨询也可免费授本周期价权；Priority本身不能授予免费权 |

- 当前 customer_daily_price_access 同时承载 day 和 cycle，存在模型混叠风险。建议 F02-1 另建 customer_price_cycle_unlocks、customer_day_quota_ledger、unlock_event_history 的候选物理表；当前376字段不含以上三表，需A审定后再增加，不提前施工。
- 当前 customer_quota_adjustments 记录临时追加，但不是日账里全部base及consume。单车免费权、周期切换及日期切换必须分别负例测试；不固定将示例“20台”写入数据库常量。
- **阻断清单**：consultations.listing_cycle_id、权限两表的当前/历史版本键、价格按日账/周期解锁拆表与对应原子唯一性、Refund到同Customer的复合FK设计。未获A定稿前，G0_MODEL_FREEZE_PENDING。

## 本阶段边界

所有以上内容为非执行工程约束候选。G0不得运行新表DDL、历史迁移、种子或F03/F04业务逻辑。跨时刻的并发、身份资格、资金余额和权益核定仍需后续正式事务Guard，不可因文档上写有UNIQUE便宣称已实现。
