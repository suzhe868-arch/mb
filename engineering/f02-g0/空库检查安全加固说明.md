# F02-G0｜全库空库审查安全加固

> 保留原隔离环境硬拒绝，**没有** F02-1 DDL、正式业务迁移、老清库或生产库连接。

## 空库定义

原守卫仅检查 public schema 中的表，存在“另一个非 public 用户 schema 中存有对象”的漏判。现在在 PostgreSQL 16 系统目录同时检查：

- public_table_count = 0（原有检查保持）；
- non_public_user_schema_count = 0（不允许任何非 public 用户 schema，包含仅建立 schema、尚无表的情况）；
- user_relation_count = 0（public 及任何非系统用户 schema 中的表、分区、视图、物化视图、序列、外部表或索引）；
- 仅过滤 PostgreSQL 内建 pg_catalog / information_schema / pg_toast* / pg_temp*，**不**过滤普通自定义 schema；
- 身份仍必须是 CI 一次性 PG16、本机 f02_schema_test、角色 f02_ci、非超级用户，整个预检在 BEGIN READ ONLY 内执行并 ROLLBACK。

## 真实正反例

1. CI 全新独立库：三个计数都为 0，应真实通过。
2. CI 仅创建 f02_g0_negative_fixture 空 schema：预检必须拒绝。
3. 同一专用 fixture 下再创建 synthetic_probe 测试表：预检仍必须拒绝。

负例使用 **CI disposable PG16 容器中的专用合成测试夹具**，并置于所有正常测试之后，随 GitHub job 结束自动销毁。创建合成 fixture 是对空库条件的反向安全测试，不是 Current Initial Schema 的 F02-1 建表/迁移，不触及旧库、生产库或真实用户数据。不调用 DROP SCHEMA 旧脚本。

风险：内建系统对象的 schema 类型需遵 pg16 目录排除规则；当测试库存在被外部安装的 extension 自定义 schema 时，采用保守拒绝而非允许绕过。`G0_MODEL_FREEZE_PENDING` 不变。
