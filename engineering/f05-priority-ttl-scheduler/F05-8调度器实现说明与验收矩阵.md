## 三、运行边界与策略

1. 只允许 \`APP_ENV=test\`、\`NODE_ENV=test\`、\`API_HOST=127.0.0.1\` 和 \`I_AUTHORIZE_DISPOSABLE_F05_CATALOG_PG16_ONLY\`。
2. 数据库必须是 \`f05_catalog_test\`，连接角色必须是 \`f05_catalog_ci\`，服务器必须是 PostgreSQL 16，且运行时实际查询 \`pg_roles.rolsuper=false\`；任何不匹配均失败关闭。
3. 拒绝 \`F05_PRIORITY_TTL_PRODUCTION\`、\`F05_PRIORITY_TTL_EXTERNAL_CALLS\`、\`F05_PRIORITY_SCHEDULER_USE_PRODUCTION\`、\`F05_CATALOG_USE_PRODUCTION\`、\`ENABLE_PRODUCTION_RUNTIME\` 等冲突开关。
4. 默认轮询 1000ms、单批最多 10 条（硬上限 25）、最大运行 300000ms；各参数有上下界，最大退避不得小于基础退避。
5. tick 串行，不重叠；空队列休眠；异常采用有界指数退避。调度器只调用已验收 \`createIsolatedPrioritySchedulerWorker().runDue()\`，不复制仲裁逻辑。
6. \`runDue()\` 返回的计数只用于脱敏日志。日志不输出 Customer ID、车辆 ID、手机号、Token 或原始敏感 Payload。
7. tick 超过剩余运行时长时，调度进程以退出码 124 终止，避免仍在执行的数据库查询拖延退出；队列 lease 已提交后，必须等 \`lease_until\` 到期，再由重启进程领取。
8. 生产环境、正式 Issuer、JYT/Collector、CDN/OSS、飞书、公网请求、真实电话与资金操作均不在本任务授权内。

## 四、真实验收矩阵

| 场景 | 通过条件 |
|---|---|
| PG16 与身份门禁 | 真实应用连接为 \`f05_catalog_ci\` 非超级用户；临时提升超级用户后 runner 拒绝启动，测试后恢复 NOSUPERUSER |
| 自动到期处理 | 真实 Node 子进程自动调用队列消费者；到期 Priority 结束，旧客户的抑制事实和新 Priority 由既有业务 worker 决定 |
| 批量边界 | 单批配置为 1 时，两个到期任务必须由独立 tick 处理，不能超批 |
| 双进程并发 | 两个真实 runner 同时启动；每个到期 Priority 只生成一次 DONE 与一次 sweep 事件 |
| 数据库故障与重试 | PG16 触发器注入真实事务失败；原 Priority 不得部分结束，队列持久记录 retry，移除故障后重启可完成 |
| 截止时间与恢复 | 锁住车辆行使 sweep worker 阻塞；runner 达到硬截止后退出 124，已提交 lease 保留；租约过期后重启完成并记录 RECOVERED |
| 进程崩溃 | 实际 SIGKILL runner；PG16 保留 claimed lease，过期后重启重新领取且不重复仲裁 |
| 空队列与停机 | 空队列产生 claimed=0 的轮询事件；SIGTERM 后干净退出并记录 signal；最大运行时长到期后正常退出 |
| 最终证据 | 同一最终 HEAD 的官方 Push Run 全部 completed/success、失败 0、跳过 0；Artifact 含 SHA/Run/分支、脱敏日志与校验和，低于 20 MiB，保留 1 天 |
