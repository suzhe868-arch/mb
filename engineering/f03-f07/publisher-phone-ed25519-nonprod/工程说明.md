# F03→F07 Ed25519 非生产协议工程说明

## 使用范围

仅允许在本任务指定的 GitHub Actions 分支 `feat/f03-f07-publisher-phone-ed25519-nonprod-01` 上，由指定 Workflow 使用一次性 PostgreSQL 16、非超级用户和 loopback TLS 执行。代码不接入产品路由，不能用于真实电话或生产。

## 文件职责

- `protocol.mjs`：协议常量、固定载荷顺序、challenge/载荷严格校验、运行时 Ed25519 密钥对。
- `issuer.mjs`：沿用 F03 `IsolatedAuth.withSession` 读取当前权限与生命周期事实后签发短时断言。
- `challenge-store.mjs`：F07 独立 PG16 challenge 原子消费和最小审计记录。
- `verifier.mjs`：验签、绑定、TTL、原子消费以及原 F07 Guard 二次授权。
- `harness.mjs`：仅 loopback 的 F03/F07 HTTPS 测试入口，服务间 TLS 显式信任本次测试证书。
- `fixtures.mjs`、`schema.sql`、`environment.mjs`：隔离环境、私有 CI Schema 和合成测试事实。
- `tests/business.test.mjs`、`tests/https.test.mjs`：真实 PG16 与 HTTPS 正反例。
- `workflow-trigger-audit.rb`、`verify-contract.mjs`：旧工作流触发审计、路径白名单、语法和运行封印。
- `evidence.mjs`：同 SHA 测试日志、PG16 身份、测试矩阵和 SHA-256 证据归档。

## CI 流程

1. 两个独立 Job 各自创建新 `f03_auth_test` 与 `f07_runtime_test`，角色 `f03_ci` / `f07_runtime_ci` 均为 NOSUPERUSER、NOCREATEDB、NOCREATEROLE。
2. 只运行既有 F03-1 / SG01 的隔离初始化和本任务合成 fixture；既有 F03/F07 服务、Guard、公共 Schema/Migration 不修改。
3. 执行路径白名单、`git diff --check`、全部新增 JavaScript `node --check`、工作流触发审计。
4. 分别运行真实 PG16 业务用例与真实 loopback HTTPS 黑箱用例。测试失败/跳过都不允许形成通过状态。
5. 证据脚本把最终 SHA、Run/Attempt/Ref、PG16 身份、TAP 计数、测试矩阵、源文件清单及 SHA-256 写入去敏报告。Artifact 每 Job 不超过 5 MiB，保留 1 天。
6. 不重跑、不修改、不补签 F05-7 历史 66 项/旧 Oracle。正式 CRM/电话 Issuer、外部可信来源和生产依旧未接通。
