# F03→F07 Ed25519 签名授权协议与威胁模型

## 1. 定位与不可突破的边界

本实现是 **CI-only、CI_SYNTHETIC_ONLY** 的非生产协议适配器。它不注册到 `app.mjs` / `server.mjs`，不生成正式信任根，不使用长期密钥，也不连接真实 JYT、Collector、CDN/OSS、飞书、真实电话号码、真实客户或资金。

协议仅适配已批准的 `publisher.phone.sensitive` 与 `LOCKED_ONLY` / `ALL_ACTIVE_JYT`。任何正式 Source Issuer、通用能力签发、生产权限或 F05-7 历史 Oracle 证明都不在本任务内。父 Issue #187 继续 `SOURCE_GAP/FAIL_CLOSED`。

## 2. 数据流

1. F07 loopback HTTPS 入口从 `__Host-mb_pc` 会话读取当前员工 ID；员工、操作和车辆以服务端当前会话与严格请求字段绑定，不接受客户端 employee/role/scope/permission。
2. F07 ChallengeStore 在独立 PG16 `f07_runtime_test` 中锁定当前 listing-cycle（如果存在），创建随机 UUID challenge 和 256-bit nonce。数据库只存 nonce 的 SHA-256 摘要；明文 nonce 仅在本次内存请求中发给 F03。
3. F07 通过显式信任临时 TLS 证书的 loopback HTTPS 请求 F03 Issuer。F03 使用原 `IsolatedAuth.withSession(...,{normalOnly:true})` 在真实 PG16 重新读取员工、角色、门店、`publisher.phone.sensitive` 个人覆盖、有效 `publisher_phone_special` Scope/Binding、F03 专项模式与生命周期水位。
4. 只有所有当前事实允许时，F03 使用本次进程内存 Ed25519 私钥签名固定字段白名单载荷。私钥不写入文件、环境、数据库、日志、Artifact 或仓库。
5. F07 以同一运行时公钥验签，核对 issuer/audience/kid、协议版本、challenge/request/employee/action/vehicle/listing-cycle/nonce 绑定、TTL 和来源标记，然后在 PG16 中以单条条件 UPDATE 原子消费 challenge。
6. 消费成功后必须调用已验收的 `authorizePublisherPhone` Guard 再读当前 F03 权限、F07 车辆和锁车状态。签名不是当前权限的替代品；签名后撤权或对象状态变化仍拒绝。
7. F07 写入仅含 request/challenge ID、员工/车辆 ID、阶段、拒绝码和 allow/deny 的 CI 私有审计行。没有手机号、token、nonce、签名、私钥或原始凭证字段。

## 3. 签名载荷

载荷字段严格固定为 `version, issuer, audience, kid, jti, challengeId, nonce, requestId, employeeId, capability, action, vehicleId, listingCycleId, scopeMode, f03FactsSha256, iat, exp, origin, formalSourceSigned, productionReady`。使用固定顺序 JSON 字节作为 Ed25519 输入；未知字段、类型错误、非规范标识或绑定错配拒绝。

- `version=F03_F07_PUBLISHER_PHONE_ED25519_V1`
- `issuer=f03.publisher-phone.nonprod`
- `audience=f07.publisher-phone.scope.nonprod`
- `capability=publisher.phone.sensitive`
- `origin=CI_SYNTHETIC_ONLY`
- `formalSourceSigned=false`，`productionReady=false`
- 断言有效期最多 15 秒；本实现目标 10 秒；时钟偏差最多 2 秒。
- `kid` 是本次临时公钥 SPKI DER 的 SHA-256 前 24 位十六进制指纹，不是正式长期密钥 ID。

## 4. 重放、撤权和对象绑定

- Challenge 的 nonce 至少 256 bit；表中只保留摘要。
- `consume()` 通过 challenge ID、request ID、员工、操作、车辆、listing-cycle、audience、nonce 摘要、来源、未消费状态和有效期进行同一条条件 UPDATE。并发相同 challenge 最多一个成功。
- 任何签名字段修改、错误公钥/kid、issuer/audience、请求/员工/能力/操作/车辆/周期/nonce 错配、过期/未来签发/TTL 超限都 fail-closed。
- F03 个人 deny 优先；权限、Scope/Binding、员工在职/凭证、角色/门店快照或员工生命周期审计水位变化都会阻止签发。
- F07 在验签并消费后仍调用原 Guard。车辆必须是当前 active 的 JYT wholesale，必须有发布人映射；`LOCKED_ONLY` 必须有当前周期的 active 未过期 Lock。
- 任一 F03/F07 数据库、Scope、审计或 Guard 依赖不可用都不得返回 allow。

## 5. 威胁模型与残余风险

防护：调用方伪造员工 ID、跨请求/跨车/跨操作重放、过期签名、伪造签发方/受众、签名篡改、nonce 并发重放、个人 deny/撤权、员工停用、Scope 结束、车辆下架/转来源、旧周期锁、错误 Host/Origin/CSRF、非 loopback 访问和日志敏感字段泄漏。

本任务刻意不覆盖：正式服务间身份认证、正式公钥带外分发、密钥托管/轮换、正式 JYT/Collector 数据可信链、正式 F07 Runtime 路由和生产电话返回。由于公钥只在同一个 CI 进程注入，成功只证明测试协议内部正确，不构成正式外部来源的密码学信任。

使用 `工程说明.md` 的一次性 PG16 流程；最终 SHA、Run、Job、PG16 身份、TAP、ZIP digest 和文件 SHA 清单均由官方 Artifact 内 `f03-f07-evidence.json`、`测试矩阵.tsv` 与 `最终运行交接.md` 绑定。不要把本目录协议用于生产。
